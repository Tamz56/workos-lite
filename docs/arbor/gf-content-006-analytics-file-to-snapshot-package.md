# คู่มือนำเข้าข้อมูลสถิติจากไฟล์วิเคราะห์ (Analytics CSV / Table to Snapshot Specification)

เอกสารระบุข้อกำหนดด้านเทคนิคและคู่มือการใช้งานระบบนำเข้าชุดสถิติประสิทธิภาพประจำช่วงเวลา (Performance Snapshots) ผ่านกลไกคัดลอกวางตารางดิบ (CSV/TSV/Table) จากระบบ Google Analytics 4 (GA4) และ Facebook Insight

---

## 1. ความแตกต่างของแหล่งสถิติ (GA4 vs Facebook Insight)

ในการวิเคราะห์กลยุทธ์คอนเทนต์ของ Green Fineness เราแบ่งมิติตัวเลขประสิทธิภาพออกเป็น 2 ประเภทหลัก:

### A. Google Analytics 4 (GA4) - Article-Level / Website Signals
- **ขอบเขต**: วิเคราะห์พฤติกรรมคนอ่านที่เข้าชมหน้าเว็บบล็อกโดยตรง (หน้าบทความจริง)
- **ตัวชี้วัดสำคัญ**:
  - `Views` (จำนวนการดูหน้าเว็บ)
  - `Active Users` (ผู้ใช้งานจริง)
  - `Average Engagement Time` (เวลาในการอ่านหรือมีส่วนร่วมเฉลี่ย)
  - `Bounce Rate` (อัตราคนตีกลับ/ปิดหน้าจอทันที)
  - `Events` (การกระทำที่สำคัญในเว็บ)
  - `Source/Medium` (ระบุทราฟฟิกขาเข้า เช่น จาก facebook หรือ google organic)

### B. Facebook Insight - Post-Level / Distribution Signals
- **ขอบเขต**: วิเคราะห์แรงส่งและการแจกจ่าย (Reach / Engagement) ของโพสต์โปรโมตบนโซเชียลมีเดีย
- **ตัวชี้วัดสำคัญ**:
  - `Reach` (จำนวนบัญชีที่โพสต์เข้าถึง)
  - `Impressions` (จำนวนครั้งที่โพสต์ปรากฏบนฟีด)
  - `Reactions` (ยอดกดไลก์/เลิฟ/หัวใจ)
  - `Comments` (ยอดความคิดเห็น)
  - `Shares` (ยอดแชร์ขยายผล)
  - `Link Clicks` (ยอดคลิกลิงก์เพื่อนำทางมายังเว็บไซต์)
  - `Saves` (ยอดบันทึกโพสต์เก็บไว้อ่านทีหลัง)

## 2. รูปแบบตารางข้อมูลที่รองรับ (Supported Formats)

เพื่อความง่ายและไม่สร้างภาระให้ผู้ใช้ (No-fuss experience) ระบบรองรับการคัดลอกข้อความตาราง (Paste raw text) จากสเปรดชีต เช่น Excel, Google Sheets, ไฟล์ CSV หรือตารางสรุปสรุปจาก AI โดยรองรับการแยกข้อมูลด้วยอักขระ:
1. **Tab-separated values (TSV)**: รูปแบบเริ่มต้นเมื่อคัดลอกจาก Google Sheets / Excel มาวางโดยตรง
2. **Comma-separated values (CSV)**: รูปแบบไฟล์ตารางมาตรฐานคั่นด้วยเครื่องหมายจุลภาค `,`
3. **Semicolon-separated values**: รูปแบบตารางคั่นด้วยเครื่องหมายอัฒภาค `;`
4. **Space-aligned table**: รูปแบบตารางเว้นวรรคสองช่องขึ้นไปแบบตารางผลลัพธ์ของ CLI หรือ AI

## 4. กฎการจับคู่บทความ (Article Matching Priority Rules)

ระบบจะแกะข้อมูลจากแถวตารางสถิติเพื่อหาบทความเป้าหมายในฐานข้อมูล SQLite โดยทำงานตามลำดับความสำคัญ:
1. **Exact URL Match (ความมั่นใจสูงสุด - High)**: จับคู่คอลัมน์เส้นทาง URL ของแถวกับคอลัมน์ `published_url` ของบทความตรงตัว
2. **Slug Match (ความมั่นใจสูง - High)**: ตัดช่วงท้ายของเส้นทาง URL ออกมาเพื่อจับคู่กับ `slug` ของโปรเจกต์
3. **Title Match (ความมั่นใจปานกลาง - Medium)**: จับคู่ข้อความหัวข้อหน้าเว็บเข้ากับชื่อบทความปลายทางโดยตรง
4. **Manual Selector Fallback (ความมั่นใจต่ำ - Low)**: หากระบบสืบค้นไม่พบ หรือแถวมีข้อมูลไม่ชัดเจน ระบบจะแสดงเครื่องหมายคำเตือน `⚠️ No Match` และบังคับให้ผู้ใช้เลือกระบุโครงการปลายทางด้วยตนเองผ่านกล่อง Dropdown

## 5. การตรวจสอบความซ้ำซ้อนและการเตือนทับซ้อน (Duplicate Handling)

- **ห้ามทำการบันทึกเงียบ (No Silent Overwrite)**: ระบบจะนำข้อมูลสถิติชุดใหม่ไปตรวจสอบในฐานข้อมูลปลายทาง หากพบว่ามีข้อมูล Snapshot ประจำช่วงเวลา (เช่น `snap24h`) และแหล่งข้อมูล (เช่น `GA4`) บันทึกอยู่ในระบบอยู่แล้ว:
  1. ระบบหลังบ้าน (API Route) จะส่งคำเตือนแนบไปกับโครง validation
  2. หน้าจอ Preview Area จะแสดงแถบการเตือนสีส้มเด่นชัดที่หัว Preview ว่า `"คำเตือน: พบการเขียนทับ Snapshot เดิม"`
  3. เพื่อป้องกันไม่ให้ผู้ใช้บันทึกทับข้อมูลที่สำคัญโดยไม่ได้ตั้งใจ

## 6. โครงสร้างแหล่งที่มา (Snapshot Source Metadata)

ทุกครั้งที่มีการนำเข้าสถิติระบบจะจัดเก็บ Metadata ของไฟล์นำเข้าไว้ควบคู่กันภายใต้คีย์ `performanceFeedback.sourceMetadata` เพื่อเป็นบันทึก Audit:
- `sourceFileName`: ชื่อที่มาข้อมูล (ค่าเริ่มต้น "Pasted Text")
- `sourceType`: แพลตฟอร์มแหล่งสถิติ (`GA4`, `Facebook Page`, `Facebook Group`, `Personal Profile`)
- `snapshotWindow`: ช่วงเวลาของตัวสถิติ (`24h`, `7d`, `30d`, `90d`)
- `snapshotDate`: วันที่ดึงบันทึกสถิติ
- `matchedBy`: วิธีการจับคู่เป้าหมาย (`exact_url`, `slug`, `title`, `manual_selection`)
- `matchConfidence`: ความมั่นใจในการจับคู่ (`High`, `Medium`, `Low`)
- `rawSourceSummary`: สรุปข้อมูลแถวดิบแบบย่อ
- `importNote`: บันทึกช่วยจำเพิ่มเติมจากผู้ใช้

## 7. รายการตรวจสอบความเสถียร (QA Checklist)
- [ ] สกัดข้อมูลแถวและคอลัมน์ออกได้ถูกต้อง ไม่มีอาการหน้าจอบั๊ก/ค้างเมื่อวางข้อมูลที่มีคอลัมน์ไม่สนับสนุน (Unknown columns)
- [ ] เมื่อวางตารางรายสถิติ สัญญาณประเภท SourceType ต้องคำนวณถูกต้องตามคีย์เวิร์ด
- [ ] การจับคู่ต้องแสดงผลลัพธ์ชัดเจน พร้อมสัญลักษณ์แจ้งระดับความแม่นยำ
- [ ] หากตรวจพบข้อมูลในรอบวันเดียวกันซ้ำ ต้องขึ้นแถบเตือนสีส้มสว่างไสวที่ Preview Area
- [ ] ข้อมูลที่นำเข้ารอบเวลาเดี่ยวๆ ต้องไม่ทำลายข้อมูล Snapshot รอบเวลาอื่นๆ ที่บันทึกอยู่ก่อนหน้านี้
- [ ] การสร้างไฟล์อัปเดตตรงตามข้อกำหนดสกีมา `workos-writing-lab-update-v0.1`

## 8. พร้อมท์ควบคุมสำหรับ AI (AI Prompt Template)

คุณสามารถนำแม่แบบนี้ป้อนให้ Arbor หรือ ChatGPT เพื่อให้ระบบทำการแปลงข้อมูลดิบของรายงานสถิติหน้าจอให้เป็นตาราง CSV ที่พร้อมนำมาคัดลอกวางในหน้า Arbor Inbox:

```markdown
คุณคือผู้ช่วยจัดการข้อมูลสถิติการตลาดสำหรับ Green Fineness
หน้าที่ของคุณคือรับตัวเลขรายงานสถิติของบทความจากหน้าจอ แล้วจัดระเบียบให้มีหัวข้อคอลัมน์เป็นไปตามสกีมานำเข้าในรูปแบบ CSV คั่นด้วย Tab (\t)

กรุณาเรียบเรียงให้ออกมาเป็นตารางที่มีคอลัมน์หลักดังนี้:
1. หากเป็นสถิติ GA4: Page path, Views, Active users, Average engagement time, Event count, Page title
2. หากเป็นสถิติ Facebook: Post URL, Reach, Reactions, Comments, Shares, Link clicks, Date

กรุณาแปลงข้อมูลดิบต่อไปนี้ให้เป็นข้อความตาราง CSV ที่ถูกต้องและพร้อมนำมาป้อนเข้าระบบทันที:
---
[วางข้อมูลสถิติดิบที่คัดลอกจาก GA4 หรือ Facebook ที่นี่]
---
```
