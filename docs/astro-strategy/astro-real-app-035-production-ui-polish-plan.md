# DEV-035 — Production UI Polish Plan

## Goal
จัดทำแผนปรับแต่งและยกระดับหน้าจอผู้ใช้งานสภาพแวดล้อมจริง (Production UI Polish Plan) สำหรับ Astro Real App ภายหลังการสลับเส้นทางนำทางหลักและ Smoke QA สำเร็จลุล่วง เพื่อลดความเป็นลักษณะพรีวิวทดลอง และส่งมอบอินเตอร์เฟซที่พรีเมียม สะอาดตา และปลอดภัยแก่ผู้ใช้งาน

## Scope
- การทบทวนและประเมินป้ายข้อความนำทางเชิง Preview, Prototype, หรือ Demo
- การวางแนวทางการซ่อน/ย้าย หรือปิดบังแผงจัดการข้อมูล (Data Tools) และคำสั่งล้างคีย์ความจำ
- การจัดวางข้อเสนอแนะโครงสร้างการจัดเรียงแท็บนำทาง (Tab Navigation Order)
- การคุมโทนการนำเสนอภาษาและจริยธรรมข้อมูลดาราศาสตร์เพื่อลดความหวาดกลัวหรือความลึกลับ

## Non-scope
- ไม่ดำเนินการแก้ไขโค้ดการแสดงผลรันไทม์ของ UI, ไม่ปิดป้ายพรีวิว และไม่ลบเครื่องมือจัดการข้อมูลในขั้นตอนนี้ (Planning/Documentation only)

2. **Footer Caption**: ระบุว่า *"Astro Strategy Lab — Real App LocalStorage Preview (DEV-012)"* และแจ้งเตือนข้อมูลจำลองการพรีวิว

## Polish Recommendations (ข้อเสนอแนะการปรับปรุง)

### 1. การจัดการป้ายคำเตือนและแบนเนอร์พรีวิว (Preview & Experimental Labels)
- **แผง Header (ส่วนหัว)**: 
  - *ข้อเสนอแนะ*: ปรับเปลี่ยนหัวข้อแบนเนอร์หัวเพจจาก *"Astro Strategy Lab — Real App Preview"* เป็น **"Astro Strategy Lab"**
  - *ข้อเสนอแนะ*: นำป้ายสถานะสีม่วงเข้ม *"PREVIEW MODE"* ออกเพื่อเพิ่มความเป็นระบบจริงที่เป็นมืออาชีพ หรือปรับขนาดให้อยู่ในตรรกะเชิงสัญลักษณ์ที่นุ่มนวลขึ้น
- **แผง Footer (ส่วนท้าย)**:
  - *ข้อเสนอแนะ*: เปลี่ยนข้อความลิขสิทธิ์ท้ายหน้าจอเป็น **"Astro Strategy Lab — ระบบวิเคราะห์และวางแผนเชิงกลยุทธ์ส่วนบุคคล"** และซ่อนรหัสรันการทดลอง (เช่น DEV-012)
- ** disclaimers คำเตือน**: คงสถานะคำเตือนจริยธรรมข้อมูลดาราศาสตร์ไว้ท้ายแผงควบคุมสรุปและวิเคราะห์ของแต่ละหน้าเพื่อปฏิบัติตามมาตรฐานการปกป้องผู้ใช้และความปลอดภัยทางใจ

### 2. การจัดการแท็บเครื่องมือข้อมูล (Data Tools Visibility)
- **แนวทางเชิงปฏิบัติที่ปลอดภัย (Data Tools)**: 
  - *ข้อเสนอแนะ*: ในเส้นทางหลัก `/workspaces/astro-strategy` ให้ **ซ่อน** แท็บ *"⚙️ เครื่องมือข้อมูล" (tools)* ออกจากการเรนเดอร์ปกติ เพื่อป้องกันผู้ใช้ทั่วไปกดล้างประวัติบันทึกสะท้อนคิดสะสมโดยไม่ตั้งใจ
  - *ข้อเสนอแนะ*: คงแท็บ *"⚙️ เครื่องมือข้อมูล" (tools)* นี้ไว้เฉพาะในเส้นทางตรวจสอบเทคนิค `/workspaces/astro-strategy/real-app-preview` เท่านั้น เพื่อให้ทีมนักพัฒนายังสามารถกดล้างคีย์และตรวจวัดคีย์ LocalStorage ของเครื่องในการทดสอบภายในได้ง่าย
  - *ข้อเสนอแนะ*: การสั่งทำงาน Migration และตรวจสอบ Dry-run คีย์เก่า จะจำกัดให้ทำงานเฉพาะบนหน้าพรีวิวย่อย `/workspaces/astro-strategy/real-app-preview` หรือซ่อนไว้ภายใต้ปุ่มขยาย "เครื่องมือขั้นสูง" (Advanced Panel) พร้อมการถามยืนยันแบบสองขั้นตอน (Two-step confirmation) เพื่อความรัดกุมสูงสุด

### 3. การจัดเรียงลำดับแท็บนำทางยุทธศาสตร์ (Tab Navigation Order)
ปัจจุบันลำดับแท็บมีความกระจัดกระจายและมีเครื่องมือย่อยผสมอยู่มาก
*ลำดับที่เสนอสำหรับการปรับปรุงในอนาคต (ลำดับความสำคัญตามระดับยุทธศาสตร์การใช้งานจริง)*:
1. **📊 สรุปวันนี้ (Today)**: สำหรับดูจังหวะชีวิตระดับวันทำงาน
2. **📅 สรุปสัปดาห์ (Weekly)**: สำหรับประเมินแผน 7 วันถัดไป
3. **📅 สรุปรอบเดือน (Monthly)**: สำหรับวางธีมภาพรวมและรีวิวประวัติ (Reflection pattern)
4. **✍️ สะท้อนคิด (Reflection)**: แผงแบบฟอร์มบันทึกการทำงานประจำวัน
5. **📋 ประวัติ (History)**: ตารางประวัติการบันทึกเก่าของผู้ใช้
6. **🎯 แผนกลยุทธ์ (Planning)**: สมุดบันทึกโน้ตเป้าหมายงานส่วนบุคคล
7. **👤 โปรไฟล์ดวงเกิด (Birth Profile)**: ข้อมูลพื้นฐานส่วนบุคคล
8. **📖 คู่มือ (Guide)**: คู่มือและคำแนะนำจริยธรรมข้อมูลในการใช้งานอย่างปลอดภัย
9. **⚙️ เครื่องมือข้อมูล (Data Tools)**: (ซ่อนไว้สำหรับหน้าผู้ใช้ปกติ และเปิดเผยเฉพาะในหน้า /real-app-preview เท่านั้น)

### 4. การคุมโทนและความปลอดภัยทางภาษา (Copy & Safety)
- ยึดตรรกะการนำเสนอเชิงกลยุทธ์ (Planning focused) ที่เป็นกลางและมีข้อความที่ชัดเจน
- บันทึกคำเตือนการวินิจฉัยข้อมูลดาราศาสตร์ให้ระบุชัดว่าใช้สำหรับการ "สะท้อนคิดร่วมกับบันทึกและประเมินกลยุทธ์" ไม่ใช่คำชี้ขาดอนาคต

## Proposed DEV-036 Implementation Scope
หากแผนการขัดเกลา UI นี้ได้รับการเห็นชอบ ขอบเขตของภารกิจ **DEV-036** จะครอบคลุม:
1. ซ่อนแท็บนำทาง *"⚙️ เครื่องมือข้อมูล"* ในหน้า `/workspaces/astro-strategy` โดยตรวจสอบจากเส้นทางเบราว์เซอร์หรือพารามิเตอร์ หรือซ่อนผ่านเงื่อนไขการเรนเดอร์พร็อพ
2. ปรับข้อความของ Header Banner และ Footer Caption บนหน้าจอหลักเพื่อเปลี่ยนผ่านเข้าสู่โหมดการใช้งานจริง
3. จัดลำดับแท็บนำทางใหม่ตามตารางที่วางไว้
4. ทำการบิวด์และตรวจเช็คลินต์เพื่อยืนยันผลการเปลี่ยนผ่าน

---

## Risks / Edge Cases
- **กรณีการซ่อนเครื่องมือย้ายข้อมูล (Migration)**: หากซ่อนแท็บ Data Tools ในเพจหลัก ผู้ใช้อาจมองไม่เห็นฟังก์ชันการย้ายประวัติเก่าไปสู่ระบบใหม่
  - *วิธีบรรเทาความเสี่ยง*: สามารถเพิ่มปุ่มแนะนำเล็กๆ ในแท็บ "โปรไฟล์ดวงเกิด" หรือแสดงแบนเนอร์แจ้งเตือนการเปลี่ยนถ่ายระบบชั่วคราว พร้อมระบุลิงก์นำทางไปยัง `/workspaces/astro-strategy/real-app-preview` เพื่อให้ผู้ใช้เดิมที่ต้องการย้ายประวัติสามารถกดทำงานได้ด้วยตนเอง
