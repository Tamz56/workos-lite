# ASTRO-REAL-APP-DEV-054 — Thai Astrology Output Contract & Copy Safety Review

## Goal
จัดทำเอกสารข้อกำหนดเชิงโครงสร้างข้อมูล (TypeScript Output Contract) และแนวทางการคุมภาษาและการนำเสนอที่ปลอดภัยทางจิตวิทยา (Copy Safety Review) สำหรับ **Thai Astrology Strategy Layer v0.1** ในระบบ Astro Strategy Lab ของ ArborDesk เพื่อล็อกประเภทข้อมูล รูปแบบข้อความนำเสนอ วิธีแก้ปัญหาสัญญาณขัดแย้ง และระบบคำเตือนทางจริยธรรมก่อนที่จะมีการอิมพลีเมนต์จริงในขั้นตอนถัดไป

---

## Scope
- ความสำคัญของการออกแบบสัญญาข้อมูลส่งออก (Output Contract) ก่อนเริ่มเขียนโปรแกรมจริง
- สัญญาอินเตอร์เฟซ TypeScript (TypeScript-style Output Contract) และคำอธิบายความหมายของแต่ละฟิลด์อย่างละเอียด
- ตัวอย่างข้อความคำเตือนและคำแนะนำที่ปลอดภัย (Safe Wording Patterns) และตัวอย่างประโยคต้องห้าม (Forbidden Wording Patterns)
- ข้อกำหนดในการสื่อสารช่วงเวลาฤกษ์ยามที่ไม่ดี (Yam Caution Rules)
- กฎการจัดการความขัดแย้งเชิงลอจิกระหว่างระบบ (Conflict Handling & Low-burnout Priority)
- รายการตรวจสอบจริยธรรมภาษาสำหรับการตรวจสอบในอนาคต (Copy-safety Checklist)
- แผนการตรวจรับและทดสอบระบบด้วยตนเอง (Manual QA Plan)

## Non-scope
- การดัดแปลงหรือแก้ไขซอร์สโค้ดโปรแกรมรันไทม์ในโฟลเดอร์ `src/` (Documentation-only)
- การทดสอบการคำนวณยามอุบากองจริงในรันไทม์

---

## Why Output Contract Must Come Before Implementation

1. **การควบคุมการเติบโตของฟิลด์และโค้ดบวม (Anti-Bloat Constraint)**:
   การกำหนดชื่อฟิลด์ ประเภทตัวแปร และหน้าที่อย่างเบ็ดเสร็จช่วยบล็อกไม่ให้เกิดการเขียนโค้ดเพิ่มฟิลด์ตามอำเภอใจในภายหลัง ซึ่งจะนำไปสู่ความกระจัดกระจายและขนาดไฟล์ประวัติ (`ReflectionHistoryItem`) เติบโตโดยไม่จำเป็น
2. **การป้องกันปัญหาพังทลายของระบบข้อมูลนำเข้า/ส่งออก (Data Portability Integrity)**:
   ฟังก์ชันนำเข้ากู้คืนข้อมูล (Import/Restore) จาก v3 ทำงานอิงตาม JSON Schema Validation การล็อกโครงสร้างผลลัพธ์ของเลเยอร์ใหม่ก่อนเขียนโค้ดช่วยให้มั่นใจได้ว่าระบบ Schema Validator จะรู้จักคีย์ทั้งหมดล่วงหน้า และจะไม่เกิดข้อผิดพลาด "ข้อมูลเสียหาย" เมื่อผู้ใช้คืนค่าข้อมูลข้ามเบราว์เซอร์
3. **การล็อกกรอบภาษาจริยธรรมเป็นตัวแปรถาวร (Deterministic Copy Enforcement)**:
   การทำ Copy Safety Review ร่วมกับ Output Contract ช่วยเปลี่ยนแนวทางปฏิบัติทางจิตวิทยาให้กลายเป็นกฎเกณฑ์เชิงโครงสร้างซอฟต์แวร์ ซึ่งจะบังคับให้เนื้อหาที่จะบันทึกลงฐานข้อมูลต้องผ่านตัวกรองความปลอดภัยเดียวกัน

## Proposed TypeScript-style Output Contract

อินเตอร์เฟซเอาท์พุตสำหรับวิเคราะห์ผลลัพธ์ของ Thai Astrology Layer:

```typescript
export interface ThaiAstroOutputContract {
  /** ชื่อเลเยอร์ความรู้เพื่อระบุบนหน้าจอ เช่น "Thai Astrology Strategy" */
  readonly layerName: string;
  /** แหล่งที่มาหรือเวอร์ชันของระบบคำนวณ เช่น "ArborDesk Thai Astro Engine v0.1" */
  readonly source: string;
  /** ข้อมูลสภาพแวดล้อมทางเวลาที่ระบบตรวจพบ */
  readonly timingContext: {
    /** ตรวจพบว่าวันเป้าหมายตรงกับวันเกิดทางสุริยคติประจำสัปดาห์หรือไม่ */
    readonly isBirthWeekdayCycle: boolean;
    /** ดัชนีรอบยามอุบากองกลางวัน (0 ถึง 4) */
    readonly currentYamIndex?: number;
    /** เวลาจริงที่เครื่องนำมาสแกนวิเคราะห์ยาม เช่น "14:15" */
    readonly rawTimeChecked: string;
  };
  /** สัญญาณยามสั้นๆ เช่น "ยามปลอดโปร่ง (สี่จักรา)" */
  readonly thaiAstroSignal: string;
  /** ความหมายดั้งเดิมเชิงอุปมาอุปไมยปรัชญาธรรมชาติ */
  readonly symbolicMeaning: string;
  /** แผนเชิงกลยุทธ์การทำงานและการทบทวนความคิดที่แนะนำ */
  readonly strategyImplication: string;
  /** การปฏิบัติจริงทีละขั้นเพื่อประคองสมาธิ */
  readonly suggestedAction: string;
  /** คำถามกระตุ้นความคิดชวนจดลง Daily Checkin */
  readonly reflectionPrompt: string;
  /** ข้อสังเกตในการเฝ้าระวังหรือชะลอการทำกิจกรรมเชิงรุก */
  readonly cautionNote: string;
  /** ระดับความสอดคล้องเชิงฤกษ์ยามของวัน (0.0 ถึง 1.0) */
  readonly symbolicAlignment: number;
  /** บันทึกที่มาการตรวจสอบคำแนะนำ */
  readonly confidenceNotes: string;
  /** ข้อปฏิเสธความรับผิดชอบเชิงจิตวิทยาและการตั้งสติ */
  readonly safetyDisclaimer: string;
  /** วันเวลาที่ผลลัพธ์นี้ถูกสร้างขึ้น (ISO Format) */
  readonly generatedAt: string;
}
```

## Copy-Safety & Language Guardrails

### 1. Safe Output Examples (ตัวอย่างข้อความที่ปลอดภัย)
* **ตัวอย่างที่ 1 (ยามระมัดระวัง)**:
  - `thaiAstroSignal`: "ช่วงยามเตือนสติ (ยามศูนย์หนึ่ง)"
  - `strategyImplication`: "ฤกษ์ยามท้องถิ่นแนะนำให้ใช้จังหวะเวลานี้ชะลอการลงนามตัดสินใจ หรือตรวจสอบความเรียบร้อยของข้อกำหนดโครงการอย่างรอบคอบ แทนการเร่งรีบส่งมอบงาน"
  - `suggestedAction`: "ยืดเส้นยืดสายบริเวณบ่าและไหล่ 3 นาที ตรวจหาข้อผิดพลาดในหน้าเอกสารหลัก 1 รอบ"
* **ตัวอย่างที่ 2 (วันรอบเกิดประจำสัปดาห์)**:
  - `thaiAstroSignal`: "วันครบรอบวันเกิดประจำสัปดาห์ (วันพฤหัสบดี)"
  - `strategyImplication`: "เป็นโอกาสดีในการลดภาระงานลง 20% เพื่อหยุดทบทวนความล้าสะสมของจิตใจ และสรุปความคืบหน้าของสัปดาห์ที่ผ่านมา"
  - `suggestedAction`: "เขียนบันทึกความในใจสั้นๆ ลงประวัติสะท้อนคิด และหลีกเลี่ยงการเปิดประเด็นพัฒนาโค้ดชิ้นใหม่"

  - *"ธาตุลมส่งเสริมให้ลงเงินในหุ้นวันนี้เพื่อรับโชคลาภเงินแสน"* (คำมั่นสัญญาการเงินงมงาย)

## Copywriting Guardrail Rules (กฎการคุมภาษาเชิงลึก)

1. **กฎคำเชิงเตือนสติ (Caution Wording Rules)**:
   - ห้ามใช้คำแสดงเคราะห์ร้ายหรือความสูญสิ้น ให้ใช้คำเชิง **"การประคองตัว"**, **"จังหวะเวลาในการทบทวน"**, **"ช่วงเวลาที่เหมาะสมในการชะลอเพื่อปิดช่องโหว่"**
   - คำแนะนำต้องเป็นคำตอบปลายเปิดหรือข้อเสนอแนะในการจัดการแผนงาน เช่น *"อาจเป็นช่วงเวลาที่ดีในการ..."* แทนการสั่งการเด็ดขาด
2. **กฎคำมงคล/ส่งเสริม (Auspicious Wording Rules)**:
   - ห้ามให้คำสัญญาว่ากิจกรรมจะประสบความสำเร็จรวยล้นฟ้า 100% แต่ให้เสนอในลักษณะ **"โอกาสสนับสนุนความโปร่งสบายของสมาธิ"** หรือ **"พลังงานส่งเสริมให้การเจรจามีความยืดหยุ่นราบรื่น"**
3. **กฎด้านพิธีกรรมและความเชื่อทางศาสนา**:
   - **ห้าม** ชี้นำให้ผู้ใช้บริจาคเงิน ทำพิธีสะเดาะเคราะห์ ปล่อยนกปล่อยปลา หรือบังคับให้กราบไหว้วัตถุมงคลใดๆ เพื่อแก้ผลลัพธ์ของฤกษ์ยาม

## Conflict Handling & Composer Integration

### 1. ลำดับความสำคัญการป้องกันภาวะเหนื่อยล้า (Low-burnout Priority)
- หาก Today Engine ชี้ขาดโหมดประคองตัว `Pause & Calibrate` แต่ยามไทยระบุยามปลอดโปร่ง `ลุยทำเชิงรุก` **ระบบ composer จะยึดถือโหมด Pause & Calibrate เป็นตัวนำสูงสุดบน UI**
- *การเรนเดอร์*: แสดงคำแนะนำหลักให้ผู้ใช้พักผ่อนเพื่อลดสภาวะล้าสะสม และใช้ข้อความยามไทยเป็นส่วนสนับสนุนย่อย เช่น *"แม้ช่วงเวลาบ่ายจะมียามปลอดโปร่ง แต่การประเมินพลังงานร่างกายแนะนำให้ท่านใช้ยามนี้สะสางงานง่ายๆ ที่ค้างอยู่ แทนการรับภาระงานใหม่"*

### 2. การจัดการสัญญาณขัดแย้งกันอย่างมีนัยสำคัญ (Mixed Signals Logic)
- ในอนาคตเมื่อรวมเลเยอร์อื่นๆ (จีน อี้จิง) หากผลลัพธ์ของแต่ละเลเยอร์ชี้ทิศทางขัดกันอย่างสิ้นเชิง ระบบ composer จะคัดสกัดคำเตือนที่แสดงสถานะ **"Mixed Signals (พลังงานรอบวันแสดงสัญญาณกึ่งกลาง)"** ขึ้นแสดง และแนะแนวทางให้ผู้ใช้หันมาทำสมาธิจดจ่อลมหายใจ (Chakra Layer) แทนการฝืนพึ่งพาฤกษ์ยาม

## Copy-Safety Checklist (รายการตรวจสอบจริยธรรมภาษา)
- [ ] ไม่มีคำว่า "หายนะ", "วิบัติ", "เคราะห์ร้าย", "อุบัติเหตุ", "สูญเสียชีวิต"
- [ ] ไม่มีคำว่า "รวยแน่นอน", "ถูกหวย", "ได้โชคลาภเงินล้าน"
- [ ] คำชี้แนะทั้งหมดใช้ภาษาเชิงเลือกทำ/เลือกถอย เช่น "สนับสนุน", "แนะนำให้พิจารณา", "อาจเป็นจังหวะที่ดีในการ"
- [ ] มีปุ่มและลอจิกในการกดซ่อนหน้าต่างแสดงผลฤกษ์ยามนี้บน UI เพื่อรักษาความสงบสายตาของผู้ใช้ (Cognitive Calmness)
