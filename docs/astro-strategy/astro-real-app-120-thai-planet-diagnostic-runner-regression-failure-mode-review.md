# ASTRO-REAL-APP-DEV-120 — Thai Planet Diagnostic Runner Regression & Failure Mode Review

เอกสารทบทวนการวิเคราะห์โหมดความล้มเหลวและการป้องกันการถดถอยเชิงระบบ (Regression & Failure-Mode Review) สำหรับตัวตรวจความสอดคล้องรันไทม์จำลองดวงดาวไทย v0.1

## 1. Purpose (วัตถุประสงค์)

วัตถุประสงค์ของงานรอบ **DEV-120** คือการสอบทาน ตรวจสอบ และทบทวนโหมดความล้มเหลว (Failure Modes) และพฤติกรรมการสกัดกั้นความเสี่ยงถดถอย (Regression Checks) ของสคริปต์รันเนอร์ตรวจสอบสัญญารันไทม์ [check-thai-planet-placement-contract.cjs](file:///Users/tamz/projects/workos-lite/scripts/astro-diagnostics/check-thai-planet-placement-contract.cjs) ที่ได้ทำการอัปเกรดในรอบ DEV-119 

เพื่อให้มั่นใจว่าตัวรันเนอร์สามารถดักจับและขัดขวางข้อผิดพลาด (Fails properly on contract breach) และแยกแยะขอบเขตความปลอดภัยได้อย่างถูกต้อง ก่อนที่จะก้าวข้ามไปทำงานในส่วนความสามารถการเรนเดอร์และการปรับปรุงประสิทธิผลของอินเตอร์เฟสผู้ใช้งาน (UI) ในรอบถัดๆ ไป

## 2. Current Runner Behavior Summary (สรุปพฤติกรรมการทำงานของตัวตรวจสอบในปัจจุบัน)

สคริปต์รันเนอร์เวอร์ชันอัปเกรดล่าสุดขับเคลื่อนระบบตรวจสอบผ่านกลไก 2 มิติตามแผนงาน Option A:

1. **Static Analysis & File Isolation Check**: ตรวจสอบโครงร่างซอร์สโค้ดของไฟล์อแดปเตอร์และเครื่องมือคำนวณจำลอง เพื่อสกัดกั้นคำสั่งไม่พึงประสงค์ (LocalStorage, Composer Imports) และตรวจสอบ Copy Safety (ห้ามมีคำเคลมความถูกต้องหรือองศาจริง)
2. **Runtime Contract Check**: ทำการประเมินโครงร่างออบเจกต์ของชุดข้อมูลขาออก (JSON schema structure) กับข้อมูลในหน่วยความจำ เพื่อเช็กว่ามีดาวครบ 10 ดวง, ข้อมูลราศีและองศาเป็น placeholder เท่านั้น, และสัดส่วนค่าสอบเทียบ (`comparableCount`) มีค่าเป็น 0

## 3. Regression Checks that Currently Pass (การตรวจสอบการป้องกันการถดถอยที่ผ่านเกณฑ์ในปัจจุบัน)

จากการประเมินผ่านตัวรันเนอร์ในสภาวะปกติ ทุกระบบทำงานสอดคล้องตามสัญญาและคืนสถานะผ่านเกณฑ์ครบถ้วนทั้ง 9 หมวดการทดสอบหลัก:

* **Planet ID coverage**: ผ่านเกณฑ์การตรวจเช็กว่ารหัสประจำดวงดาวครบทั้ง 10 ดวง (0 ถึง 9)
* **Placeholder-only signRasi**: ข้อมูลราศีของทุกดาวระบุเป็นค่ารอตรวจสอบความถูกต้องจำลองเท่านั้น
* **Placeholder-only degree**: ข้อมูลองศาดาวไม่มีการรั่วไหลขององศาหรือลิปดาจริง
* **Adapter status stub-only**: ตัวอแดปเตอร์รายงานสถานะขีดจำกัดตนเองเป็นสตับจำลองสถานะ (`stub-only`)
* **Safety summary comparable count**: ตัวนับค่าประเมินสอบเทียบดวงดาวชี้วัดเป็น `0` ป้องกันการแปลผลเปรียบเทียบในสภาพแวดล้อมสถิติ
* **Safety summary not-comparable count**: จุดดาวทั้งหมดถูกกักบริเวณเป็นค่าประเมินสอบเทียบไม่ได้ (`10` จุด)
* **generatedAt metadata-only**: ตัวแปรเวลาแสดงสถานะ ISO timestamp และทำหน้าที่เป็น metadata เท่านั้น
* **LocalStorage isolation**: ไม่มีโค้ดปะปน localStorage ภายในขอบเขตการคำนวณ
* **Strategy isolation**: สถาปัตยกรรมอแดปเตอร์แยกขาดจากโมดูลแนะนำกลยุทธ์หลักอย่างสมบูรณ์

## 4. Failure Modes the Runner is Expected to Catch (โหมดความล้มเหลวที่ตัวตรวจสอบสามารถสกัดกั้นได้จริง)

หากมีการดัดแปลงไฟล์หรือระบบข้อมูลจำลองผิดแปลกไปจากข้อตกลง ตัวรันเนอร์จะรายงานเป็นความล้มเหลว (Failed) และสั่งหยุดการบิวด์ทันทีในกรณีต่างๆ ดังนี้:

| โหมดความล้มเหลวเชิงเทคนิค | พฤติกรรมดักจับของ Runner | ผลกระทบที่ขัดขวาง | ระดับความเสี่ยงหากหลุดรอด |
|---|---|---|---|
| **มีโค้ดเขียนลง LocalStorage ในอแดปเตอร์** | สแกนพบคำว่า `localStorage` ในไฟล์ TS ของอแดปเตอร์ ทำให้เกิดข้อผิดพลาด static guard | สกัดกั้น Side-effects จากการประมวลผล Mock data ไปทับข้อมูลจริง | **ปานกลาง-สูง** (ข้อมูลผู้ใช้อาจเสียหาย) |
| **เรียกใช้หรืออิมพอร์ต Composer ในอแดปเตอร์** | สแกนพบคำว่า `buildNatalTransitStrategyComposerOutput` ในไฟล์ข้อมูลจำลอง | ป้องกันไม่ให้โมดูลจำลองปะปนกับระบบประเมินกลยุทธ์หลัก | **สูง** (โครงสร้างข้อมูลและคะแนนกลยุทธ์ผิดพลาด) |
| **อิมพอร์ตฟังก์ชันรันไทม์จำลองไปที่หน้า Preview โดยตรง** | สแกนตรวจสอบไฟล์ `AstroRealAppPreview.tsx` หากพบโค้ดอิมพอร์ต `buildThaiPlanetPlacementRuntimeAdapterV01` โดยตรง จะปฏิเสธทันที | บังคับให้การเรียกใช้หน้าจอ UI ต้องผ่านตัวสกัดกั้นความปลอดภัยและคอมโพเนนต์ Diagnostics เสมอ | **ปานกลาง** (UI ทำงานข้ามขั้นตอนความปลอดภัย) |
| **เขียนโค้ดเคลมความแม่นยำดวงดาว** | สแกนพบคีย์คำเฉพาะ เช่น `accurate placement`, `real chart`, `ดาวอยู่ราศี`, `ผลดวงจริง` | สกัดกั้นคำโฆษณาชวนเชื่อหรือการแปลความโหราศาสตร์ดวงจริงบนระบบวินิจฉัยจำลอง | **สูง** (ปัญหาลิขสิทธิ์ความน่าเชื่อถือและการแปลข้อมูล) |
| **จำนวนดวงดาวไม่ครบ 10 หรือรหัสไม่ถูกต้อง** | ตรวจสอบอาร์เรย์ `results` ขาออกในรันไทม์จำลอง หากจำนวนไม่ใช่ 10 หรือไม่มีดวงใดดวงหนึ่งในรหัส 0-9 | ขัดขวางไม่ให้ส่งข้อมูลที่ไม่ครบสมบูรณ์ไปยังอินเตอร์เฟสวิเคราะห์ดวงดาวไทย | **สูง** (หน้าจอ UI เรนเดอร์ล้มเหลวเนื่องจากข้อมูลขาดหาย) |
| **มีข้อมูลราศีจริงหรือองศาจริงใน Stub Output** | ตรวจสอบฟิลด์ `signRasi` หรือ `degree` หากไม่ใช่ค่า placeholder ที่กำหนด จะล้มเหลวทันที | ป้องกันการสอดแทรกผลองศาดาราศาสตร์จริงเข้าสู่อแดปเตอร์โดยไม่ได้รับการสอบเทียบที่ถูกต้อง | **สูง** (ระบบเข้าใจผิดว่าเป็นการคำนวณจริง) |
| **สถานะของระบบความปลอดภัยมีค่าเปรียบเทียบเพิ่มขึ้น** | ตรวจสอบ `safetySummary.comparableCount` หากมีค่ามากกว่า 0 บนกรณีทดสอบวินิจฉัยทั่วไป | สกัดกั้นไม่ให้โปรแกรมตีความเปรียบเทียบดวงกรณี placeholder เข้ากับกรณีศึกษาอ้างอิง | **สูง** (สถิติการสอบเทียบมีความคลาดเคลื่อน) |

## 5. Failure Modes Not Yet Automatically Testable (ข้อจำกัดที่ยังไม่สามารถตรวจสอบแบบอัตโนมัติได้)

* **การประมวลผลองศาดาวเคราะห์ด้วยสมการในระดับเบราว์เซอร์**: สคริปต์รันเนอร์รันบนสภาพแวดล้อม Node.js ผ่าน CLI เท่านั้น หากมีการเปลี่ยนลอจิกหรือเรียกใช้งาน API ภายใน event handler ที่เกิดขึ้นเฉพาะฝั่งไคลเอนต์ (เช่น ทำงานในเบราว์เซอร์ผ่านปุ่มกด) โดยไม่มีการบันทึกคีย์เวิร์ดไว้ในไฟล์ซอร์ส ตัวตรวจสอบจะไม่เห็นพฤติกรรมนี้จนกว่าหน้าจอจะเรนเดอร์จริง
* **การดัดแปลงข้อมูล mock data จากเครื่องมือภายนอก**: หากนักพัฒนาป้อนพิกัดดวงดาวจริงเข้าผ่านไฟล์ภายนอกอื่นๆ ที่ไม่อยู่ในขอบข่ายการสแกน และนำเข้ามาใช้งานโดยตรงในอินเทอร์เฟสโดยไม่ผ่านอแดปเตอร์จำลอง

## 6. Risk of False Confidence & Oracle-Risk Review (บทวิเคราะห์ความเชื่อมั่นลวงและขอบเขต Oracle)

* **ความเสี่ยงความเชื่อมั่นลวง (False Confidence)**: การที่รันเนอร์แสดงผลลัพธ์ Passed หมายความว่าสัญญาระหว่างข้อมูล (Technical Contract) มีความกักแยกและสอดคล้องตามโครงสร้างข้อมูลจำลอง v0.1 เท่านั้น **ไม่ใช่การรับรองความถูกต้องของสมการทางดาราศาสตร์โหราศาสตร์**
* **ขอบเขต Oracle (Oracle-Risk Boundary)**: สคริปต์นี้ทำหน้าที่เป็นผู้เฝ้าประตู (Gatekeeper) ตรวจสอบความสอดคล้องเชิงเทคนิคทางเดียว ไม่ทำงานเป็นผู้ชี้ขาดความแม่นยำของการคำนวณดวงชะตา เพื่อไม่ให้โครงการหลักเกิดความสับสนหรือมีสคริปต์ลอจิกการทายผลแอบแฝง

---

## 7. Static Guard False-Positive Risk (ความเสี่ยงแจ้งเตือนผิดพลาดเชิงสถิต)

* หากมีการอธิบายความคิดเห็น (Comments) เอกสารประกอบการสอน หรือบันทึกประวัติการปรับปรุงภายในไฟล์ `astroRealAppThaiPlanetPlacementAdapter.ts` หรือ `astroRealAppThaiPlanetPlacementSafety.ts` โดยใช้คำที่อยู่ในกลุ่มเฝ้าระวัง เช่น `"Accurate placement is planned for v0.2"` ตัว Static guard จะปฏิเสธและบล็อกการบิวด์ทันที
* **แนวทางแก้ไขเมื่อเกิดการปฏิเสธผิดพลาด (False Positive Remediation)**: ให้ทำการปรับปรุงคำอธิบาย (Rephrase) หรือลบข้อความเฝ้าระวังออก โดยสามารถเปลี่ยนไปอธิบายในไฟล์ภายนอกแทน เช่น การย้ายบันทึกไปยังเอกสารข้อตกลงการพัฒนาหลัก `docs/astro-strategy/`

## 9. Conclusion (บทสรุปและความพร้อม)

โครงการหลักมีความสะอาด ปลอดภัย และมีผู้เฝ้าประตูทางเทคนิค (Technical Gatekeeper) ที่ทำงานได้อย่างเข้มแข็ง สคริปต์รันเนอร์สามารถดักจับการถดถอยเชิงข้อมูลได้อย่างน่าเชื่อถือและส่งออกรหัสความล้มเหลว (Non-zero exit) ได้อย่างแม่นยำ 

**ข้อเสนอแนะ**: โครงการมีความพร้อมเต็มที่ (100% Ready) ในการเปลี่ยนผ่านจากการสร้างตัวทดสอบหลังบ้าน ไปสู่การพัฒนาปรับปรุงและจัดระเบียบหน้าจอส่วนแสดงผลวินิจฉัย (Visible UI Polish) ในรอบตั๋วถัดไป
