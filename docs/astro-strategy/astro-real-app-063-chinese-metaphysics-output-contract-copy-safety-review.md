- สัญญาอินเตอร์เฟซ TypeScript (TypeScript-style Output Contract) และคำอธิบายความหมายของแต่ละฟิลด์อย่างละเอียด
- ตรรกะการคุมภาษาและการนำเสนอเชิงบวก (Safe wording patterns & Forbidden wording patterns)
- กฎการใช้ภาษาสำหรับห้าธาตุ รอบฤดูกาล ความสมดุล/ไม่สมดุล และวงจรเกื้อกูล/ควบคุม
- กฎการจัดการความขัดแย้งเชิงลอจิกระหว่างระบบ (Today Engine, Thai Layer, Future layers)
- รายการตรวจสอบจริยธรรมภาษาสำหรับการตรวจสอบในอนาคต (Copy-safety Checklist)
- แผนการตรวจรับและทดสอบระบบด้วยตนเอง (Manual QA Plan)

- การทดสอบการคำนวณธาตุเกิดจีนจริงในรันไทม์

## Why Output Contract Must Come Before Implementation
1. **การควบคุมความสะอาดของระบบข้อมูล (Anti-Bloat Constraint)**:
   การกำหนดชื่อคีย์ข้อมูลและประเภทให้เบ็ดเสร็จช่วยป้องกันการใส่ฟิลด์ประสงค์ส่วนตัวสะเปะสะปะในภายหลัง ซึ่งจะนำไปสู่ความเทอะทะและขนาดไฟล์ประวัติสะสม (`ReflectionHistoryItem`) เติบโตโดยไม่จำเป็น
2. **การรักษาความเข้ากันได้ของการกู้คืนข้อมูล (Data Portability Integrity)**:
   ลอจิกการส่งออกและนำเข้าข้อมูลสำรอง (Export/Import) อิงตาม Schema Validation การระบุรูปแบบฟิลด์เสริมของจีนให้แน่นอนทำให้ตัวอ่าน Schema ของเวอร์ชันก่อนหน้า (v3) ละเว้นฟิลด์นี้ได้โดยอัตโนมัติ ไม่ส่งผลให้ไฟล์กู้คืนพังเสียหาย
3. **การบังคับใช้ภาษาที่ปลอดภัยเชิงสถาปัตยกรรม (Deterministic Copy Enforcement)**:
   การล็อกรูปแบบเอาท์พุตทำให้มั่นใจได้ว่าข้อมูลทั้งหมดที่จะผ่านเข้ามาในระบบจะถูกครอบงำด้วยตัวกรองความปลอดภัย (Copy-Safety Filters) เดียวกัน ปราศจากความสุ่มเสี่ยงเชิงถ้อยคำที่ไม่ได้กลั่นกรอง

## Copy-Safety & Wording Guardrails

### Wording Principles (หลักเกณฑ์การใช้ภาษา)
1. **ภาษาที่พึงใช้ (Safe wording patterns)**: 
   * *"มีส่วนช่วยสนับสนุน (may support)"*, *"สามารถใช้เป็นกรอบสะท้อนสติ (can be used as a reflection lens)"*, *"จังหวะเวลาที่เอื้อต่อการปรับสมดุล (a useful moment to balance)"*, *"พิจารณาเสริมสร้างความแข็งแกร่ง (consider strengthening)"*, *"เป็นช่วงเวลาที่ดีในการทบทวน (good moment to review)"*
2. **ภาษาที่ต้องหลีกเลี่ยงและห้ามใช้ (Forbidden wording patterns)**:
   * *"ต้อง (must)"*, *"จะเกิดขึ้นแน่นอน (will happen)"*, *"ดวงร้าย/เคราะห์ตก (bad luck / danger)"*, *"โชคชะตาลิขิต (fate)"*, *"การันตีความสำเร็จ (guaranteed success)"*, *"เงินทองจะไหลเข้าแน่นอน (wealth will come)"*, *"ความสัมพันธ์จะพังทลาย/สำเร็จแน่นอน (relationship will succeed/fail)"*

### Rules for Five Elements Language
* แสดงคำแปลธาตุในเชิงเปรียบเปรยการทำงาน:
  * **ไม้**: การวางแผนงาน ความคิดริเริ่ม
  * **ไฟ**: การส่งมอบผลงาน การลงมือทำจริง
  * **ดิน**: การจัดระเบียบเอกสาร ฐานข้อมูล
  * **ทอง**: การ Refactor โค้ด การคัดกรองส่วนเกิน
  * **น้ำ**: การยืดหยุ่น การเจรจา พักผ่อนเพื่อกักเก็บพลังงาน

### Rules for Seasonal Rhythm Language
* นำฤดูกาลมาใช้สื่อสารสัญญะของจังหวะธรรมชาติประจำปี:
  * หลีกเลี่ยงการทำนายสภาพอากาศจริงหรือชี้นำดวงชะตาชีวิต 
  * ให้เน้นการกระตุ้นให้ผู้ใช้ปรับสภาพการทำงาน (Work rhythm) ลื่นไหลไปตามรอบปีธรรมชาติ เช่น ฤดูหนาวคือการสะสมปัญญา ฤดูร้อนคือการทุ่มพลัง

### Rules for Balance / Imbalance Language
* **ห้าม** ใช้สถานะความขัดแย้งของธาตุมาเคลมอาการป่วยทางการแพทย์ (เช่น โรคหัวใจ หรือโรคตับ) หรือทำนายการเกิดอุบัติเหตุ
* **ต้อง** ใช้คำอุปมาสมดุลพลังสมองและจิตใจในการจัดการภารกิจเท่านั้น (เช่น พลังธาตุไฟท่วมท้นอาจทำให้จดจ่อได้น้อยลงชั่วคราว)

### Rules for Generation / Control Cycle Language
* นำเสนอวงจรธาตุเป็นกลวิธีสร้างสมาธิชดเชย:
  * ไม่ทำให้วงจรควบคุมดูน่าสะพรึงกลัว (เช่น ทองทำลายไม้ = หายนะ) แต่แปลความว่า *"การนำพลังธาตุทอง (การควบคุมกรอบจำกัด) เข้ามาตีกรอบ จะช่วยประคองความฟุ้งซ่านของธาตุไม้ (การขยายไอเดียไม่มีที่สิ้นสุด) ให้มีทิศทางใช้งานได้จริง"*

### Rules for Caution Wording
* ข้อเตือนใจ (Caution Note) ต้องระบุแบบประนีประนอมเพื่อระวังสุขภาพจิต ปราศจากน้ำเสียงข่มขู่หรือสั่งห้ามกระทำพฤติกรรมในชีวิตจริงเด็ดขาด เช่น เปลี่ยนจาก *"ห้ามออกจากบ้าน"* เป็น *"ควรระมัดระวังความล้าสะสมจากการเดินทางติดต่อกัน"*

### Rules for "Mixed Signal" Wording
* หากเกิดสัญญาณขัดกันระดับปฏิทินหรือระดับวัน ระบบจะต้องชี้สัญญะว่า *"สัญญะรอบวันมีความกึ่งกลาง (Mixed Signals) แนะนำให้ผู้ใช้จัดสรรการตัดสินใจด้วยความสงบนิ่งเชิงส่วนบุคคล และหลีกเลี่ยงการเร่งรีบตามเงื่อนไขแวดล้อม"*

## Conflict Handling & Composer Integration

### 1. Conflict Handling with Today Engine
* **Today Engine** (ตัวประเมินความล้าสะสมทางกายภาพ) ถือเป็นกฎเหล็กสูงสุด (Absolute Safe Guard)
* หาก Today Engine สั่งโหมดประคองตัว `Pause & Calibrate` แต่ระบบจีนวิเคราะห์เป็นธาตุไฟเชิงรุก ตัวComposer จะบังคับปรับเปลี่ยนและลดทอนความดุดันของคำชี้แนะจีนทันที โดยระบุว่าการถนอมพลังงานสำคัญที่สุด

### 2. Conflict Handling with Thai Astrology Layer
* ระบบไทย (ยามชั่วโมงย่อย) และระบบจีน (ธาตุและฤดูกาลรายวัน/สัปดาห์) จะแสดงผลเคียงคู่กันอย่างเป็นสัดส่วน (Parallel views)
* หากเกิดสัญญาณขัดกันอย่างรุนแรง (เช่น ไทยห้าม-จีนหนุน) ระบบจะแสดงสเตตัสแจ้งเตือนเป็น **"Mixed Signals"** พร้อมข้อแนะนำให้ประเมินสภาพร่างกายและสติปัญญาของตนเองเป็นหลัก (Autonomy-first)

### 3. Conflict Handling with Future I Ching / Chakra Layers
* ลำดับการขจัดความขัดแย้ง (Priority Resolution Ladder):
  1. `Today Timing Engine` (สถิติทางกายภาพและความล้า - สูงสุด)
  2. `Thai Astrology Layer` (จังหวะเวลารายชั่วโมงย่อย)
  3. `Chinese Metaphysics Layer` (ฤดูกาลรายเดือนและธาตุคู่มิตรรายวัน)
  4. `Future Layers` (อี้จิง/จักระ - ล่างสุด)
* เลเยอร์ระดับล่างสุดจะไม่สามารถส่งข้อความหักล้างคำสั่งเตือนระดับความล้าหรือหยุดพักผ่อนของเลเยอร์ด้านบนได้

## Copy-Safety Checklist

- [ ] ไม่มีคำว่า "หายนะ", "วิบัติ", "ล้มละลาย", "อุบัติเหตุร้ายแรง", "อันตรายถึงชีวิต"
- [ ] ไม่มีคำว่า "รวยชั่วข้ามคืน", "ชนะพนัน", "การันตีผลกำไร", "ได้คู่ครองแน่นอน"
- [ ] คำอธิบายความสมดุลห้าธาตุใช้ภาษาเชิงเลือกทำ/เลือกพักผ่อน เช่น "ส่งเสริมความยืดหยุ่น", "เหมาะสำหรับสะสางงานคงค้าง"
- [ ] คำเตือนความสัมพันธ์ขัดแย้งใช้ประโยคประนีประนอมเตือนสติความล้าสะสม
- [ ] มีตัวเลือกการเปิด/ปิด (Toggle Switch) แสดงผลเลเยอร์จีนใน UI เพื่อความเงียบสงบส่วนบุคคล (Cognitive Calmness)
- [ ] จัดเก็บข้อมูลเอาท์พุตลงประวัติสะสมโดยใช้เพียงรหัสย่อ (IDs) เพื่อความปลอดภัยและประหยัดพื้นที่จัดเก็บ
