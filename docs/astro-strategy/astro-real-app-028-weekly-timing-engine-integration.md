# ASTRO-REAL-APP-DEV-028 — Weekly Timing Engine Integration

เอกสารนี้ระบุรายละเอียดการออกแบบและผลลัพธ์ในการเชื่อมโยงข้อมูลคำนวณจาก Astrology Engine เข้ากับแผงกลยุทธ์สรุปรายสัปดาห์ (Weekly Timing View) ในแอป Preview

## Goal
วิเคราะห์และสร้างโครงสร้างข้อมูล ปฏิทินรายสัปดาห์ 7 วัน และคอมโพเนนต์แสดงผลสำหรับรายสัปดาห์ โดยอิงตามข้อมูลจาก Birth Profile ที่จัดเก็บใน LocalStorage ปัจจุบันเพื่อช่วยในกระบวนการทำงานและพักผ่อนในแต่ละวันอย่างมีจริยธรรม

## Scope
- เพิ่มโครงสร้างประเภทข้อมูล `AstroWeeklyTimingDay` และ `AstroWeeklyTimingViewModel`
- สร้าง View Model `astroRealAppWeeklyTimingViewModel.ts` เพื่อประมวลผลข้อมูล 7 วันนับตั้งแต่วันปัจจุบัน
- สร้างและออกแบบคอมโพเนนต์ย่อย `<AstroWeeklyPanel>` สำหรับจัดการการแสดงผล
- เพิ่มแท็บย่อยใหม่ **"📅 สรุปสัปดาห์" (Weekly Timing)** ในหน้าพรีวิวหลัก แยกออกจากแท็บสรุปรายวันเพื่อไม่ให้หน้าแรกยาวเกินไป
- รักษาแนวทางภาษาแบบ Non-deterministic (ไม่มีการคาดเดาอนาคตเชิงลบหรือผลกระทบทางสุขภาพ)

## Non-Scope
- ไม่ยุ่งเกี่ยวกับเส้นทางหลัก `/workspaces/astro-strategy`
- ไม่ปรับแต่ง API หรือ Logic การย้ายข้อมูล
- ไม่ทำระบบคำนวณและแสดงผลในระดับรายเดือน (Monthly) ในรอบนี้

## Data Flow & Birth Profile Source
1. ในขณะที่หน้าพรีวิวหลักถูก Hydrated หรือมีการสลับแท็บไปยัง "📅 สรุปสัปดาห์" แอปจะเรียกใช้ฟังก์ชัน `loadAstroBirthProfile()` จาก Birth Profile Adapter เพื่อดึงข้อมูล `birthWeekday` และข้อมูลอื่น ๆ
2. ข้อมูลโปรไฟล์จะถูกป้อนเข้าสู่ View Model `buildWeeklyTimingViewModel()` ซึ่งจะจำลองเป้าหมายเวลา 7 วัน (เริ่มต้นจากวันปัจจุบัน)
3. แต่ละวันจะถูกประมวลผลความสอดคล้องของรอบสุริยคติประจำสัปดาห์ (Solar Weekday Cycle) หากวันนั้นตรงกับวันเกิดทางดาราศาสตร์ประจำสัปดาห์ (เช่น วันพฤหัสบดีสำหรับคุณตั้ม) ระบบจะระบุค่า `isBirthWeekdayCycle: true` เพื่อแสดงผลการเตือนพักผ่อนและจัดระเบียบงานค้างในสไตล์ "Pause & Calibrate"
4. ผลลัพธ์ที่แปลงเสร็จสมบูรณ์จะถูกเรนเดอร์ในคอมโพเนนต์ `<AstroWeeklyPanel>`

## Fallback Behavior
- หากผู้ใช้ยังไม่มีข้อมูลวันเกิดเก็บอยู่ใน LocalStorage ระบบจะดึงค่าเริ่มต้นมาตรฐาน (ของคุณตั้ม - เกิดวันพฤหัสบดี) มาประมวลผลทันที
- หากระบบคำนวณเกิดการพังหรือเกิด Date parsing Error ระหว่างการรันไทม์ บล็อก `try-catch` จะดึงข้อมูลจำลองที่เตรียมไว้ในระบบแบบปลอดภัยมาประมวลผลแทน (Fallback Mode) ทำให้ระบบไม่มีการค้างหน้าจอขาวเด็ดขาด
