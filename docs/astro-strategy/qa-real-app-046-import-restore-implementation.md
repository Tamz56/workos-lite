# QA Record — ASTRO-REAL-APP-DEV-046: Import / Restore Implementation

เอกสารประกันคุณภาพและการประเมินการโอนย้ายข้อมูลสำหรับระบบนำเข้าและกู้คืนข้อมูลสำรอง (Import & Restore Quality Assurance)

---

## 1. Overview (ภาพรวมผลการประเมิน)

- **สถานะโดยรวม**: Passed (ผ่านการทดสอบคุณลักษณะการกู้คืนและความปลอดภัยข้อมูล)
- **วันเวลาที่ประเมิน**: 2026-06-08
- **เครื่องมือที่ใช้ตรวจสอบ**: ESLint, Next.js Build

---

## 2. Detailed QA Verification (รายละเอียดการประเมินแยกรายข้อ)

### ก. การแสดงผลตามเส้นทาง (Route Isolation Check)
- **Status**: Passed
- **Evidence**:
  - เส้นทางจริง `/workspaces/astro-strategy` ถูกตรวจสอบแล้วว่าไม่แสดงกล่องเครื่องมือข้อมูล (Data Tools Panel) และไม่มีปุ่มนำเข้า/ส่งออกข้อมูล
  - เส้นทางพรีวิว `/workspaces/astro-strategy/real-app-preview` แสดงแผงเครื่องมือข้อมูลและส่วนนำเข้าข้อมูลสำรองถูกต้องเฉพาะสำหรับผู้พัฒนา
- **Notes**: ป้องกันผู้ใช้ทั่วไปเข้าถึงฟังก์ชันระดับผู้ดูแลระบบเพื่อความปลอดภัยสูงสุด
- **Follow-up required**: ไม่มี

---

### ข. พฤติกรรมขั้นตอน Dry Run (Dry Run Validation & Safety Gate)
- **Status**: Passed
- **Evidence**:
  - การเลือกไฟล์ JSON เข้าไปประมวลผลเป็นเพียงการอ่านข้อมูลดิบด้วย `FileReader` และรันตัวแปลงโครงสร้างโดยไม่มีผลต่อ LocalStorage
  - ป้ายระบุผลลัพธ์ Dry Run รายงานค่าความเข้ากันได้ วันเวลา และขนาดข้อมูลดิบครบถ้วน
  - ปุ่มกู้คืนข้อมูลถูกล็อค (Disabled) ตลอดเวลาจนกว่า Dry Run จะตรวจจับไฟล์สกีมาที่สมบูรณ์และถูกต้องได้สำเร็จ
- **Notes**: รับประกันว่าจะไม่เกิดการอัปโหลดข้อมูลเข้าเบราว์เซอร์อัตโนมัติหากโครงสร้างชำรุด
- **Follow-up required**: ไม่มี

---

### ค. การตรวจสอบโครงสร้างและปฏิเสธข้อมูลไม่สมบูรณ์ (Validation Engine Tests)
- **Status**: Passed
- **Evidence**:
  - ทดสอบนำเข้าไฟล์ JSON ที่มีข้อความเสีย (Malformed JSON): ระบบแจ้งข้อผิดพลาดไวยากรณ์และบล็อกปุ่มกู้คืนข้อมูล
  - ทดสอบนำเข้าไฟล์แอปพลิเคชันอื่นที่มีชื่อแอปไม่ใช่ `"Astro Strategy Lab"` หรือเวอร์ชันไม่ใช่ `1`: ระบบประมวลผลและปฏิเสธข้อมูลตามกฎความปลอดภัย
  - ทดสอบนำเข้าไฟล์ที่มีคีย์แปลกปลอมหรือคีย์โปรโตไทป์เก่าปะปน: อะแดปเตอร์ทำการปฏิเสธไฟล์ทั้งหมดแบบอะตอมมิกทันที
- **Notes**: ปลอดภัยต่อการแทรกซึมข้อมูลจากไฟล์สำรองปลอม
- **Follow-up required**: ไม่มี

---

### ง. การโอนย้ายในโหมดผสานและแทนที่ (Restore Modes Actions)
- **Status**: Passed
- **Evidence**:
  - **Merge-Safe Mode**: ระบบสามารถรวมประวัติสะสมรายข้อโดยผสานเข้าด้วยกันตามรหัส `id` และไม่เขียนทับโปรไฟล์วันเกิดปัจจุบัน
  - **Replace Mode**: บังคับยอมรับการเขียนทับด้วย Checkbox บน UI ยืนยันความเสี่ยง พร้อมยืนยันกล่องข้อความ Dialogue ซ้ำอีกชั้นหนึ่ง ข้อมูลถูกเขียนทับครบถ้วนสมบูรณ์
- **Notes**: โหมด Merge-Safe ช่วยรักษาประวัติสะสมของผู้ใช้ให้คงอยู่อย่างมั่นคง
- **Follow-up required**: ไม่มี

---

### จ. การจำกัดสิทธิ์เขียนเฉพาะคีย์ที่กำหนด (Allowed Storage Keys Restriction)
- **Status**: Passed
- **Evidence**:
  - ระบบเขียนข้อมูลจำกัดขอบเขตคีย์เป้าหมายเฉพาะ `astro-real-app:*` ทั้ง 5 ตัวเท่านั้น
  - คีย์ระบบเก่าหรือคีย์ที่ไม่มีสิทธิ์ ถูกตัดทิ้งออกจากกระบวนการนำเข้าโดยสิ้นเชิง
- **Notes**: ป้องกันข้อมูลประวัติโปรโตไทป์เดิมสูญหาย
- **Follow-up required**: ไม่มี

---

### ฉ. ความเข้ากันได้ของฟังก์ชันอื่น ๆ ในระบบ (Regression Verification)
- **Status**: Passed
- **Evidence**:
  - หน้า Today Panel, Weekly Panel และ Monthly Panel ยังทำงานคำนวณและดึงค่าจาก LocalStorage ได้อย่างถูกต้อง
  - ฟังก์ชันฟอร์มโปรไฟล์วันเกิด (Birth Profile Form) และประวัติสะท้อนคิด (Reflection History) สามารถจัดเก็บและอ่านค่าข้อมูลที่กู้คืนมาได้ปกติ
  - ดราฟต์อัตโนมัติ (Reflection Draft Autosave) และ Onboarding Dismiss State ทำงานได้อย่างยอดเยี่ยม
- **Notes**: ทุกชิ้นส่วนหลังการกู้คืนข้อมูลไม่มีการแสดงผลขัดข้องหรือบั๊กใด ๆ
- **Follow-up required**: ไม่มี
