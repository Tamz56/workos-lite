# ASTRO-REAL-APP-DEV-081 — Composer Output Contract & Copy Safety Review

เอกสารกำหนดรูปแบบข้อมูลเอาท์พุตและระเบียบความปลอดภัยถ้อยคำภาษาสำหรับ **Natal + Transit Strategy Composer**

---

## 1. Goal (เป้าหมาย)

1. ล็อกสัญญาข้อมูลขาออก (**Output Contract**) ของตัวกลางประสานข้อมูลกลยุทธ์ (Composer) ในรูป TypeScript Interface เพื่อเตรียมความพร้อมในการสร้าง runtime Composer จริงในรอบพัฒนาถัดไป
2. ล็อกคลังภาษา คำชี้แนะเชิงกลยุทธ์ และกำหนดคำต้องห้ามเด็ดขาด เพื่อป้องกันการตีความเชิงทำนายชะตาร้าย หรือการชี้นำจนทำลายอำนาจตัดสินใจส่วนบุคคลของผู้ใช้งาน
3. มุ่งใช้ผลลัพธ์เพื่อนำมาสะท้อนสติ วางแผนบริหารความล้า สมาธิ และจัดสรรงานประจำวันตามบริบทสุขภาวะจริง

---

## 2. Output Interface Contract (โครงสร้างข้อมูลขาออก)

การกำหนดชนิดข้อมูล TypeScript Interface สำหรับเอาท์พุตหลัก:

```typescript
export interface SuppressedSignalDetail {
  readonly signalId: string;
  readonly sourceLayer: "natal" | "transit" | "history" | "engine" | "optional";
  readonly suppressionReason: string;
  readonly suppressedBy: "user_fatigue" | "today_engine_priority" | "low_confidence" | "duplicate";
  readonly confidenceImpact: number;
}

export interface NatalTransitStrategyComposerOutput {
  readonly layerName: string;                     // ชื่อชั้นข้อมูลประสานสัญญาณ (เช่น "Natal + Transit Strategy Composer")
  readonly source: string;                        // ซอร์สที่มาและเวอร์ชันซอฟต์แวร์
  readonly strategyDate: string;                  // วันเป้าหมายการประสาน (รูปแบบ YYYY-MM-DD)
  readonly strategyMode: "Focus" | "Stabilize" | "Pause" | "Review" | "Recover"; // โหมดสะท้อนสติหลัก
  readonly primaryRecommendation: string;          // สรุปคำชี้แนะหลักเชิงกลยุทธ์สูงสุด 1 ข้อ
  readonly secondaryRecommendation: string[];      // ข้อปฏิบัติย่อย 2-3 จุด
  readonly cautionLevel: "low" | "medium" | "high"; // ระดับสัญญะข้อพึงระวังสะท้อนสมอง
  readonly focusWindow?: string;                   // ช่วงเวลาที่สมาธิสมบูรณ์ที่สุด (optional)
  readonly workModePriority: string[];            // ลำดับประเภทงานที่เหมาะประจำวัน
  readonly recoveryPriority: string[];            // ลำดับวิธีการคืนพลังงานสมอง
  readonly decisionGuidance: string;               // แนวทางประเมินการตัดสินใจชิ้นใหญ่
  readonly supportingSignals: string[];            // รายการรหัสสัญญาณ (Signal IDs) ที่ผ่านการคัดสรรแล้ว
  readonly suppressedSignals: SuppressedSignalDetail[]; // รายการรายละเอียดสัญญาณที่ถูกปิดกั้น
  readonly conflictResolutionNotes: string;        // บันทึกคำอธิบายสั้นๆ ของการประสานตรรกะข้อขัดแย้ง
  readonly reflectionPrompt: string;              // คำถามสะท้อนคิดประจำวันหลังประสานสัญญาณ
  readonly confidenceNotes: string;               // บันทึกความน่าเชื่อถือและการ fallback
  readonly safetyDisclaimer: string;              // คำประกาศความปลอดภัยของข้อมูล
  readonly generatedAt: string;                   // เวลาประมวลผล (ISO timestamp)
}
```

## 3. Field Definitions (คำอธิบายฟิลด์ข้อมูล)

* **`strategyMode`**: ตัวกำหนดทิศทางใหญ่เชิงกลยุทธ์ที่ผ่านการประสานน้ำหนัก (เช่น หากพบดัชนีเหนื่อยล้าสูง จะสลับจาก Focus เป็น Recover/Pause เสมอ)
* **`primaryRecommendation`**: สรุปสมาธิหลักหนึ่งประโยคสั้นๆ เพื่อป้องกันการล้นของข้อมูล (Cognitive Overload)
* **`cautionLevel`**: ประเมินระดับความอ่อนไหวของสมาธิ ช่วยเตือนให้สังเกตสภาวะจิตใจ
* **`workModePriority`**: ลิสต์สั้นชี้แจงประเภทงานที่เหมาะ (เช่น งานตรวจทาน QA ดีบัก หรือ ร่างเอกสารย่อย)
* **`recoveryPriority`**: ลิสต์กิจกรรมเล็กๆ เพื่อคลายความเค้นของสมอง
* **`decisionGuidance`**: คำเตือนสติเกี่ยวกับการลงนามสัญญาหรือการเปิดประเด็นขัดแย้งใหญ่
* **`supportingSignals`**: ข้อมูลรหัสผ่านกรองเพื่อการวิเคราะห์ทางเทคนิคเบื้องหลัง
* **`suppressedSignals`**: เก็บประวัติว่ามีสัญญาณใดถูกระงับ เพื่อประโยชน์ในการดีบักตัว Orchestrator
* **`conflictResolutionNotes`**: คำอธิบายทางตรรกะว่าทำไมโหมดนี้จึงถูกเลือก (เช่น "ปรับเป็นโหมด Recover เนื่องจากผู้ใช้ระบุค่าความเหนื่อยล้าสะสมระดับ High ถึงแม้ดวงจรดาวจะส่งเสริมให้ลุยงานหนัก")
* **`confidenceNotes`**: คะแนนชี้วัดความครบถ้วนของลัคนาเกิดและวันเวลาจร หากข้อมูลขาดตกจะมีการปรับคะแนนลดลงและอธิบายโหมด fallback

---

## 4. Strategy Mode Policy (นโยบายการประเมินโหมด)

* **Focus**: เหมาะสำหรับการทำงานจดจ่อ ทำงานลอจิก สร้างสรรค์ และการดีลิเวอร์งาน
* **Stabilize**: เหมาะกับการตรวจทานความเสถียร จัดการงานเบื้องหลัง เคลียร์ระบบ (System clean-up)
* **Pause**: ควรหยุดนิ่ง ร่างแผนงานย่อย งดการสลับโปรเจกต์ถี่เกินไป
* **Review**: ตรวจทานทบทวนประวัติสะสม วิเคราะห์จุดตกหล่น
* **Recover**: มุ่งเน้นการนอนหลับพักผ่อน ฟื้นคืนสมาธิ บำบัดสติด้วยคลื่นเสียงจักระ
* **นโยบายความอิสระ**: ทุกโหมดเป็นเพียง **ข้อคิดสะท้อนเพื่อการวางแผนเชิงกลยุทธ์** ไม่ใช่คำสั่งตายตัว ผู้ใช้สามารถตัดสินใจเลือกทางเดินชีวิตจริงได้เสมอ หากพบดัชนีเหนื่อยล้าสูงเป็นตัวเหนี่ยวนำ โหมด Recover / Pause จะได้รับสิทธิ์ควบคุมก่อนเสมอ

---

## 5. Signal Priority Policy (นโยบายลำดับความสำคัญ)

การจัดลำดับการวิเคราะห์สัญญาณใน Composer:
1. **User Safety & Fatigue Index** (ระดับดัชนีสะสมความเหนื่อยล้าจริงจากผู้ใช้)
2. **Today Engine Mode** (โหมดคำแนะนำกลางจากแอป)
3. **Reflection History** (หลักฐานผลประเมินพฤติกรรมจริงในอดีต)
4. **Thai Transit** (สภาพดวงจรปัจจุบัน)
5. **Natal Baseline** (คุณลักษณะพื้นดวงกำเนิดหลัก)
6. **Optional layers** (ยามไทยอุบากอง และธาตุจีนประจำวัน)

---

## 6. Suppressed Signals Contract (โครงสร้างการปิดบังความถี่รบกวน)

ในการกรองสัญญาณรบกวน สัญญาณใดๆ ที่มีความน่าเชื่อถือต่ำ ขัดแย้งกับสเตตัสสุขภาพ หรือเป็นประเภทข้อแนะนำที่ซ้ำซ้อน จะถูกเก็บเข้า `suppressedSignals` โดยมีฟิลด์ดังนี้:
- `signalId`: รหัสสัญญาณดั้งเดิมที่ถูกระงับ
- `sourceLayer`: เลเยอร์ต้นทางของสัญญาณ
- `suppressionReason`: คำอธิบายเหตุผลในการระงับ (เช่น `"suppressed because user fatigue level is high"`)
- `suppressedBy`: กฎที่ใช้ระงับ (`"user_fatigue"`, `"today_engine_priority"`, `"low_confidence"`, หรือ `"duplicate"`)
- `confidenceImpact`: ผลกระทบต่อคะแนนความมั่นใจรวมของวัน

---

## 7. Conflict Resolution Notes (การเขียนบันทึกประสานความขัดแย้ง)

- ต้องอธิบายเหตุผลสั้นกระชับเข้าใจง่าย
- ห้ามใช้คำอ้างสิทธิ์เหนือดวง เช่น "ชะตากำหนดให้ปรับตัว" หรือ "ดวงบีบบังคับ"
- ต้องเน้นการตัดสินใจเชิงตรรกะว่าระบบปกป้องสุขภาวะและลดภาระทางสมองของผู้ใช้
- หากข้อมูลนำเข้าไม่เพียงพอ ต้องชี้แจงใน `confidenceNotes` ทันที

---

## 8. Safe Copy Patterns (รูปแบบถ้อยคำภาษาที่ปลอดภัยและแนะนำ)

* ✔️ *"วันนี้เหมาะกับการจัดลำดับงานที่ค้างให้ชัดเจน"*
* ✔️ *"ควรเริ่มจากชิ้นงานที่สามารถปิดจบได้ง่ายเพื่อสะสมความมั่นใจ"*
* ✔️ *"เหมาะแก่การตรวจทาน ตรวจสอบความถูกต้อง (QA) และเคลียร์ไฟล์ระบบเบื้องหลัง"*
* ✔️ *"หากรู้สึกล้าสะสม แนะนำให้ลดน้ำหนักของงานประเภทที่ต้องใช้พลังการตัดสินใจสูง"*
* ✔️ *"ใช้จังหวะเวลานี้เป็นสัญญาณแวดล้อมเพื่อประกอบการไตร่ตรองเท่านั้น ไม่ใช่ข้อยุติ"*
* ✔️ *"ควรเว้นพื้นที่สั้นๆ สำหรับการหยุดทบทวนและการพักสายตาระหว่างรอบงาน"*

---

## 9. Forbidden Copy Patterns (ถ้อยคำภาษาต้องห้ามเด็ดขาด)

* ❌ **เคราะห์ / ซวย / กาลกิณี / ดวงบังคับ** (สร้างความตื่นตระหนกและละเมิดความเชื่อส่วนบุคคล)
* ❌ **อุบัติเหตุ / เงินเสียแน่ / งานพัง / ความรักพัง** (คำทำนายเหตุการณ์ล่วงหน้าแบบเจาะจง)
* ❌ **ห้ามทำเด็ดขาด / ต้องทำวันนี้เท่านั้น / ถ้าไม่ทำจะเสียโอกาส** (คำพูดที่ทำลายความอิสระส่วนบุคคล)
* ❌ คำทำนายด้านสุขภาพร่างกาย การวินิจฉัยโรค หรือทิศทางการรักษาทางการแพทย์
* ❌ คำทำนายผลลัพธ์การเสี่ยงโชค การเงิน หรือหุ้นในสัญญะฟันธงล่วงหน้า

## 11. Storage & Export Compatibility (ความเข้ากันได้ของการสำรองข้อมูล)

- **Runtime Compute Only**: ตัว Composer v0.1 จะประมวลผลบนหน่วยความจำ RAM เท่านั้น ไม่มีการจัดเก็บข้อมูลผลลัพธ์ลง LocalStorage
- **Future Persistence Plan**: หากจำเป็นต้องจัดเก็บในอนาคต จะบันทึกเฉพาะชุดรหัสย่อย `supportingSignals` และ Metadata ขนาดสั้น ห้ามจัดเก็บถ้อยคำข้อความสรุปขนาดยาว (Long copy) เพื่อประหยัดพื้นที่จัดเก็บ
- **Data Isolation**: การนำเข้า/ส่งออก และฟื้นฟูข้อมูลเดิมของระบบ (Export / Import / Restore) จะไม่เกิดความบกพร่องเนื่องจากระบบดัดแปลงตัวเก็บข้อมูลนี้

---

## 12. UI Compatibility (ทัศนวิสัยและการเรนเดอร์หน้าจอ)

Composer จะไม่สร้างการ์ดกล่องข้อความทับซ้อนเพิ่มขึ้นมาใน Today Tab ของแอป แต่จะรับหน้าที่กลั่นกรองสรุปทิศทางลงใน `AstroTodayPanel` เดิมตามสเปก:
1. การระบุหัวข้อนำทางเด่นสุด 1 ข้อ (1 main recommendation)
2. การแจ้งระดับการเตือนสติหรือข้อพึงระวังย่อย 1 ข้อ (1 caution note)
3. การแนะนำวิธีการฟื้นฟูพลังงานเล็กๆ 1 ข้อ (1 recovery note)
4. การเสนอคำถามชี้แนะชวนสะท้อนสติ 1 คำถาม (1 reflection prompt)
