# ASTRO-REAL-APP-DEV-071 — Thai Natal Chart Calculation Plan

## 1. Goal
วางแผนการคำนวณและประมวลผลแผ่นดวงชะตากำเนิดไทยขั้นต้น (Thai Natal Chart Calculation Plan v0.1) สำหรับเป็นคู่มือและแผนผังตรรกะในอนาคตของ Astro Strategy Lab โดยจะนำข้อมูลการเกิดจริงของบุคคล (วันเกิด เวลาเกิด พิกัดสถานที่เกิด และเขตเวลา) มาประมาณการพิกัดทางดาราศาสตร์เพื่อสร้าง **"Birth Pattern"** หรือ **"Natal Strategy Profile"** ที่สามารถชี้วัดศักยภาพ สไตล์การทำงาน วินัยการตัดสินใจ และความทนทานต่อสมาธิ โดยปราศจากการทำนายชีวิต โชคชะตา หรือสัญญะชะตาขาดเชิงลี้ลับใด ๆ

---

## 2. Input Requirements
การประมวลผลดวงกำเนิดต้องการข้อมูลเข้าที่สมบูรณ์เพื่อให้เกิดความแม่นยำสูงสุด ดังนี้:

* **birthDate**: วันเดือนปีเกิดจริงของบุคคล (รูปแบบสากล `YYYY-MM-DD`)
* **birthTime**: เวลาเกิดจริง (รูปแบบสากล `HH:MM` แบบ 24 ชั่วโมง)
* **birthPlace**: ชื่อเมือง/อำเภอและจังหวัดเกิดเพื่อบันทึกประวัติอ้างอิง
* **latitude**: พิกัดละติจูดของสถานที่เกิด (จุดทศนิยม 4 ตำแหน่ง เช่น `13.7563`)
* **longitude**: พิกัดลองจิจูดของสถานที่เกิด (จุดทศนิยม 4 ตำแหน่ง เช่น `100.5018`)
* **timezone**: เขตเวลา ณ วันเกิดของผู้ใช้ตามมาตรฐานฐานข้อมูล IANA (เช่น `"Asia/Bangkok"`)
* **calendarSystem**: ล็อกระบบการคำนวณแบบปฏิทินไทยสุริยคติ/จันทรคติย่อ
* **optionalLunarInfo**: ข้อมูลข้างขึ้น/ข้างแรมเพิ่มเติม (หากบันทึกมาด้วย)
* **dataConfidence / missing-field note**: กลไกตรวจสอบความน่าเชื่อถือของข้อมูล หากผู้ใช้ไม่ได้ระบุเวลาเกิด พิกัดองศา หรือเขตเวลา ระบบจะตั้งค่า `confidenceScore` ต่ำลง และแสดงบันทึกเตือนความคลาดเคลื่อนที่เป็นไปได้บนหน้าจอวิเคราะห์

## 3. Calculation Scope v0.1
การคำนวณในเวอร์ชันแรกจะจำกัดขอบเขตการคำนวณดาราศาสตร์ทางเลือกให้อยู่ในรูปแบบประหยัดทรัพยากร (Rule-based & Approximation):

* **ลัคนาโดยประมาณ (Approximated Ascendant)**: คำนวณอันโตนาทีจำลองหรือตารางเวลาอาทิตย์ขึ้นเฉลี่ยตามละติจูดท้องถิ่นเพื่อหาราสีลัคนาเกิดโดยประมาณ
* **ราศีของลัคนา (Ascendant Sign)**: กำหนดราศีลัคนา (เมษ - มีน) เพื่อเป็นพิกัดจุดเริ่มต้นในการจัดเรือนชะตา
* **เรือนชะตา 12 เรือน (House System)**: สร้างระบบเรือนชะตาสัมพันธ์แบบดั่งเดิม (Equal House System) โดยเริ่มนับเรือนที่ 1 (ตนุ) จากราศีที่ลัคนาสถิต หมุนทวนเข็มนาฬิกาจนครบ 12 เรือน
* **ตำแหน่งดาวเคราะห์แบบ Approximation**: ใช้หลักการคำนวณตรรกะแบบถอยหลังอิงวันที่เฉลี่ย (Interpolation) หรือ Placeholder ตรรกะแบบ Rule-based เพื่อสกัดหาช่องราศีที่ดาวเคราะห์ทั้ง 10 ดวงสถิต โดยยังไม่มีการเรียกใช้ Ephemeris Engine ขนาดใหญ่
* **ธาตุเด่นจากราศีและดาวเคราะห์**: วิเคราะห์จุดสมดุลพลังงานสี่ธาตุโดยสรุปคะแนนจากตำแหน่งลัคนาและดาวเคราะห์ที่ไปสถิตในราศีธาตุต่าง ๆ (เช่น ราศีกลุ่มไฟ ธาตุไฟในดวงเกิดจะได้คะแนนสูงขึ้น)
* **การจัดตำแหน่งดาวสถิตเรือน (Planet-to-House Placements)**: สกัดความสัมพันธ์ว่าดาวดวงใดอยู่ในเรือนชะตาใด (เช่น ดาวพุธ(4) อยู่ในเรือนกัมมะ ชี้วัดสไตล์งานสื่อสาร)
* **การส่งสัญญาณดวงชะตากลยุทธ์ขั้นต้น (Basic Natal Strategy Signals)**: สกัดรหัสสัญญะเปรียบเทียบพฤติกรรมการทำงานส่วนบุคคล

## 4. Calculation Non-scope (ขอบเขตที่ไม่ทำในระบบคำนวณ)
* **ไม่คำนวณสมผุสดาวเคราะห์องศาละเอียด**: ไม่มีการคำนวณองศาลิปดาทดทศนิยมของดาวเคราะห์ 10 ดวงที่ต้องการความแม่นยำสูงระดับปีแสงทางกายภาพจริง
* **ไม่ใช้ระบบ ephemeris สำเร็จรูปภายนอกขนาดใหญ่**: หลีกเลี่ยงการนำเข้าไลบรารีดาราศาสตร์ที่สร้างภาระการดาวน์โหลดหน้าเว็บ
* **ไม่คำนวณแผนภาพซับซ้อนระดับปลีกย่อย**: ไม่คำนวณหาแผ่นดวงนวางค์จักร ตรียางค์จักร ฤกษ์ย่อย นวคระหะ หรือสิบกาลโยคในเฟสนี้
* **ไม่แปลการทำมุมส่งกระแสส่งอิทธิพลเต็มรูปแบบ (No Aspect Interpretation)**: จะไม่มีการประเมินมุมตรีโกณ จตุโกณ หรือมุมโยคระหว่างดาวครบทุกดวง
* **ไม่ทำ MyHora Clone**: จะไม่มีการเรนเดอร์กราฟิกแผ่นดวงกลมสำหรับให้หมอดูอาชีพใช้อ่านชะตากรรม
* **ไม่เขียนข้อความพยากรณ์ลี้ลับ**: แบนระบบตีความเคราะห์กรรม ปัญหาสุขภาพ อุบัติเหตุความตาย หรือความราบรื่นทางการเงินส่วนบุคคลอย่างสิ้นเชิง

## 5. Approximation Strategy
เพื่อให้ระบบแบบ Local-first ทำงานได้อย่างเสถียรและยืดหยุ่น:
* **การประมาณการเชิงสัญลักษณ์ (Symbolic Planning Approximation)**: การประมาณตำแหน่งดาวลัคนาใน v0.1 จะยึดถือเอาเพื่อใช้สะท้อนแนวโน้มพฤติกรรมการจัดการสมาธิและชีวิต ไม่ใช่เพื่อผลการตัดสินใจทางธุรกิจที่เด็ดขาด
* **มาตรการกรณีขาดข้อมูลเวลาเกิด**: หากเวลาเกิดไม่ระบุ (ผู้ใช้กรอก "ไม่ทราบเวลาเกิด") ระบบจะตั้งค่าสเตตัสเริ่มต้นเป็นเวลาเที่ยงวัน (12:00 น.) เพื่อหาตำแหน่งเฉลี่ยดาวเคราะห์ และปรับลดค่า `confidenceScore = 0.5` พร้อมระบุเตือน *"คำนวณโดยไม่มีเวลาเกิดลัคนาอาจมีความคลาดเคลื่อนสูง"*
* **มาตรการกรณีขาดพิกัดละติจูด/ลองจิจูด**: ระบบจะกำหนด fallback อิงตามเมืองหลวงของจังหวัดเกิดที่ผู้ใช้เลือกจากรายการดั้งเดิม
* **มาตรการกรณีขาดข้อมูลเขตเวลา**: Fallback ไปที่เขตเวลาเครื่องหรือ `"Asia/Bangkok"` กรณีระบุสถานที่เกิดในประเทศไทย
* **บันทึกความน่าเชื่อถือ (confidenceNotes)**: จะต้องแสดงผลระบุระดับความน่าเชื่อถือของข้อมูลให้ผู้ใช้ทราบทุกครั้งบนบอร์ดวิเคราะห์

## 6. Output Contract Concept
โครงสร้างสัญญาข้อมูลส่งกลับจากระบบคำนวณ (Calculation Layer Output):

```typescript
export interface ThaiNatalChartCalculationOutput {
  /** ราศีลัคนาเกิด */
  readonly ascendantZodiac: string;
  /** องศาลัคนาเกิดโดยประมาณ */
  readonly ascendantDegreeApprox: number;
  /** ความสัมพันธ์ของราศีและเรือนชะตาทั้ง 12 */
  readonly houseMap: Record<string, string>; // เช่น {"aries": "tanu", "taurus": "kadumpa"}
  /** สรุปตำแหน่งดาวเคราะห์ 10 ดวง */
  readonly planetPlacementSummary: {
    readonly planetId: number;
    readonly zodiacSign: string;
    readonly houseId: string;
    readonly approximateDignity: string;
  }[];
  /** สัดส่วนคะแนนสี่ธาตุเกิด */
  readonly dominantElements: {
    readonly earth: number;
    readonly water: number;
    readonly wind: number;
    readonly fire: number;
  };
  /** รหัสสัญญาณวิถีการทำงานส่วนบุคคล */
  readonly workStyleSignals: string[];
  /** รหัสสัญญาณพฤติกรรมการตัดสินใจ */
  readonly decisionStyleSignals: string[];
  /** รหัสสัญญาณการพักผ่อนฟื้นฟู */
  readonly recoverySignals: string[];
  /** บันทึกอธิบายระดับความมั่นใจของข้อมูลวิเคราะห์ */
  readonly confidenceNotes: string;
  /** คำเตือนความปลอดภัยจริยธรรมข้อมูล */
  readonly safetyDisclaimer: string;
}
```

## 7. Strategy Interpretation Boundary (ขอบเขตการคำนวณและการตีความ)
ระบบจะแยกส่วนแบ่งหน้าที่ระหว่างเลเยอร์คำนวณและเลเยอร์ตีความกลยุทธ์ออกจากกันอย่างชัดเจน:
* **Calculation Layer**: มีหน้าที่ประมวลผลคำนวณตำแหน่งองศา ราศี เรือนชะตา และตรวจสอบมาตรฐานดาวดวงเกิดหรือดาวจร แล้วสกัดออกมารหัสเป็นสัญญาณเชิงเทคนิคแบบแห้ง (technical signal IDs) เท่านั้น ห้ามเขียนคำทำนายขยายประโยคด้วยตนเอง
* **Interpreter Layer (and Dictionary)**: มีหน้าที่รับข้อมูลรหัสวิเคราะห์ แล้วจับคู่แสดงผลผ่านคลังข้อความภาษาไทย (Client-side Dictionary) และสกัดเป็นคำแนะนำกลยุทธ์การทำงานและการประคองสุขภาพจิตเพื่อแสดงบน UI ป้องกันโค้ดบวมและรักษาความสะอาด

## 8. Safety & Ethics Rules
การจำกัดการใช้ถ้อยคำเพื่อปกป้องสภาพอารมณ์ของผู้ใช้:
* **คำที่ถูกแบนโดยสิ้นเชิง**: ห้ามให้ข้อความคำนวณแสดงคำทำนายตายตัว เช่น *"จะเกิดปัญหาแน่นอน"*, *"เคราะห์ร้ายใหญ่หลวง"*, *"สูญเสียทรัพย์สินหรือเกิดคดีความ"*, *"ความรักล้มเหลว"*, *"เสี่ยงอันตรายคอขาดบาดตาย"*
* **ภาษาทดแทนที่เป็นทางเลือกทางความคิดเชิงบวก**:
  - *"มีแนวโน้มพึงระมัดระวังในเรื่องการสื่อสารที่รวดเร็วเกินไป"*
  - *"จังหวะรอบวันช่วงนี้เอื้อต่อการทบทวนความถูกต้องของระบบข้อตกลง"*
  - *"ชะลอการเปิดโครงการใหม่ และหันมาปิดเป้าหมายย่อยเดิม"*
  - *"จัดสรรรอบเวลาทำงานให้มีจุดผ่อนปรนสมดุลธาตุน้ำเพื่อลดอาการตึงสมอง"*
  - *"หลีกเลี่ยงการสลับหน้าจองานบ่อย (Context Switching)"*

## 9. Relationship to DEV-072
* **DEV-071 (Natal Chart Calculation Plan)**: วางแผนสร้างระบบแผ่นดวงเกิดส่วนบุคคล (Natal Chart Baseline) ซึ่งเปรียบเสมือนแผ่นบันทึกคุณสมบัติพื้นฐานเฉพาะตัวที่จะไม่มีการเปลี่ยนแปลงตราบเท่าชีวิต
* **DEV-072 (Transit Timing Calculation Plan)**: จะเป็นแผนคำนวณกระแสการเคลื่อนที่ของดวงดาวจร ณ เวลาปัจจุบัน (Transit Movement) ซึ่งทำหน้าที่เสมือนลมฟ้าอากาศที่พัดผ่านเข้ามาทำมุมส่งผลดีหรือผลร้ายชั่วคราวต่อจุดพิกัดในแผ่นดวงเกิด
