# ASTRO-REAL-APP-DEV-074 — Thai Transit Adapter v0.1 Implementation Plan

## 1. Goal
จัดทำแผนการสร้างตัวประมวลผลดวงจรไทย (Thai Transit Adapter v0.1 Implementation Plan) สำหรับเป็นแผนแม่บทเชิงสถาปัตยกรรม (Architectural Blueprint) ของแอปพลิเคชัน Astro Strategy Lab ใน ArborDesk โดยมีหน้าที่รับพารามิเตอร์วันเกิด ลัคนากำเนิด วันเวลาเป้าหมายจร เพื่อนำมาคัดแยกสัญญะดาวจรตกเรือนสัมพันธ์และแปลงออกมาเป็นกลุ่มรหัสสัญญาณกลยุทธ์การทำงานและการจัดเวลาพักผ่อน โดยที่เอกสารนี้มีเป้าหมายเชิงทฤษฎีและจะยังไม่มีการเขียนโค้ดรันไทม์จริงในขั้นตอนการทำงานนี้

## 3. Adapter Responsibilities (หน้าที่รับผิดชอบของตัวแปลง)
* **รับข้อมูลขาเข้าดวงเกิด**: รับผลลัพธ์โครงสร้าง `natalChartCalculationOutput`
* **รับพารามิเตอร์เป้าหมายจร**: รับค่า `targetDate` / `targetTime` / `timezone`
* **ประมาณการดาวจรบนท้องฟ้า**: ประเมินพิกัดดาวจร 10 ดวง แบบ Rule-based อ้างอิงตารางเฉลี่ย
* **คำนวณดาวจรตกเรือนสัมพันธ์**: เทียบราศีปัจจุบันดาวจรคู่กับราศีลัคนาของแผ่นดวงเกิด
* **ส่งกลับรายการเรือนจรทำงาน (activeTransitHouses)**: ลิสต์เรือนชะตาที่ถูกดาวสำคัญกุมอยู่ในปัจจุบัน
* **ส่งกลับผลกระทบเรือนกำเนิด (natalHouseImpacts)**: ชี้วัดระดับความเครียด/ความราบรื่นในเรือนชะตา
* **ส่งกลับสมดุลธาตุรอบวัน (elementRelationship)**: ประเมินความขัดแย้งของธาตุจรกับธาตุเกิด
* **ส่งกลับรหัสสัญญาณกลยุทธ์ (Short IDs)**: สร้างรายการ `workTimingSignals`, `decisionCautionSignals`, และ `recoverySignals`
* **ส่งต่อ metadata ความถูกต้อง**: แนบข้อมูล `confidenceNotes` และ `safetyDisclaimer` ไปกับออบเจ็กต์ข้อมูล

---

## 4. Non-Responsibilities (สิ่งที่ตัวแปลงต้องไม่รับผิดชอบ)
* **ไม่บรรจุหรือเขียนประโยคทำนายขนาดยาว**: หลีกเลี่ยงการเขียนสคริปต์ข้อความยาวในตัว Adapter เพื่อคงความกระชับ
* **ไม่เรนเดอร์ชิ้นส่วน UI เอง**: ทำหน้าที่สกัดพิกัดข้อมูลดิบเท่านั้น (Pure Logic Adapter)
* **ไม่เขียนข้อมูลผลลัพธ์ลง LocalStorage**: ทำการประมวลผลสดบนหน่วยความจำเบราว์เซอร์เท่านั้น
* **ไม่แก้ไข Schema ประวัติเดิม**: ป้องกันข้อมูลประวัติสะท้อนคิดเดิมเสียหาย
* **ไม่เชื่อมต่อระบบออนไลน์ภายนอก**: รันตรรกะแบบ Local-first 100% บนเบราว์เซอร์ของผู้ใช้
* **ไม่คำนวณองศาลิปดาดาราดาราศาสตร์ละเอียด**: หลีกเลี่ยงความหน่วงของเครื่อง
* **ไม่ทำ MyHora Clone**: ปฏิเสธการสร้างกราฟดวงจักร

---

## 5. Calculation Approximation Strategy
* **การจำลองแบบ Rule-based**: ใช้ปฏิทินตำแหน่งดวงดาวเฉลี่ยรายสัปดาห์/รายเดือนแทน Ephemeris Engine ขนาดใหญ่
* **การชี้แจงความแม่นยำ**: กำหนดสถานะความสมบูรณ์และพิกัดองศาเป็นค่า "ประมาณการเชิงสัญญะ"
* **การตั้งค่ากรณีไม่มีข้อมูลดาวจร**: หากตำแหน่งพิกัดดาราศาสตร์ของดาวจรไม่มี ให้ระงับกล่องข้อชี้แนะเฉพาะจุด และ fallback เป็นข้อมูลประมาณการรอบสากลแทน
* **บันทึกระดับความน่าเชื่อถือ**: ต้องแนบคำชี้แจง `confidenceNotes` ชี้แจงระดับความถูกต้องของเวลาเกิดและพิกัดทุกครั้ง
* **การป้องกันขอบเวลา (Timezone Guard)**: ตั้งพิกัดคำนวณเที่ยงตรง (12:00 น.) ของวันจร เพื่อเป็นกันชนความคลาดเคลื่อนเวลาเครื่องผู้ใช้สลับโซนเวลา

## 6. Dictionary Strategy
* **การใช้อ้างอิงรหัสสัญญาณสั้น (Signal IDs)**: กำหนดสัญญาณเป็นตัวอักษรไม่เกิน 20 อักขระ (เช่น `TH_SIG_QA_REVIEW`)
* **คลังแปลภาษาฝั่งไคลเอนต์**: แยกเก็บข้อความคำแปลยาวๆ ไว้ในโครงสร้าง Dictionary ปลายทาง ป้องกันข้อความขยายใหญ่แทรกซึมไปสู่ประวัติสะท้อนคิด
* **การลดขนาด Backup**: ช่วยประหยัดเนื้อที่การส่งออกและนำเข้าข้อมูล JSON

## 7. Strategy Mapper Design
โครงร่างตรรกะแปลงพิกัดสัมพันธ์เรือนจรเข้าสู่กิจกรรมการปฏิบัติงานประจำวัน:
* **กัมมะ (Kamma)** -> แมปเป็น `recommendedWorkModes: ["structured_work", "system_design"]` (งานหลัก, งานออกแบบโครงสร้างระบบ)
* **อริ (Ari)** -> แมปเป็น `recommendedWorkModes: ["qa_testing", "debugging"]` (การหาบั๊ก, งานดีบัก, ล้างความเสี่ยง)
* **ลาภะ (Lapa)** -> แมปเป็น `recommendedWorkModes: ["delivery", "summary_notes"]` (งานส่งมอบ, การเขียน checkpoint)
* **วินาศ (Vinas)** -> แมปเป็น `recommendedWorkModes: ["research", "system_cleanup"]` (งานค้นคว้าเบื้องหลัง, งานลบโค้ดเก่า)
* **ปัตนิ (Patni)** -> แมปเป็น `recommendedWorkModes: ["meeting", "agreements"]` (การประชุมรับฟัง, การร่างสัญญา)

## 8. Composer Design (ตัวจัดสรรและผสานความขัดแย้ง)
* **แผ่นดวงเกิด (Natal Baseline)**: ระบุขอบเขตศักยภาพและจุดสมาธิหลักคงที่
* **ดวงจรปัจจุบัน (Transit Timing)**: เป็นสัญญาณชี้แนะชั่วคราวดังเช่นสภาพอากาศประจำวัน
* **ประวัติอารมณ์จริง (Reflection loop)**: คือจุดตัดสินสุดท้าย
* **Today Engine Priority**: ตรรกะของเอนจิ้นหลัก Today Engine คุมพลังงานสูงสุด
* **เกณฑ์ Low-burnout priority**: หากผู้ใช้ลงบันทึกในระบบสะท้อนคิดว่ามีความล้าสะสมสูง แม้ดาวจรจะมีเกณฑ์ดีเยี่ยมให้ลุยงานหนัก ตัว Composer จะสั่ง **"สลับข้อความแนะแนวให้ออกแนวตั้งหลักพักผ่อนเป็นสำคัญอันดับแรก"** โดยดวงจรไม่มีสิทธิ์ override หรือบังคับให้เปิดงานใหม่

## 10. Safety & Copy Guardrails
* **การควบคุมขอบเขตภาษา**: ตัวแปลงจะส่งออกเฉพาะ IDs รหัสและข้อมูลเชิงตัวแปร
* **การจำกัดคำต้องห้าม**: จะใช้ Dictionary ที่กรองล้างข้อความขู่เรื่องอุบัติเหตุ เคราะห์ ความตาย การแตกหักการเงินและความสัมพันธ์ออกไปอย่างสมบูรณ์
* **ข้อชี้แนะนำเชิงทางเลือก**: การจัดฟอร์แมตภาษาปลายทางจะแนะนำในลักษณะข้อสังเกตและตัวเลือกปรับใช้ เพื่อมอบความเป็นอิสระและสติปัญญาให้แก่ผู้ใช้สูงสุด

## 11. Testing Plan for Future DEV-075
แผนการทดสอบแบบครอบคลุมล่วงหน้าเพื่อเตรียมพร้อมในการพัฒนารันไทม์:
1. **กรณีขาดดวงชะตากำเนิด (missing natal chart)**: ตรวจสอบว่าระบบส่งกลับ fallback note และไม่ทำตัวเว็บล่มเสียหาย
2. **กรณีเวลาเป้าหมายคลาดเคลื่อน (missing target time)**: ตรวจสอบการ fallback เวลาประมวลผลช่วงกลางวัน
3. **การตกโซนเวลาเบราว์เซอร์ (timezone fallback)**: จำลองเครื่องผู้ใช้ข้ามซีกโลก
4. **ตารางดาวจรไม่มีข้อมูล (transit positions unavailable)**: ตรวจสอบการซ่อนตัวของการ์ดดวงจรอย่างเงียบเชียบ
5. **ภาวะสมองล้าปะทะดาวจรตึงเครียดหนัก (high pressure + high fatigue reflection)**: ตรวจเช็คการสลับแสดงผลลัพธ์เป็น Pause
6. **ความขัดแย้งดาวส่งลุยกับอารมณ์ผู้ใช้ล้า (conflicting supportive transit + tired user)**: ยืนยันว่า Low-burnout priority ทำงานป้องกันอาการหมดไฟได้ถูกต้อง
7. **สแกนข้อความคำศัพท์ปลอดภัย (safe copy scan)**: ตรวจหาคำลี้ลับ/คำเตือนอันตรายทางกายภาพต้องไม่มีใน Dictionary
8. **ความเข้ากันได้ของการสำรองข้อมูล (export/import compatibility)**: ตรวจสอบโครงร่างการพกพาไฟล์ JSON เก่ายังผ่าน Validator 100%
9. **ความสะอาดของ Storage (no LocalStorage write)**: การทดสอบรันต้องไม่มีคีย์ประมวลผลจรถูกเขียนลงพื้นที่ LocalStorage
