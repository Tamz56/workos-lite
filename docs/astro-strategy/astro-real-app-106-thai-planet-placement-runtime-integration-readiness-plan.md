# Thai Planet Placement Runtime Integration Readiness Plan (DEV-106)

เอกสารวางแผนความพร้อมในการผสานการทำงานระบบการประมาณตำแหน่งดาวเคราะห์ไทยรุ่นรันไทม์จำลอง (Thai Planet Placement Runtime Stack) เข้ากับแผงควบคุมและส่วนติดต่อผู้ใช้ของ Astro Strategy Workspace ในเฟสถัดไป เพื่อให้มั่นใจในความมั่นคงปลอดภัยและความเป็นเอกเทศเชิงข้อมูล

---

## 1. Purpose (วัตถุประสงค์)

แผนเตรียมความพร้อมรอบ DEV-106 นี้จัดทำขึ้นเพื่อกำหนดเงื่อนไขความพร้อมและมาตรการป้องกันความปลอดภัย ก่อนที่จะนำเอาระบบคำนวณจำลองและระบบกักภัยข้อมูลตำแหน่งดาวเคราะห์ไทย 10 ตำแหน่ง (ดาว ๐ ถึง ๙) เข้าสู่ส่วนติดต่อผู้ใช้จริง (UI) หรือการทำงานของโมดูลอื่นๆ ในโปรเจกต์ ซึ่งจะช่วยคัดกรองความปลอดภัยและป้องกันพฤติกรรมผิดพลาดจากการนำข้อมูลจำลองไปใช้งานจริง

---

## 2. Scope and Non-goals (ขอบเขตและข้อกำหนด)

* **ขอบเขตการทำงาน (Scope)**:
  * การวิเคราะห์ความพร้อมในเชิงทฤษฎีและขอบเขตทางวิศวกรรมข้อมูล
  * การกำหนดแม่แบบส่วนติดต่อผู้ใช้ทางเลือกสำหรับการวินิจฉัย (Diagnostics / Debug Mode)
  * การวางกฎระเบียบ Copy Safety สำหรับคำอธิบายทางวิชาการ
  * การแยกส่วนโครงสร้างการอิมพอร์ตโค้ด (Technical Integration Boundary)
* **ขอบเขตที่ยกเว้น (Non-goals)**:
  * **ไม่มีการเชื่อมต่อ UI จริง**: จะไม่มีการอิมพอร์ตตัวประสานงานเข้าสู่หน้าจอแอปพลิเคชันหลักในรอบนี้
  * **ไม่มีการเข้าถึง LocalStorage**: ห้ามเขียนข้อมูลตำแหน่งดาวเกิดไทยลงในเบราว์เซอร์
  * **ไม่มีการคำนวณจริง**: จะไม่มีการเพิ่มลอจิกการคำนวณมุมดวงดาว ราศี หรือองศาทางดาราศาสตร์จริง
  * **ไม่มีการเคลมผลพยากรณ์**: จะไม่มีคำอธิบายหรือคำทำนายที่สื่อถึงโชคชะตาหรือการฟันธงเด็ดขาด
  * **ไม่มีการดึงข้อมูลจากแหล่งภายนอก**: ไม่มีการดึงข้อมูลผ่านระบบ scraping จากเว็บโหราศาสตร์อื่นๆ

---

## 3. Current Runtime Stack Summary (สรุปสถานะรันไทม์ปัจจุบัน)

โครงสร้างรันไทม์ที่พัฒนาเสร็จสิ้นแล้วในรอบก่อนหน้าประกอบด้วย:
1. **DEV-099 Stub (โครงร่างจำลอง)**: ตัวแทนโครงร่างตำแหน่งดาว ๐ ถึง ๙ คืนค่าสถานะเป็น `pending-reference-validation` และสถานะพิเศษเป็น `unavailable`
2. **DEV-100 Safety Harness (ระบบกักกันความปลอดภัย)**: ตรวจสอบความถูกต้องและสกัดกั้นค่าจำลอง โดยคืนค่าเทียบเคียงเป็น `not-comparable` และตั้งค่าจำนวนเทียบเคียงได้เป็น 0
3. **DEV-101 Orchestrator (ตัวประสานงานรันไทม์)**: ฟังก์ชัน `buildThaiPlanetPlacementRuntimeAdapterV01` ประสานการดึงข้อมูลจาก Stub และ Safety Harness ร่วมกันพร้อมประทับเวลา `generatedAt` แบบชั่วคราว
4. **DEV-105 Manual Diagnostic Script Stub**: สคริปต์ตรวจความถูกต้องของโครงสร้างสัญญาในระดับนักพัฒนาเครื่องถิ่น (Local-only CLI)

---

## 4. Integration Readiness Checklist (รายการตรวจสอบความพร้อมก่อนผสานงาน)

ก่อนทำการเชื่อมต่อตัวประสานงาน (Orchestrator) เข้าสู่ UI ในเฟสถัดไป ระบบจำต้องผ่านการตรวจสอบตามรายการด้านล่าง:
* [ ] Orchestrator คืนค่าผลลัพธ์ตำแหน่งดาวครบถ้วนทั้ง 10 ดวง (Planet ID 0–9)
* [ ] ทุกผลลัพธ์ดวงดาวยังคงเป็น `pending-reference-validation` หรือ `unavailable` (ห้ามมีค่าราศี/องศาจริงปะปน)
* [ ] ค่าฟิลด์ `adapterStatus` ได้รับการยืนยันว่าเป็น `stub-only`
* [ ] ระบบกักภัยความปลอดภัย (Safety Summary) แสดงผลความสัมพันธ์และจำนวนเทียบเคียงได้เป็น 0 รายการ
* [ ] สคริปต์วินิจฉัยควบคุมสามารถเรียกใช้ผ่าน Node.js ในเครื่องถิ่นได้สำเร็จ
* [ ] ไม่พบจุดอิมพอร์ตของ Orchestrator ปรากฏในไฟล์ฝั่ง UI ปัจจุบัน
* [ ] ไม่มีการประมวลผลหรือบันทึกข้อมูลของ Adaptor เข้าสู่วงจรอ่านเขียน LocalStorage
* [ ] กำหนดนโยบายระเบียบการใช้ข้อความ Copy Safety ที่รัดกุมก่อนที่จะแสดงผลลงหน้าจอ

## 5. Future UI Placement Options (ทางเลือกในการแสดงผลบน UI ในอนาคต)

การแสดงผลในเฟสถัดไปควรจำกัดอยู่ในพื้นที่เฉพาะเพื่อวัตถุประสงค์ในการวินิจฉัยระบบเท่านั้น ทางเลือกที่เป็นไปได้มีดังนี้:
1. **Birth Profile Diagnostic Section**: เพิ่มการ์ดรายงานย่อยต่อท้ายข้อมูลโปรไฟล์การเกิด เพื่อแสดงว่าระบบตรวจพบปฏิทินไทยในสถานะทดลอง
2. **Debug-only Preview Panel**: แผงควบคุมสำหรับนักพัฒนาซอฟต์แวร์ที่เปิดให้เข้าถึงผ่าน Flag ควบคุมพิเศษ
3. **Data Tools Tab**: แท็บจำลองชุดข้อมูลใน Workspace สำหรับการสอบเทียบ
4. **Hidden Developer Diagnostics**: กล่องคอนโซลล็อกหรือรายงานซ่อนในชั้นตรวจสอบ
5. **ข้อแนะนำที่ไม่ควรทำ**: *ไม่แนะนำให้นำค่าไปวางใน Today's Guidance หรือหน้าสรุปผลของแอปหลักอย่างเด็ดขาดจนกว่าจะได้รับผลการสอบเทียบที่ได้รับการพิสูจน์แล้ว*

---

## 6. Recommended First UI Integration Strategy (กลยุทธ์การเชื่อมต่อ UI เฟสแรก)

* **Preview/Debug Only**: ออกแบบหน้าจอให้แสดงผลเฉพาะในโหมดจำลองสถานะการพัฒนา (Developer Preview)
* **Wording Label**: ระบุชื่อสัญลักษณ์และสถานะว่า “Diagnostic / Not Validated”
* **No Interpretation Influence**: ห้ามนำเอาลัพธ์ตำแหน่งดาวจำลองนี้เข้าไปมีส่วนร่วมในการประมวลผลข้อความแนะแนวทางชีวิตประจำวัน (Today / Weekly / Monthly strategy outputs)
* **Zero Persistence**: ห้ามทำการ Commit หรือ Save ค่าเหล่านี้ลงในระบบ LocalStorage หรือ Database

---

## 7. Copy Safety Requirements (ข้อกำหนดด้านความปลอดภัยทางภาษา)

ในการเชื่อมต่อฝั่ง UI ในอนาคต ข้อความบรรยายสถานะต้องใช้ประโยคที่ระมัดระวังเป็นพิเศษ:
* **ข้อความที่อนุญาตให้ใช้**:
  * `"อยู่ระหว่างรอการทดสอบสัญญาอ้างอิงข้อมูล (pending reference validation)"`
  * `"ระบบวินิจฉัยภายในเท่านั้น (diagnostic only)"`
  * `"ไม่มีผลต่อการวิเคราะห์แนวทางหรือเนื้อหากลยุทธ์ (not used for interpretation)"`
  * `"ยังไม่ได้รับการสอบเทียบกับแหล่งคัมภีร์โหราศาสตร์ไทยจริง"`
* **ข้อความต้องห้าม**:
  * ข้อความที่สื่อว่าระบบวิเคราะห์พิกัดดาวเคราะห์ได้อย่างแม่นยำแล้ว
  * ข้อความที่เป็นการทำนายโชคชะตาหรือแนวโน้มเคราะห์กรรม (เช่น ดี/ร้าย, มั่งคั่ง/อับโชค)
  * ข้อความที่ให้รายละเอียดองศาหรือราศีจริงเป็นตัวเลขเปรียบเทียบ

---

## 8. Technical Integration Boundary (การคัดแยกขอบเขตเชิงเทคนิค)

* **In-memory Call Only**: เรียกใช้ฟังก์ชัน `buildThaiPlanetPlacementRuntimeAdapterV01` เฉพาะในระหว่างที่คอมโพเนนต์ Mount อยู่ใน Memory โดยไม่มีการสร้างตัวแปรเก็บไว้ในระบบไฟล์หรือระบบบันทึกความคงอยู่
* **Separate Strategy Interpreter**: จัดกลุ่มโฟลเดอร์สำหรับจัดการการแสดงผลแยกต่างหาก และไม่นำผลลัพธ์จำลองนี้ไปผูกติดกับ Adapter กลยุทธ์ Natal/Transit Composer เป็นอันขาด
* **Feature Flag Control**: ควรปิดการทำงานของส่วน UI ใหม่นี้ไว้ภายใต้ฟิลด์ตรวจสอบ เช่น `process.env.NODE_ENV === 'development'`

---

## 9. Risk Review (การประเมินความเสี่ยงเชิงระบบ)

* **ความเสี่ยงของข้อมูลรั่วไหล**: ผู้ใช้อาจเข้าใจผิดว่าค่า `pending-reference-validation` คือตำแหน่งดาวเคราะห์จริงหากจัดวางตำแหน่งบน UI ไม่เหมาะสม (ลดความเสี่ยงโดยการระบุ Label คำเตือนให้เด่นชัด)
* **ผลกระทบต่อประสิทธิภาพรันไทม์**: การตรวจสอบความถูกต้องทุกครั้งที่คอมโพเนนต์เปลี่ยนสถานะอาจทำให้เกิดการคำนวณซ้ำซ้อนในแอปหลัก (ลดความเสี่ยงโดยเรียกใช้ข้อมูลผ่าน state ที่เสถียร)
* **ความเข้ากันได้ของระบบจัดเก็บข้อมูล**: ป้องกันไม่ให้อแดปเตอร์รุ่นถัดไปบันทึกข้อมูลจำลองนี้ทับข้อมูลประวัติโปรไฟล์เกิดของผู้ใช้ที่มีอยู่เดิมใน LocalStorage

---

  * ไม่เขียนข้อมูลทับ LocalStorage
  * ต้องรายงานคุณสมบัติ `safetySummary` และ `adapterStatus` ครบถ้วนหน้าจอ
