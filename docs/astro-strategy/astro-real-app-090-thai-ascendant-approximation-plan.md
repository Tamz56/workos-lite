# ASTRO-REAL-APP-DEV-090 — Thai Ascendant Approximation Plan

เอกสารฉบับนี้กำหนดแผนงานและแนวทางการประมวลผลประมาณค่าลัคนาไทย (Thai Ascendant Approximation Plan v0.1) เพื่อใช้เป็นโครงสร้างและวิธีการประเมินความสอดคล้องลัคนาชะตากำเนิดของผู้ใช้ร่วมกับระบบวางแผนยุทธศาสตร์ โดยมุ่งเน้นการควบคุมระดับความมั่นใจของการประเมินผลลัพธ์ด่านหน้าเป็นสำคัญ

---

## 1. Goal (เป้าหมายของแผนการประมาณลัคนา)

* **วางกรอบการคำนวณประมาณลัคนาไทย v0.1**: กำหนดตรรกะและโครงสร้างสูตรการประมาณพิกัดราศีลัคนาบนClient-side
* **เตรียมพร้อมสำหรับขั้นถัดไป**: เพื่อใช้เป็นรากฐานสำหรับระบบประมวลภพเรือนชะตา (House Mapping System) และโมดูลประมวลผลดวงชะตาเกิด (Natal Chart Runtime) ในอนาคต
* **ข้อจำกัดเชิงระบบ**: 
  - ยังไม่เริ่มเขียนรหัสคำนวณรันไทม์จริงในรอบนี้
  - ยังไม่มีการแก้ไขโครงสร้างหน่วยความจำ (LocalStorage schema) ใดๆ ของโปรเจกต์

## 2. Why Ascendant Matters (ความสำคัญของลัคนา)

ลัคนา (Ascendant) ถือเป็นจุดกำหนดพิกัดราศีที่ขึ้นทางขอบฟ้าทิศตะวันออก ณ วินาทีเกิดของผู้ใช้ มีความสำคัญสูงสุดต่อการวิเคราะห์เชิงระบบดังนี้:
* **จุดเริ่มต้นเรือนชะตา**: ลัคนาถูกกำหนดให้เป็นภพที่ 1 (ตนุ) จากทั้งหมด 12 ภพเรือนชะตา หากลัคนาขยับเปลี่ยนราศี การนับภพชะตาถัดไป (กัมมะ, ลาภะ, อริ ฯลฯ) จะเคลื่อนไปทั้งระบบ
* **ผลกระทบต่อแผนงานและยุทธศาสตร์**: การแปลความหมายของดาวจรปะทะดาวเกิด ตลอดจนการระบุสัญญะกลยุทธ์ (เช่น วันที่ควรลุยงานหนัก วันที่ควรจำศีลทบทวนบัญชี) จะอ้างอิงตำแหน่งภพชะตาจากลัคนาเป็นหลัก
* **ความคลาดเคลื่อนสะสม**: หากการประมาณลัคนาคลาดเคลื่อนเพียง 1 ราศี จะส่งผลให้ข้อเสนอแนะและโหมดกิจกรรมเปลี่ยนไปโดยสิ้นเชิง ระบบจึงต้องระมัดระวังเรื่องความแน่นอนของข้อมูลนำเข้า

---

## 3. Required Inputs (ข้อมูลนำเข้าเพื่อการคำนวณ)

การประเมินค่าประมาณลัคนาไทยต้องการตัวแปรนำเข้าดังนี้:
* `birthDate`: วันเกิดสุริยคติของผู้ใช้ (YYYY-MM-DD)
* `birthTime`: เวลาเกิด (HH:mm)
* `timezone`: เขตเวลากำเนิด (เช่น Asia/Bangkok)
* `birthPlaceName`: ชื่อจังหวัดที่เกิด (เพื่อนำมาใช้ประมาณความต่างของอาทิตย์อุทัยท้องถิ่น)
* `latitude` / `longitude`: พิกัดภูมิศาสตร์ (ไม่บังคับระบุใน v0.1)
* `calendarSystem`: ปฏิทินดาราศาสตร์อ้างอิง
* `birthTimeConfidence` / `birthplaceConfidence`: ระดับความยินยอมระบุความแน่ชัดของเวลาและสถานที่เกิด

## 4. Approximation Strategy v0.1 (กลยุทธ์ประมาณค่าเวอร์ชันเริ่มต้น)

เนื่องจากเวอร์ชันเริ่มต้นต้องการความคล่องตัวและไม่ขยายขนาดซอฟต์แวร์เกินความจำเป็น แผนการคำนวณจึงเลือกใช้แนวทางประมาณค่าเชิงสถิติ (Rule-Based Approximation):
1. **การหาองศาของดวงอาทิตย์สัมพัทธ์ (Solar Longitude Approximation)**: ประเมินหาราศีที่ดวงอาทิตย์ผ่าน ณ วันที่เกิดโดยประมาณ (ประมาณวันละ 1 องศา อ้างอิงตามวันเปลี่ยนราศีเฉลี่ยของโหราศาสตร์ไทยดั้งเดิม เช่น อาทิตย์ย้ายประมาณวันที่ 13-16 ของแต่ละเดือน)
2. **การแบ่งยามเวลาเกิดท้องถิ่น (Local Time-Block Approximation)**: 
   - ลัคนาจะสถิตร่วมราศีเดียวกับอาทิตย์เกิดเมื่อเวลาประมาณ 06:00 - 08:00 น. (ช่วงอาทิตย์ขึ้น)
   - ลัคนาจะเดินหน้าถัดไปทีละ 1 ราศีในทุกๆ 2 ชั่วโมงโดยประมาณ (เช่น 08:00 - 10:00 น. จะขยับไปราศีถัดไปในทางทวนเข็มนาฬิกา)
3. **การประยุกต์ใช้เวลาท้องถิ่นปัดเศษ (Simplified Ascendant Band)**: การประเมินจะแบ่งช่วงย่อยออกเป็น 12 คาบเวลา (Time Blocks) และประเมินจุดก้ำกึ่งใกล้เคียงโดยให้คะแนนระดับความมั่นใจลดหลั่นลงไป
4. **ข้อจำกัดที่ชี้แจง**: 
   - ยังไม่มีการใช้งาน Ephemeris ฐานข้อมูลพิกัดจริง
   - ไม่อ้างอิงความแม่นยำเทียบเท่าโปรแกรมคำนวณสมผุสละเอียดสำหรับผูกดวงชะตาโหราศาสตร์แบบดั้งเดิม

## 5. Accuracy & Confidence Policy (นโยบายความเที่ยงตรงและระดับความมั่นใจ)

เพื่อคุ้มครองความเข้าใจของผู้ใช้ ระบบจะประเมินคะแนนความมั่นใจ (`confidenceScore` ช่วง 0.0 - 1.0) ทุกครั้ง:
* **ข้อมูลนำเข้าสมบูรณ์ (birthTime exact)**: เวลาเกิดที่แน่นอนระดับนาทีและการระบุจังหวัดชัดเจน จะได้รับระดับความเชื่อมั่นเริ่มต้นสูง (0.8 - 0.9)
* **ไม่ระบุเวลาเกิดที่ละเอียด (birthTime unknown)**: หากผู้ใช้ไม่ทราบเวลาเกิดและเลือกใช้โหมดประมาณการ (เช่น ป้อนเวลา 12:00 น. เป็นค่าเริ่มต้น) ระบบจะลดคะแนนความมั่นใจลงเหลือไม่เกิน 0.3 และระบุแฟล็กเตือนความไม่สอดคล้องของลัคนา
* **ไม่ระบุสถานที่เกิด (birthplace missing)**: ระบบปัดค่าใช้ค่าพิกัดจังหวัดกึ่งกลางประเทศไทย และหักคะแนนความมั่นใจของลัคนาลง 20%
* **ความเสี่ยงรอยต่อวันเกิด (dayBoundaryRisk)**: หากผู้ใช้เกิดในเวลา 00:00 - 06:00 น. ตามปฏิทินสากล ซึ่งการเปลี่ยนผ่านวันทางจันทรคติโหราศาสตร์ไทยเดิมยังไม่เกิดขึ้น (มักเปลี่ยน ณ เวลาดวงอาทิตย์ขึ้น ประมาณ 06:00 น.) ระบบจะบันทึกสถานะแจ้งเตือนใน `dayBoundaryRisk`
* **การบันทึกตำแหน่งคาบเกี่ยว**: คะแนนความมั่นใจจะปรากฏในเอาต์พุตเสมอเพื่อความโปร่งใสทางระบบ

## 6. Output Contract (ข้อตกลงรูปแบบผลลัพธ์ข้อมูลลัคนา)

โครงสร้างผลลัพธ์ของแกนประมวลผลประมาณค่าลัคนา มีรูปแบบข้อมูลดังนี้:

```typescript
interface AscendantApproximationOutput {
  ascendantZodiacSign: string;        // ราศีลัคนาสถิต (ภาษาอังกฤษตัวเล็ก เช่น "gemini")
  degreeApprox?: number;              // องศาประเมินโดยประมาณ (ถ้าทำได้)
  calculationMethod: 'sunrise_offset_v1' | 'table_lookup' | 'fallback_noon'; // วิธีที่ใช้คำนวณ
  timeBlockUsed: string;               // ช่วงยามที่ประเมินใช้ (เช่น "08:00-10:00")
  timezoneOffset: number;             // ค่าความต่างเขตเวลาที่นำมาคำนวณ
  locationConfidence: 'high' | 'approximate' | 'low'; // ระดับความแน่นอนของสถานที่เกิด
  birthTimeConfidence: 'high' | 'medium' | 'low' | 'unknown'; // ระดับความแน่นอนของเวลาเกิด
  confidenceScore: number;            // คะแนนประเมินรวม (0.0 - 1.0)
  uncertaintyNotes: string;           // หมายเหตุอธิบายความก้ำกึ่งหรือความไม่แน่นอน
  dayBoundaryRisk: boolean;           // สถานะคาบเกี่ยวเวลาเปลี่ยนผ่านวัน
  isApproximation: boolean;           // แฟล็กยืนยันว่าข้อมูลนี้เกิดจากการประมาณค่า (ต้องเป็น true เสมอใน v0.1)
  generatedAt: string;                // วันเวลาประมวลผลสำเร็จ (ISO-8601)
}
```

## 7. Fallback Rules (เกณฑ์การแก้ไขในกรณีข้อมูลไม่สมบูรณ์)

เมื่อเกิดเหตุข้อมูลเข้าของระบบเกิดข้อบกพร่อง ระบบจะประยุกต์ใช้กฎสถิติดังนี้:
* **ไม่มีเวลาเกิด**: กำหนดให้เวลาเกิดเปลี่ยนเป็น 12:00 น. (กึ่งกลางวันท้องถิ่น), ตั้งค่าความมั่นใจลดเหลือ 0.1, สลับ calculationMethod เป็น `fallback_noon` และซ่อนเนื้อหายุทธศาสตร์เชิงลึกที่ขึ้นอยู่กับลัคนา
* **ไม่มีสถานที่เกิด**: กำหนดให้ดึงค่าพิกัดกรุงเทพมหานครและเขตเวลา Asia/Bangkok เป็นค่าตั้งต้น, ลดระดับความเชื่อมั่นสถานที่เกิดเป็น `low`
* **รอยต่อวันเกิด**: แสดงคำแนะนำระบุว่าความเที่ยงตรงของยุทธศาสตร์อาจคลาดเคลื่อนครึ่งวัน และแนะนำให้ผู้ใช้เปรียบเทียบผลลัพธ์ของวันเกิดก่อนหน้ากับวันถัดไปควบคู่กัน
* **เขตเวลาของเบราว์เซอร์ไม่สอดคล้อง**: กรณีตรวจสอบข้อมูลข้ามประเทศ หากเขตเวลาปัจจุบันของเครื่องผู้ใช้ต่างไปจากเขตเวลาท้องถิ่นชั่วขณะเกิด ระบบจะต้องแปลงความต่างเวลาชั่วขณะเกิดนั้นให้ถูกต้อง ไม่นำเวลาบราวเซอร์ปัจจุบันไปคำนวณโดยตรง

## 8. Validation & Reference Plan (แผนการเปรียบเทียบและสอบทานความถูกต้อง)

เพื่อตรวจสอบความสามารถในการประเมินผลของระบบประมาณการ เวอร์ชัน 0.1 จะใช้การเปรียบเทียบผลลัพธ์ตำแหน่งราศีลัคนากับข้อมูลอ้างอิงภายนอก:
* **การสอบเทียบกับแหล่งข้อมูลดั้งเดิม**: เปรียบเทียบผลการคำนวณกับระบบผูกดวงไทยที่ได้มาตรฐาน (เช่น MyHora หรือสูตรดาราศาสตร์ปฏิทินไทยเดิม)
* **เกณฑ์การยอมรับ**: ในกรณีระบุวันเกิดและเวลาเกิดปกติอย่างชัดเจน อัตราการก้ำกึ่งของตำแหน่งราศีลัคนาต้องมีความเบี่ยงเบนไม่เกิน 1 ราศี (ความแม่นยำราศีข้างเคียงไม่น้อยกว่า 90% จากกลุ่มตัวอย่างทดสอบ)
* **การจำกัดผลลัพธ์**: ยังไม่มีการตรวจสอบเทียบเคียงระดับองศาหรือลิปดาละเอียดยิบในเฟสนี้

## 9. Product Interpretation Policy (นโยบายการแปลผลและจุดยืน)

การประเมินลัคนาเวอร์ชัน 0.1 จะถูกใช้ภายใต้เงื่อนไขกลยุทธ์วางแผนอย่างเคร่งครัด:
* **จุดประสงค์หลัก**: ใช้เป็นจุดอ้างอิงในการเริ่มนับภพเรือนชะตา เพื่อสกัดรหัสสัญญะงาน (Strategic Signal IDs) ไปใช้จัดลำดับความสำคัญของตารางเวลาประจำวัน
* **ไม่มีเนื้อหาเชิงลบล่วงหน้า**: ข้อมูลตำแหน่งลัคนาจะไม่นำไปผูกโยงกับคำทำนายชะตาชีวิต ความสูญเสีย หรือการเกิดอุบัติเหตุความเสี่ยงที่แก้ไขไม่ได้

## 10. Copy Safety (ความปลอดภัยด้านคำศัพท์ทางจิตวิทยา)

ห้ามไม่ให้มีการแสดงคำต้องห้ามดังต่อไปนี้บนหน้าจอและรายงานเอกสาร:
* *เคราะห์, ซวย, กาลกิณี, อุบัติเหตุ, เงินเสียแน่, งานพัง, ความรักพัง, ห้ามทำเด็ดขาด, จะเกิดแน่นอน, ดวงบังคับ*

คำแนะนำที่จะแสดงผลให้แก่ผู้ใช้จะเลือกใช้ภาษาที่ประคองการตระหนักรู้เชิงยุทธศาสตร์:
* "ข้อมูลตำแหน่งนี้ใช้เพื่อประมาณการกรอบแนวทางกลยุทธ์เบื้องต้นเท่านั้น"
* "ระดับความมั่นใจของคำแนะนำส่วนบุคคลขึ้นอยู่กับความแน่ชัดของวันและเวลาเกิดที่ป้อนเข้าสู่ระบบ"
* "ใช้เป็นข้อมูลสนับสนุนเพื่อการสะท้อนคิดและการจัดสรรโหมดเวลาอย่างสร้างสรรค์"
* "ในกรณีที่ข้อมูลเข้าไม่ครบถ้วน ระบบจะปรับลดระดับความน่าเชื่อถือลงโดยอัตโนมัติ"

## 11. Non-Scope (ขอบเขตที่ไม่ดำเนินการเด็ดขาด)

* **ไม่เริ่มเขียนรหัสประมวลรันไทม์**: โค้ดของระบบจะไม่ถูกเพิ่มเติมหรือดัดแปลงแก้ไขในรอบการทำงานนี้
* **ไม่สร้างผลกระทบต่อ LocalStorage**: ป้องกันความเสถียรของประวัติและฐานข้อมูลบราวเซอร์
* **ไม่ผูก Ephemeris ขนาดใหญ่**: เพื่อรักษาขนาดของซอฟต์แวร์และไม่เพิ่มปริมาณ Code Bloat
* **ไม่ใช้คำพยากรณ์เชิงกำหนดเคราะห์กรรม**: คุมจุดยืนเฉพาะข้อมูลสนับสนุนแผนงานเชิงระบบ
