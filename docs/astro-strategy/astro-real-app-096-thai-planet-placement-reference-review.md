# ASTRO-REAL-APP-DEV-096 — Thai Planet Placement Reference Review

เอกสารทบทวนแหล่งอ้างอิง เกณฑ์การประมาณค่า และการสอบเทียบตำแหน่งดวงดาวโหราศาสตร์ไทย 10 ดวง (๐ ถึง ๙) สำหรับเตรียมความพร้อมก่อนพัฒนา Thai Planet Placement Runtime Adapter ในอนาคต โดยกำหนดกรอบการออกแบบสำหรับเวอร์ชัน 0.1 ที่เน้นการประมาณค่าชั่วคราว (Approximation) บนฝั่งไคลเอนต์ โดยยังไม่เชื่อมโยงกับฐานข้อมูลตำแหน่งดาราศาสตร์จริง (Ephemeris) หรือส่งผลกระทบต่อซอร์สโค้ดระบบและโครงสร้างฐานข้อมูลปัจจุบัน

---

## 1. Goal (วัตถุประสงค์และเป้าหมาย)

* **ทบทวนแหล่งอ้างอิงตำแหน่งดาวไทย 0-9**: ศึกษาและเปรียบเทียบแหล่งข้อมูลทางโหราศาสตร์ไทยสำหรับการวางตำแหน่งดวงดาว เพื่อกำหนดเกณฑ์ที่สมเหตุสมผลสำหรับโมดูลประมาณค่า
* **กำหนดแนวทางความน่าเชื่อถือ**: วางกรอบการตัดสินใจก่อนพัฒนา Runtime Adapter ในอนาคต เช่น การประเมินคะแนนความเชื่อมั่น (Confidence Score) และจุดที่ความแม่นยำมีความผันผวนสูง
* **ควบคุมขอบเขตระยะ v0.1**: 
  - ยังไม่มีการเขียนโค้ดรันไทม์คำนวณจริง (Runtime Calculation) หรือแก้ไขไฟล์ใน `src/`
  - ยังไม่ดัดแปลงโครงสร้างข้อมูลในระบบจัดเก็บข้อมูล (LocalStorage Schema)
  - ยังไม่มีการจัดทำสมผุสดวงดาวที่แท้จริงระดับองศาลิปดา (Exact Planetary Longitude)

## 2. Current State (สถานะของระบบในปัจจุบัน)

ปัจจุบันระบบมีโครงสร้างพื้นฐานที่สนับสนุนการคำนวณและแปลผลบางส่วน แต่ยังขาดแกนสมผุสดาวจริง ดังนี้:
* **โมดูลที่มีอยู่แล้ว**:
  - **Thai House Mapping Runtime Adapter v0.1**: อแดปเตอร์รันไทม์ที่วางผังเรือนชะตา 12 ภพแบบ Simplified จากจุดลัคนาอ้างอิง
  - **Thai Planet Placement Approximation Plan**: แผนกำหนดขอบเขตและข้อตกลงรูปแบบผลลัพธ์ของดาวเคราะห์ไทย v0.1
  - **Natal Strategy Signal Dictionary**: พจนานุกรมรหัสสัญญาณเชิงกลยุทธ์ที่ใช้แปลงค่าสัญญาณเป็นความหมายที่ปลอดภัย
* **สิ่งที่ยังไม่มีในระบบ**:
  - ลอจิกการคำนวณตำแหน่งจริงของดาวเคราะห์
  - ตารางอ้างอิงพิกัดดาวเคราะห์รันไทม์ (Reference Table Runtime)
  - ฐานข้อมูลปฏิทินดาวเคราะห์ (Ephemeris Database)
  - ค่าลองจิจูดและองศาดาวเคราะห์จริงเด็ดขาด (Exact Degree / Longitude)

## 3. Planet Scope for Review (ขอบเขตดวงดาวที่ทำการทบทวน)

การศึกษาในรอบนี้ครอบคลุมดวงดาวและปัจจัยชี้วัดหลัก 10 ตำแหน่ง (ดวงดาว ๐ ถึง ๙) ตามโหราศาสตร์ไทย ดังนี้:

* **0 ลัคนา / Ascendant reference**: จุดวิถีชีวิตส่วนบุคคลและศูนย์กลางเรือนชะตา
* **1 อาทิตย์ (๑)**: จุดโฟกัสความเป็นผู้นำและการตัดสินใจหลัก
* **2 จันทร์ (๒)**: จังหวะอารมณ์ความรู้สึกและการประคองคืนสภาพกายใจ
* **3 อังคาร (๓)**: ระดับพลังงานทางกายภาพและการดำเนินการสะสางภารกิจด่วน
* **4 พุธ (๔)**: โหมดการเจรจาสื่อสาร การคิดเชิงวิเคราะห์ และการทำข้อตกลง
* **5 พฤหัสบดี (๕)**: การแสวงหาความรู้ วินัยทางวิชาการ และวิสัยทัศน์ระยะยาว
* **6 ศุกร์ (๖)**: ทักษะมนุษยสัมพันธ์ สุนทรียภาพ และการประสานงานประนีประนอม
* **7 เสาร์ (๗)**: ความอดทน ความสม่ำเสมอ และวินัยโครงสร้างการทำงานระยะยาว
* **8 ราหู (๘)**: การจับตาความเสี่ยง การวิเคราะห์จุดบกพร่อง และระบบเทคโนโลยี
* **9 เกตุ (๙)**: การทำงานเบื้องหลัง การสะสางงานตกค้างเงียบๆ และการปล่อยวาง

*หมายเหตุ: การวิจัยในเฟสนี้ยังไม่ประเมินตำแหน่งลองจิจูดที่แท้จริงของดวงดาว แต่ทำหน้าที่กำหนดกรอบวิธีประเมินผลและการตรวจสอบความถูกต้องเปรียบเทียบในอนาคต*

## 4. Reference Sources to Consider (แหล่งอ้างอิงที่ใช้พิจารณา)

ในการสอบเทียบความถูกต้องของการประมาณตำแหน่งราศีของดาวเคราะห์ในขั้นตอนทดสอบรันไทม์ในอนาคต จะใช้แหล่งอ้างอิงดังต่อไปนี้:
* **MyHora**: เว็บบริการผูกดวงชะตาและปฏิทินโหราศาสตร์ไทยเชิงระบบที่เป็นที่ยอมรับ เพื่อใช้สอบทานความสอดคล้องของราศีสถิต
* **หนังสือโหราศาสตร์ไทยและคัมภีร์ดวงดาว**: ตำราคำนวณของ อ.สุริยาตร์ หรือปฏิทินโหราศาสตร์แนวประยุกต์ เพื่อศึกษาความเร็วรอบโคจรและค่าเฉลี่ยทางสถิติ
* **ตารางสมผุสดาวไทยประจำปี**: ตารางแสดงตำแหน่งดาวเคราะห์รายวัน/รายเดือน เพื่อใช้สร้างตารางค่าอ้างอิงชั่วขณะ
* **ระบบปฏิทินดาวเทียบเคียง**: เครื่องมือคำนวณทางดาราศาสตร์ภายนอกสำหรับเปรียบเทียบความเหลื่อมล้ำระหว่างระบบสุริยยาตร์ (Suriyayart) และระบบนิรายนะดาราศาสตร์จริง (Sideral / Lahiri)
* **กรณีทดสอบควบคุมหลักของผู้ใช้ (Personal Reference Candidate)**: ใช้ข้อมูลเฉพาะเจาะจงที่ระบุในหัวข้อที่ 7 เป็นตัวแปรควบคุมในการทดสอบความสมเหตุสมผลเชิงลัพธ์

*ข้อตกลงความปลอดภัย: การรวบรวมข้อมูลครั้งนี้จะไม่ทำการคัดลอก คัดลอกแบบ scrape หรือดึงเนื้อหาคำอธิบายขนาดยาวจากแหล่งอ้างอิงภายนอกเข้ามาบันทึกในเอกสาร เพื่อป้องกันปัญหา Code/Doc Bloat*

## 5. What to Validate (หัวข้อเกณฑ์การสอบเทียบ)

การประเมินและตัดสินความสมเหตุสมผลของโมดูลประมาณค่าตำแหน่งดาวเคราะห์ จำเป็นต้องตรวจสอบหัวข้อต่อไปนี้:
* **Zodiac Sign Mapping (การระบุพิกัดราศี)**: ตรวจสอบความถูกต้องว่าดาวแต่ละดวงสามารถจับคู่ราศี (Zodiac Sign) ได้ตรงตามปฏิทินที่ใช้เป็นแกนเปรียบเทียบหรือไม่
* **ระบบปฏิทินที่ใช้อ้างอิง**: ระบุความแตกต่างของระบบโหราศาสตร์ไทยที่อิงจักราศีแบบนิรายนะ (Sideral Zodiac) ซึ่งมีการคำนวณค่าอายันศะ (Ayanamsa) เมื่อเทียบกับระบบสายนะ (Tropical Zodiac) ของซีกโลกตะวันตก
* **ค่าองศาและลิปดาโดยประมาณ (Degree / Longitude Validity)**: ในระดับ v0.1 จะไม่มีการอ้างอิงองศาจริง แต่ต้องระบุว่าระบบยอมรับความเบี่ยงเบนได้กี่องศา (เช่น ยอมรับการเบี่ยงเบนในระดับราศีข้างเคียงได้เฉพาะกรณีรอยต่อวันเปลี่ยนราศี)
* **การคำนวณราหูและเกตุ (Node Placements)**: 
  - ราหู (๘) โคจรย้อนจักรราศี (Retrograde) เป็นปกติ และต้องระบุวิธีคำนวณแบบ Mean Node หรือ True Node
  - เกตุไทย (๙) โคจรเร็วรอบจักรราศีด้วยรอบเวลาพิเศษ และมีความแตกต่างจากเกตุสากล (Ketu / South Node) ซึ่งต้องบันทึกสัญลักษณ์ให้เป็นไปตามตำราโหราศาสตร์สุริยาตร์ของไทย
* **ความปลอดภัยของช่วงวันรอยต่อ (Day Boundary & Sign Transition Risk)**: วิเคราะห์ว่าหากวันเกิดของผู้ใช้อยู่ในช่วงคาบเกี่ยวย้ายราศีของดวงดาวเฉพาะ จะต้องลดคะแนนความมั่นใจ (Confidence Score) ลงอย่างไร และต้องแสดงข้อความเตือนความไม่แน่นอนอย่างไร

## 7. Personal Reference Candidate (ตัวแปรกิจกรรมสอบเทียบ)

เพื่อใช้ประเมินความสอดคล้องในอนาคต จะกำหนดชุดข้อมูลจริงของผู้ใช้เป็นตัวแปรควบคุมหลัก (Validation Candidate):
* **วันเกิด**: 5 มิถุนายน พ.ศ. 2523 (ค.ศ. 1980)
* **เวลาเกิด**: 06:45 น.
* **สถานที่เกิด**: โรงพยาบาลศิริราช กรุงเทพมหานคร ประเทศไทย
* **เขตเวลา (Timezone)**: Thailand Standard Time (UTC+07:00)

*ข้อตกลงการใช้ข้อมูล: ข้อมูลนี้เป็นเพียงค่าสำหรับรันตัวแปรสอบทานเปรียบเทียบ (Validation Case) เท่านั้น ระบบจะยังไม่มีการสรุปหรือยืนยันตำแหน่งดวงดาวจริงของข้อมูลนี้ลงในเอกสารจนกว่าจะผ่านการวิจัยและพัฒนาเครื่องมือจำลองในขั้นตอนถัดไป*

## 8. Accuracy Risk Notes (บันทึกระดับความเสี่ยงของความแม่นยำ)

การประมาณค่าตำแหน่งดาวบนระบบไคลเอนต์โดยไม่มี Ephemeris เต็มระบบมีความเสี่ยงที่จะคลาดเคลื่อนจากความจริงดังนี้:
* **ความคลาดเคลื่อนจากความเร็วโคจรเฉลี่ย (Mean Motion Deviation)**: ดาวเคราะห์วงใน เช่น พุธ (๔) และศุกร์ (๖) โคจรเข้าใกล้ดวงอาทิตย์และมีปรากฏการณ์โคจรวิปริต (Retrograde/Stationary/Direct) บ่อยครั้ง การใช้ค่าเฉลี่ยอย่างเดียวอาจทำให้ราศีคลาดเคลื่อนไป 1-2 ราศีได้ในช่วงวิปริต
* **การเคลื่อนที่เร็วของดวงจันทร์ (Moon Fast-Motion Risk)**: จันทร์ (๒) เปลี่ยนตำแหน่งราศีทุกๆ 2.5 วันโดยประมาณ (ประมาณ 12 องศาต่อวัน) เป็นจุดที่มีความเสี่ยงคลาดเคลื่อนสูงสุดหากวันเวลาเกิดไม่แน่นอนหรืออยู่ในช่วงคาบเกี่ยวเปลี่ยนราศีรายชั่วโมง
* **ความซับซ้อนของราหูและเกตุ (Node Mismatch Risk)**: ราหู (๘) มีการคำนวณสองแบบ (Mean/True Node) ผลลัพธ์อาจต่างกันได้เล็กน้อย ขณะที่เกตุไทย (๙) มีอัตราการโคจรเฉพาะตัวตามคัมภีร์สุริยาตร์ หากสูตรคำนวณฐานเวลาคลาดเคลื่อนเล็กน้อยจะทำให้ตำแหน่งราศีเบี่ยงเบนได้ง่าย
* **ความเสี่ยงคาบเกี่ยววันเปลี่ยนราศี (Day Boundary & Transition Risk)**: เมื่อดาวโคจรเข้าใกล้พิกัดขอบเขตราศี (0 หรือ 29 องศา) ความมั่นใจของระบบต้องปรับลดลงเป็นระดับต่ำสุด เพื่อป้องกันข้อผิดพลาดในการนำผลไปแปลงค่าเป็นจุดประสงค์เชิงพฤติกรรม
* **ความเสี่ยงของเขตเวลาเกิด (Birth Timezone Risk)**: การแปลงเวลาจะต้องยึดโยงกับเขตเวลาชั่วเกิด (Birth Timezone) เสมอ ไม่ใช่การใช้เขตเวลาปัจจุบันของเบราว์เซอร์ของผู้ใช้ (Browser Timezone) ซึ่งอาจทำให้ระบบประเมินค่าเวลาสากลผิดเพี้ยนไปหลายชั่วโมง

## 9. v0.1 Decision Boundary (ข้อจำกัดการตัดสินใจในเวอร์ชัน 0.1)

ระบบในรุ่น v0.1 จะใช้มาตรการจำกัดกรอบผลลัพธ์ดังนี้ เพื่อประคองความเสถียรและความเข้าใจที่ถูกต้องของผู้ใช้:
* **ไม่แสดงองศาและลิปดา**: ปิดการเปิดเผยองศาตัวเลข (Degree) บนระบบแสดงผล เพื่อหลีกเลี่ยงไม่ให้ผู้ใช้เข้าใจผิดว่าเป็นโปรแกรมคำนวณสมผุสจริง
* **แสดงตัวบ่งชี้การประมาณการ**: ข้อมูลดาวทุกดวงจะระบุแอตทริบิวต์ `isApproximation = true` เสมอในโครงสร้างข้อมูลเอาต์พุต
* **ส่งมอบคะแนนความเชื่อมั่นและบันทึกระบุความไม่แน่นอน**:
  - แสดงผลคะแนนความมั่นใจ (`confidenceScore`) บนส่วนจำลองข้อมูลเพื่อความโปร่งใส
  - พิมพ์หมายเหตุแจ้งเตือนความคลาดเคลื่อน (`uncertaintyNotes`) เสมอหากพิกัดตกอยู่ในขอบเขตรอยต่อราศี
* **ซ่อนข้อมูลเมื่อความมั่นใจต่ำมาก**: หากไม่ระบุเวลาเกิด หรือมีคะแนนความมั่นใจรวมของตำแหน่งต่ำกว่าเกณฑ์ความน่าเชื่อถือ ระบบจะซ่อนข้อความการตีความเชิงลึก และแสดงผลเฉพาะหมวดกลยุทธ์กว้างที่ยอมรับได้
* **ไม่การันตีการทำงานเทียบเท่าปฏิทินดาราศาสตร์จริง**: แจ้งให้ผู้ใช้ทราบอย่างชัดเจนบนเอกสารและส่วนอธิบายว่าเป็นการทดลองเชิงทฤษฎีกลยุทธ์การทำงาน ไม่ใช่โปรแกรมผูกดวงชะตาเพื่อการทำนายทายทัก

## 10. Recommended Technical Direction (แนวทางสถาปัตยกรรมที่เสนอ)

จากการวิเคราะห์ระบบประมวลผลดวงดาวของไทยในระดับโครงสร้างที่ไม่ Code Bloat ได้เปรียบเทียบแนวทางเทคนิค 4 รูปแบบหลัก:

### ทางเลือก A: Static Reference Table (ตารางอ้างอิงค่าคงที่)
* **รูปแบบ**: จัดทำตารางข้อมูลคงที่ (Lookup Table) ขนาดกะทัดรัด บันทึกช่วงเวลาเปลี่ยนราศีของดาวเคราะห์หลักแต่ละดวงในช่วงปีเกิดที่รองรับ (เช่น ปี พ.ศ. 2510 - 2570)
* **ข้อดี**: ความเร็วสูงมาก (O(1)), ไม่มีภาระการคำนวณทางคณิตศาสตร์ซับซ้อน, ความแม่นยำสูงมากตามปฏิทิน MyHora หรือสุริยาตร์จริง, ทำงานแบบออฟไลน์ได้สมบูรณ์ (Offline-friendly)
* **ข้อเสีย**: ขนาดไฟล์ในบันเดิล (Bundle Size) เพิ่มขึ้นเล็กน้อยตามจำนวนปีที่ขยายครอบคลุม แต่สามารถบีบอัดให้อยู่ในระดับไม่กี่สิบกิโลไบต์ได้

### ทางเลือก B: Mean Motion Approximation (คำนวณด้วยความเร็วเฉลี่ยเชิงกล)
* **รูปแบบ**: ใช้สูตรคณิตศาสตร์คำนวณหาตำแหน่งดาวจากยุคอ้างอิง (Epoch) โดยอาศัยความเร็วโคจรเฉลี่ยของดาวเคราะห์แต่ละดวง
* **ข้อดี**: ไม่ต้องใช้พื้นที่ตารางจัดเก็บข้อมูล (Bundle Size ต่ำมาก)
* **ข้อเสีย**: ความแม่นยำต่ำมากสำหรับดาวเคราะห์วงในที่มีการโคจรวิปริตบ่อยครั้ง (พุธ, ศุกร์) รวมถึงราหูและเกตุ ส่งผลให้การคาดคะเนราศีผิดพลาดสูงและต้องประเมิน Confidence ต่ำเกือบตลอดเวลา

### ทางเลือก C: External Ephemeris Service (เรียกใช้ API ภายนอก)
* **รูปแบบ**: เชื่อมต่อเพื่อขอรับค่าตำแหน่งดาวที่ถูกต้องจาก API ระบบคำนวณดาราศาสตร์ภายนอกเมื่อโหลดหน้าเว็บ
* **ข้อดี**: ความแม่นยำร้อยละร้อยเทียบเท่าระดับดาราศาสตร์สากล
* **ข้อเสีย**: ขัดต่อนโยบายการเก็บข้อมูลแบบท้องถิ่น (Local-first & Privacy Policy), ไม่สามารถใช้งานแบบออฟไลน์ได้, ส่งผลต่อระยะเวลาดาวน์โหลดหน้าเว็บ (Network latency) และมีความเสี่ยงต่อระบบล่มหากเซิร์ฟเวอร์ปลายทางมีปัญหา

### ทางเลือก D: Manual Validation Cases (เกณฑ์การตรวจระดับกึ่งอัตโนมัติ)
* **รูปแบบ**: รวบรวมกรณียืนยันคงที่ (Manual Test Cases) จำนวนหนึ่งในระบบทดสอบ เพื่อใช้สอบทานความถูกต้องของโค้ดประมาณผลก่อนปล่อยเวอร์ชัน

### สรุปคำแนะนำเชิงสถาปัตยกรรมสำหรับ v0.1:
ระบบควรเลือกใช้ **ทางเลือก A (Static Reference Table) ร่วมกับทางเลือก D (Manual Validation Cases)** เป็นหลัก เนื่องจากให้ผลลัพธ์การทำงานที่คงเส้นคงวาและแม่นยำที่สุดตามระบบโหราศาสตร์ไทย ไม่ Code Bloat และประคองความปลอดภัยด้านข้อมูลส่วนบุคคล (Privacy) ภายใต้ระบบที่เป็น Offline-friendly

## 11. Product Interpretation Policy (นโยบายขอบเขตการแปลผลผลิตภัณฑ์)

การแปลงผลลัพธ์ตำแหน่งดาวในเรือนชะตาไปสู่หน้าแสดงผลจะจำกัดเฉพาะมิติเชิงพฤติกรรมการจัดการภารกิจการทำงานเท่านั้น:
* **สิ่งที่ระบบนำเสนอข้อมูล**:
  - **รูปแบบและสไตล์การทำงาน (Work Style)**: วิธีประยุกต์ทักษะส่วนตัวในการทำงานร่วมกับผู้อื่น
  - **โหมดการตัดสินใจวิเคราะห์ (Decision Style)**: สไตล์การรับมือปัญหาเฉพาะหน้า
  - **จังหวะการเจรจา (Communication Pattern)**: ความพร้อมในการเชื่อมต่อทางสังคม
  - **จังหวะการฟื้นคืนพลังสมอง (Recovery Pattern)**: วิธีการชะลอภาระงานเมื่อเกิดสภาพเหนื่อยล้า
  - **การทำงานร่วมกันเป็นทีม (Collaboration Pattern)**: การจัดวางสัดส่วนความรับผิดชอบ
  - **การเรียนรู้และการพัฒนา (Learning Pattern)**: โหมดการปรับปรุงทักษะเชิงลึก
  - **การควบคุมวินัยและโครงสร้างงาน (Structure / Discipline Pattern)**: การจัดการตารางงานระยะยาว
* **สิ่งที่ระบบห้ามแปลผลเด็ดขาด**:
  - ไม่ทำนายเหตุการณ์ทางกายภาพอันเกิดแก่ชีวิตและร่างกายของผู้ใช้
  - ไม่ตัดสินความเป็นความตาย ทิศทางสุขภาพ โชคลาภทางการเงิน หรือความสัมพันธ์เชิงชู้สาว
  - ไม่ระบุคำสั่งเด็ดขาดให้ทำหรือห้ามทำสิ่งใดๆ ในเชิงพฤติกรรมชีวิตส่วนบุคคล
  - ไม่ใช้ประโยคที่กระตุ้นความหวาดกลัวหรือสร้างความกังวลเชิงลบแก่ผู้ใช้

## 12. Copy Safety Guardrails (เกณฑ์การควบคุมความปลอดภัยของถ้อยคำ)

เพื่อความมั่นคงและสุขุมภาพของจิตใจผู้ใช้ เอกสารการประเมินและผลลัพธ์การแสดงผลจะต้องไม่ใช้กลุ่มคำตัดสินหรือคำทำนายที่รุนแรงตามรายการ **Copy Safety Blocklist**:
* หลีกเลี่ยงข้อความที่แสดงความล้มเหลวเด็ดขาดหรือคำประเมินแง่ลบ (เช่น deterministic negative wording, fear-based prediction terms หรือ hard-fate language)
* ปรับเปลี่ยนโทนภาษาในกรณีดวงดาวสถิตในภพเสีย (อริ, มรณะ, วินาศ) ให้เป็นภาษาเชิงกลยุทธ์และการจัดการความเสี่ยง เช่น:
  - จากข้อความเชิงลบเปลี่ยนเป็น: *"แนะนำให้เพิ่มความรัดกุมในการตรวจสอบเอกสารและวางแผนจัดเวลาพักผ่อนเชิงลึกเพื่อรักษาความสดใหม่ของสมอง"*
  - จากข้อความฟันธงเปลี่ยนเป็น: *"ใช้เป็นข้อมูลสนับสนุนเพื่อประกอบการสะท้อนคิดประเมินจุดเด่นและข้อพึงระวังในแต่ละวันเกิด"*

## 13. Data Safety / Storage (ความมั่นคงและปลอดภัยของข้อมูล)

* **ไม่แก้ไข LocalStorage Schema**: ข้อมูลดวงชะตาและผลลัพธ์ประมาณการดาวจะไม่มีการบันทึกแบบถาวรลงในเบราว์เซอร์ของระบบปัจจุบัน
* **ความเข้ากันได้ย้อนหลัง (Backward Compatibility)**: ข้อมูลระบบนำเข้า/ส่งออก (Import/Export/Restore) ของผู้ใช้ที่เคยเซฟไว้ในเวอร์ชันก่อนหน้าจะต้องใช้งานได้อย่างปกติ ปราศจากการรบกวนของตัวแปรเสริมของดาวเคราะห์
* **การปกป้องข้อมูลอ่อนไหวระดับสูง (Data Privacy Warning)**: เนื่องจากข้อมูลวัน เวลา และสถานที่เกิดเป็นข้อมูลส่วนบุคคลที่มีความอ่อนไหวสูง หากมีการพัฒนาระบบ Import/Export ในอนาคต จะต้องระบุคำเตือนเรื่องความเป็นส่วนตัว (Privacy warning) เสมอเพื่อให้ผู้ใช้รับทราบและระมัดระวังการส่งต่อไฟล์ดวงชะตา

## 14. Non-scope (ขอบเขตนอกเหนือภารกิจ)

ขอบเขตการทำงานของใบงาน DEV-096 นี้จะไม่ครอบคลุมสิ่งต่อไปนี้:
* ไม่เขียนซอร์สโค้ดการคำนวณจริงลงในโฟลเดอร์รันไทม์ `src/` ทั้งสิ้น
* ไม่ทำซ้ำ สแกน หรือดัดแปลงแก้ไขไฟล์หน้าอินเตอร์เฟซผู้ใช้ (UI Preview) ปัจจุบัน
* ไม่เพิ่มไลบรารีหรือโมดูลการประมวลผลดวงดาวขนาดใหญ่ที่จะขัดต่อนโยบายความสะอาดเรียบร้อย (Anti-Bloat Discipline)
* ไม่พยายามต่อสัญญา API หรือเชื่อมต่อบริการคำนวณดวงดาวออนไลน์
* ไม่ระบุองศาแบบละเอียดยิบลงในเอกสารวิจัย
* ไม่ใช้และไม่เขียนข้อความพยากรณ์โชคชะตาชีวิตแง่ลบหรือคำฟันธงเด็ดขาดลงในรายงานคุณภาพและพจนานุกรมคำศัพท์
