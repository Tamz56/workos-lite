# ASTRO-REAL-APP-DEV-047 — Import / Restore QA & Regression Verification

เอกสารสรุปผลการประเมินคุณภาพและการตรวจสอบความถดถอยของระบบนำเข้าและกู้คืนข้อมูล (Import / Restore QA & Regression Verification) สำหรับ Astro Real App MVP-v3

---

## 1. Goal (เป้าหมาย)

ทำการทดสอบเชิงประกันคุณภาพ (QA) และการตรวจสอบความเข้ากันได้แบบครอบคลุม (Regression Verification) สำหรับระบบนำเข้าและกู้คืนข้อมูลสำรอง (Import / Restore System) ที่ถูกพัฒนาขึ้นในรหัสงาน DEV-046 เพื่อรับประกันความมั่นคงปลอดภัยสูงสุดในสภาพแวดล้อมพรีวิว และตรวจสอบความไม่กระทบกระเทือน (No Regression) ต่อโมดูล Today, Weekly, Monthly Engine และส่วนงานอื่น ๆ ในเบราว์เซอร์

---

## 2. Scope & Non-Scope (ขอบเขตการตรวจสอบ)

### ขอบเขตการประเมิน (Scope)
1. ตรวจสอบความถูกต้องของการนำเข้าและกู้คืนข้อมูลแยกตามรายโหมด (Merge-Safe และ Replace)
2. ตรวจสอบกระบวนการจำลองข้อมูลสำรองแห้ง (Dry Run Validation & Error Handling)
3. ตรวจสอบความเข้มงวดของการเข้าถึงคีย์เบราว์เซอร์และสิทธิ์ความมั่นคงปลอดภัย
4. ตรวจสอบพฤติกรรมความเสถียรของฟังก์ชันคำนวณและประวัติสะสมสะท้อนคิดหลังการกู้คืนข้อมูล
5. รันการทดสอบ Linting และ Next.js Production Build เพื่อยืนยันความพร้อม

### นอกเหนือขอบเขต (Non-Scope)
- ห้ามพัฒนาฟีเจอร์หรือโครงสร้างปุ่มควบคุมเพิ่มเติม (Documentation-first)
- ห้ามดัดแปลงสกีมาข้อมูลปัจจุบัน ยกเว้นการทำความสะอาดข้อผิดพลาดระดับร้ายแรง (Critical Bug)

---

## 3. QA Environment (สภาพแวดล้อมที่ใช้ในการประเมิน)

- **เส้นทางการทดสอบ**:
  - เส้นทางจริง (Production Route): `/workspaces/astro-strategy`
  - เส้นทางจำลอง (Preview Route): `/workspaces/astro-strategy/real-app-preview`
- **เบราว์เซอร์เป้าหมาย**: เครื่องมือจำลอง LocalStorage และบิวท์อินของ Client-Side JS
- **ข้อมูลสำหรับการทดสอบ**: ไฟล์สำรองข้อมูลดิบ JSON ที่ได้จากการทำงานจริงของเฟส DEV-044

## 4. Import Dry-Run & Validation Verification (ผลการทดสอบขั้นตอน Dry Run)

- **ความปลอดภัยในการเลือกไฟล์ (Selecting File Security)**:
  - ได้รับการพิสูจน์แล้วว่าการเลือกอัปโหลดไฟล์ JSON จะรันเฉพาะขั้นตอนการอ่านและแยกส่วนสกีมาผ่าน `FileReader` เท่านั้น โดยไม่มีการส่งผลกระทบใด ๆ หรือทำการเขียนข้อมูลลงใน LocalStorage ของเบราว์เซอร์เลยแม้แต่ไบต์เดียว
- **การทดสอบความถูกต้องของไฟล์สำรอง (Valid Backup JSON)**:
  - ไฟล์ JSON ที่มีรูปแบบและ Envelope ครบถ้วนตามมาตรฐาน ผ่านการตรวจสอบ Dry Run ราบรื่น พร้อมสรุปชื่อโปรไฟล์ ขนาดข้อมูล และรหัสวันเกิดชัดเจน
- **การปฏิเสธไฟล์ชำรุด (Malformed / Unknown Data Protection)**:
  - เมื่ออัปโหลดไฟล์ข้อความทั่วไป หรือไฟล์ JSON ที่ไม่มีโครงสร้าง `$schema` และ `metadata` ที่ระบุ ระบบทำการปิดกั้นการกู้คืน (Validation Failed) ขึ้นแถบ Error เน้นสีแดงเตือน และปิดใช้งานปุ่มสำหรับรันกระบวนการกู้คืนโดยเด็ดขาด

---

## 5. Restore Modes & Conflict Resolution Verification (ผลการทดสอบโหมดกู้คืนข้อมูล)

### ก. Merge-Safe Mode (โหมดรวมประวัติปลอดภัย)
- **พฤติกรรมที่พบ**:
  - ประวัติสะสมสะท้อนคิดรายสัปดาห์ในไฟล์ JSON จะถูกสแกนนำเข้าเฉพาะรายการที่ไม่มีอยู่จริงในเครื่องท้องถิ่นปลายทาง โดยใช้ `id` และวันที่จดบันทึกเป็นตัวเปรียบเทียบ
  - ข้อมูลส่วนตัว (Birth Profile) และโน้ตแผนกลยุทธ์ (Planning Notes) ในเครื่องปัจจุบัน จะถูกคงคุณลักษณะเดิมไว้ ไม่ถูกเขียนทับหรือลบทิ้งโดยเด็ดขาด
- **ผลลัพธ์**: ผ่านเกณฑ์ความปลอดภัย ประวัติเก่าไม่สูญหายและประวัติใหม่ถูกรวมเข้าด้วยกันอย่างเหมาะสม

### ข. Replace Mode (โหมดเขียนทับทั้งหมด)
- **พฤติกรรมที่พบ**:
  - ข้อมูล Astro Real App ทั้ง 5 คีย์ถูกทดแทนด้วยค่าข้อมูลจากไฟล์สำรอง 100%
  - สวิตช์ Checkbox ยืนยันความเสี่ยงทำงานสอดคล้องกับคุณลักษณะปิด/เปิดปุ่มยืนยัน
  - มี Dialog ป๊อปอัปขึ้นมายืนยันเจตจำนงจากผู้ใช้อีก 1 รอบก่อนเขียนจริง
- **ผลลัพธ์**: ผ่านเกณฑ์ความเสถียร ระบบสามารถสลับดวงและดึงค่าข้อมูลมาใช้งานใหม่ได้ทันที

## 6. Rollback Snapshot Behavior Audit (การวิเคราะห์ความมั่นคงระบบ Rollback)

- **กระบวนการ Transaction**:
  - มีการสร้างฟังก์ชัน `createRestoreRollbackSnapshot` เพื่อรวบรวมสถานะจัดเก็บปัจจุบันของคีย์ทั้งหมดเข้าสู่หน่วยความจำสำรองชั่วคราว
  - เมื่อทดลองทำให้อุปกรณ์เบราว์เซอร์มีสถานะจัดเขียนขัดข้อง อะแดปเตอร์ `restoreAstroDataFromImport` จะยกเลิกการแก้ไขและสลับดึงข้อมูล Snaphot เดิมกลับมาเซฟคืนให้ทันที ทำให้เบราว์เซอร์ไม่เกิดสภาวะข้อมูลเสียหายกึ่งกลางทาง

## 7. Allowed & Forbidden Keys Review (ผลการตรวจสอบขอบเขตคีย์เบราว์เซอร์)

- **Allowed Keys (คีย์ที่เขียนได้)**:
  - `astro-real-app:birth-profile:v1`
  - `astro-real-app:reflection-history:v1`
  - `astro-real-app:planning-notes:v1`
  - `astro-real-app:reflection-draft:v1`
  - `astro-real-app:onboarding:v1`
- **Forbidden Keys (คีย์ที่ห้ามเขียนทับ)**:
  - ได้รับการยืนยันว่าไม่มีการไปยุ่งเกี่ยวกับคีย์โปรโตไทป์เก่า (`astro-strategy:*`, `astro.strategy.*`) หรือคีย์ของส่วนอื่นใน ArborDesk
  - คีย์ระบบอื่นนอกเหนือจากคีย์พรีวิวจัดเก็บข้อมูล Astro ถูกป้องกันและปฏิเสธทั้งหมด

## 8. Post-Restore Regression Review (การประเมินผลกระทบย้อนหลังต่อแอปพลิเคชัน)

หลังจากทำรายการกู้คืนข้อมูลสำเร็จ ได้ทำการตรวจทานฟังก์ชันย้อนหลังพบผลลัพธ์ดังนี้:
1. **Today Panel**: สามารถอ่านทิศทางกลยุทธ์รายวันและคำนวณทิศทางการดำเนินงานตามโปรไฟล์ดวงเกิดที่กู้คืนมาใหม่ได้ทันทีและมีข้อมูลครบถ้วน
2. **Weekly & Monthly Panel**: ประมวลสถิติสรุปตามรายรอบสัปดาห์และรอบเดือนได้สมบูรณ์ ไม่มีอาการหน้าจอค้างหรือ Error
3. **Birth Profile Form**: แสดงข้อมูลวัน เวลา สถานที่เกิด และชื่อ displayName ที่กู้คืนมาบนกล่องฟอร์มอย่างถูกต้องและสามารถแก้ไขเพื่อจัดเซฟซ้ำได้ปกติ
4. **Onboarding Banner dismiss state**: เปลี่ยนสถานะการปิดหรือแสดงแผงคำแนะนำตามที่กู้คืนมาจากระบบสำรองข้อมูล
5. **Autosave Reflection Draft**: ดราฟต์บันทึกที่พิมพ์ค้างอยู่ได้รับการฟื้นคืนสภาพ และทำงานจดจำข้อความที่พิมพ์ค้างได้ปกติ

---
