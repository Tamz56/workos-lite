# Thai Planet Debug Panel Milestone Summary & Next Scope Decision (ASTRO-REAL-APP-DEV-116)

เอกสารวิเคราะห์และสรุปผลสัมฤทธิ์ของไมล์สโตนการเชื่อมต่อระบบวินิจฉัยตำแหน่งดาวเคราะห์ไทยจำลอง (Milestone: Thai Planet Debug Panel Preview Wiring) พร้อมประเมินทิศทางขอบข่ายการพัฒนาในลำดับถัดไป (Next Scope Decision)

## 1. Purpose (วัตถุประสงค์)

วัตถุประสงค์ของเอกสารนี้คือการประมวลผลการทำงานและการประเมินความคืบหน้าของโครงการพัฒนาระบบย่อยปฏิทินดวงดาวไทย (Thai Astrology Engine v0.1 Diagnostics) ตั้งแต่ระยะเริ่มต้นจนถึงระยะผสานหน้าจอจำลองสำเร็จ เพื่อให้เป็นบันทึกทางเทคนิคที่มั่นคงและระบุความปลอดภัยในการควบคุมระบบ ตลอดจนเสนอทางเลือกทางวิศวกรรมในการดำเนินการต่ออย่างเป็นรูปธรรม

---

## 2. Milestone Coverage (สรุปประวัติภาพรวมผลงานตั้งแต่ DEV-096 ถึง DEV-115)

การพัฒนาในไมล์สโตนนี้แบ่งออกเป็นระยะหลักดังนี้:

* **ระยะกำหนดสัญญาและวางแผนฐานข้อมูล (DEV-096 ถึง DEV-102)**: ทำการศึกษากรณีศึกษาอ้างอิง (Reference Review), สร้าง Matrix กรณีศึกษามาตรฐาน (Reference Case Matrix), ออกแบบแผนสำหรับรันไทม์อะแดปเตอร์ (Runtime Adapter Plan), และจัดสร้าง Interface Stub และโครงทดสอบความปลอดภัย (Safety Harness)
* **ระยะขับเคลื่อนข้อมูลและตรวจสอบสัญญา (DEV-103 ถึง DEV-106)**: จัดทำกลไกการประสานข้อมูล (Runtime Orchestrator), ทำการรีวิวสัญญารุ่นทดสอบ (Contract QA Review), วิเคราะห์ฟิกซ์เจอร์จัดแสดงของระบบ (Diagnostic Fixture Review), และร่างแผนปฏิบัติงานเขียนสคริปต์วินิจฉัยข้อมูลด้วยมือ (Manual Diagnostic Script Plan)
* **ระยะวางแผนผสานหน้าจอวินิจฉัย (DEV-107 ถึง DEV-109)**: ออกแบบสถาปัตยกรรมการกักกันข้อมูลวินิจฉัย (Integration Readiness Plan), กำหนดกรอบแผนผสานหน้าจำลอง (Debug Preview Integration Plan), และจัดวางแผนงานโครงร่าง UI (UI Scaffold Plan/Implementation Plan)
* **ระยะพัฒนาและทบทวนความปลอดภัย (DEV-110 ถึง DEV-111)**: สร้างคอมโพเนนต์วินิจฉัยย่อยแบบปิด [ThaiPlanetPlacementDebugPanel.tsx](file:///Users/tamz/projects/workos-lite/src/components/workspaces/astro-strategy/real-app/components/diagnostics/ThaiPlanetPlacementDebugPanel.tsx), ทำการสแกนความสมบูรณ์ของรหัสโปรแกรม (Source Integrity) และการตรวจสอบความปลอดภัยของคำอธิบายภาษา (Copy Safety Review)
* **ระยะผสานติดตั้งและตรวจสอบความถดถอย (DEV-112 ถึง DEV-115)**: เขียนแผนปฏิบัติการผสานติดตั้งระดับระบบจริง (Preview Wiring Plan & Implementation Plan), ผสานติดตั้งโค้ดวินิจฉัยผ่าน Diagnostics Wrapper (`ThaiPlanetPlacementDiagnosticsSection`), และทำการทดสอบความถดถอยเชิงพฤติกรรม (QA & Regression Review) เพื่อยืนยันความเสถียร

## 3. Current Runtime State (สถานะรันไทม์ปัจจุบัน)

* **Stub-only**: ระบบรันไทม์ปฏิทินไทย v0.1 ทำงานในฐานะ Stub จำลองอินเตอร์เฟสเท่านั้น ไร้การคำนวณตำแหน่งดาราศาสตร์จริง
* **Diagnostic Status**: ตัวจัดการอะแดปเตอร์มีสถานะเป็น `"diagnostic"` เพื่อบ่งชี้วัตถุประสงค์ในการวินิจฉัย
* **Placeholder-safe**: ข้อมูลตำแหน่งดวงดาวที่ส่งมอบเป็นข้อมูลปลอดภัยเชิงโครงร่าง เช่น `"pending-reference-validation"` บนวันและพิกัดสถานที่เกิด และสตริงแจ้งเตือน `"unavailable"` บนองศา/ราศีของดาวเคราะห์
* **No Real Placement**: ยืนยันว่าไม่มีข้อมูลตำแหน่งดวงดาวหรือราศีจริงถูกใช้ประมวลผลรันไทม์ในขณะนี้

---

## 4. UI State (สถานะอินเตอร์เฟสผู้ใช้)

* **Diagnostics Wrapper**: คอมโพเนนต์ `ThaiPlanetPlacementDiagnosticsSection` ถูกสร้างแยกออกมาและติดตั้งอย่างเรียบร้อย
* **Isolated Placement**: ติดตั้งอยู่เฉพาะภายในแท็บ Data Tools (`tools` tab) ของหน้า Preview และถูกจำกัดด้วยเงื่อนไขความปลอดภัยให้พับเก็บซ่อนไว้เป็นค่าเริ่มต้น (`showDiagnostics = false`)
* **AstroTodayPanel Untouched**: โค้ดของ `AstroTodayPanel.tsx` และแผงรายงานดวงรายวัน รายสัปดาห์ หรือรายเดือนของผู้ใช้ทั่วไป **ไม่มีการดัดแปลงหรือผสานคำสั่งใดๆ เข้าไป**
* **User-facing Guidance Clean**: ไม่มีเนื้อหาการวิเคราะห์คำแนะนำชีวิตเชิงวินิจฉัยถูกแสดงผลสู่ผู้ใช้หลัก

---

## 5. Data & Persistence State (สถานะข้อมูลและ LocalStorage)

* **In-memory Only**: ข้อมูลฟิกซ์เจอร์ผ่านการประมวลผลในหน่วยความจำสดใหม่ ไม่มีการดึงข้อมูล Birth Profile ของผู้ใช้งานมาใช้งาน
* **No LocalStorage Write**: ไม่มีการสั่งการคำสั่ง `window.localStorage` เพื่อบันทึกข้อมูล หรือเขียนทับคีย์ระบบเดิม
* **No Cache**: ไม่มีระบบการทำ cache ข้อมูลวินิจฉัย
* **generatedAt as Metadata**: คีย์วันเวลาที่ถูกสร้างขึ้นในอะแดปเตอร์จำกัดเฉพาะประโยชน์ในการเช็กเวลาการอัปเดตสถานะ Component บนหน้าจอเท่านั้น ไม่นำมาวิเคราะห์เวลาดาราศาสตร์

## 6. Strategy Engine State (สถานะการแยกขาดระบบวิเคราะห์ดวง)

* **No Compositions**: ผลลัพธ์ `runtimeResult` ของปฏิทินไทยวินิจฉัยไม่ถูกอ้างอิงเข้าสู่ตัวประมวลผลดวงหลัก เช่น Today/Weekly/Monthly Strategy หรือระบบกลยุทธ์รวม Natal + Transit Strategy Composer
* **No Copy Generation**: ไม่มีคำวิเคราะห์ดวงหรือทำนายชะตาชีวิตใดๆ ที่ถูกผลิตออกมาจากโมเดลดวงดาวไทยจำลองนี้

## 7. Safety & Copy State (การควบคุมคำบรรยายภาษาแสดงผล)

### คำอธิบายภาษาเชิงวินิจฉัยที่บังคับแสดงผล (Required Wording):
* `"Diagnostic only"` (สำหรับวินิจฉัยเท่านั้น)
* `"Stub-only"` (จำลองพฤติกรรมเท่านั้น)
* `"Not validated"` (ยังไม่ผ่านการตรวจสอบความเที่ยงตรง)
* `"Pending reference validation"` (รอการเทียบเคียงกรณีศึกษาอ้างอิง)
* `"Not used for interpretation"` (ห้ามใช้ในการวิเคราะห์ออกผลคำทำนาย)
* `"No real Thai planet placement is displayed"` (ไม่มีพิกัดตำแหน่งดาวเคราะห์จริงจัดแสดง)
* `"Not persisted"` (ไม่มีการเซฟบันทึกเก็บข้อมูลลงเครื่อง)

### คำบรรยายภาษาความเสี่ยงสูงที่ห้ามใช้โดยเด็ดขาด (Avoided Wording):
* `"accurate placement"` (ข้อมูลพิกัดเที่ยงตรง)
* `"real chart"` (ดวงชะตาจริง)
* `"ดาวอยู่ราศี…"` (การระบุราศีจริง)
* `"ผลดวงจริง"` (Real reading output)
* `"ใช้ทำนาย"` (Ready for interpretation)
* `"validated placement"` (ตำแหน่งผ่านการสอบเทียบจริง)

## 8. Known Limitations (ข้อจำกัดในปัจจุบัน)

1. ไม่มีลอจิกถอดรหัสพิกัดดวงดาวดาราศาสตร์ไทยจริง
2. ไม่มีระบบฐานข้อมูลปฏิทินดาราศาสตร์ (Ephemeris) หรือ Almanac
3. ไม่มีลอจิกเปรียบเทียบผลลัพธ์กับผลลัพธ์กรณีมาตรฐาน (Reference Case Comparison) บนรันไทม์จริง
4. ไม่สามารถใช้ในการออกคำทำนาย แนะนำกิจกรรม หรือส่งออกรายงานแก่ผู้ใช้งานได้

## 9. Next Scope Options (การเปรียบเทียบ 5 ทางเลือกสำหรับการพัฒนาในระยะถัดไป)

### ทางเลือก Option A — สิ้นสุดการพัฒนาที่จุดบันทึกจำลองนี้ (Stop as Stable Checkpoint)
* **รายละเอียด**: ยุติการพัฒนาส่วนปฏิทินไทย v0.1 ไว้ที่สถานะวินิจฉัยจำลองนี้ ปลอดภัยและมีความถดถอยเชิงระบบเป็นศูนย์
* **ข้อดี**: ปลอดภัยที่สุด ใช้ทรัพยากรน้อย
* **ข้อเสีย**: ระบบไม่มีการแสดงผลคำนวณตำแหน่งจริง

### ทางเลือก Option B — ปรับแต่งประสบการณ์วินิจฉัยเชิงรหัส (Improve Debug UX Only)
* **รายละเอียด**: ปรับแต่งรายละเอียดหน้าตา ความหนาแน่นของตารางข้อมูล รายงานข้อผิดพลาด และหมายเหตุสำหรับผู้พัฒนาบน Debug Panel โดยยังคงไม่เพิ่มตรรกะคำนวณใดๆ
* **ข้อดี**: การตรวจสอบสัญญาง่ายขึ้น ปลอดภัยสูง
* **ข้อเสีย**: ยังคำนวณดวงจริงไม่ได้

### ทางเลือก Option C — จัดทำระบบตรวจสอบความสอดคล้องรันไทม์ (Build Validation Fixture Runner)
* **รายละเอียด**: พัฒนาเครื่องมือตรวจสอบความสอดคล้องทางกฎเกณฑ์ (Assertion Runner) บนรันไทม์ผ่าน TypeScript โดยปรับปรุงจากสคริปต์ตรวจสัญญาด้วยมือในปัจจุบัน เพื่อสแกนตรวจสอบความเที่ยงตรงของ Props และโครงสร้างข้อมูลวินิจฉัยแบบอัตโนมัติ
* **ข้อดี**: เสริมความแข็งแกร่งในการตรวจจับบั๊กและพฤติกรรมแปลกปลอมเชิงโครงร่าง โดยไม่ส่งผลกระทบต่อลอจิกระบบคำนวณหลัก
* **ข้อเสีย**: ยังคำนวณดวงจริงไม่ได้

### ทางเลือก Option D — ศึกษาวิจัยข้อมูลกรณีศึกษาอ้างอิงเทียบเคียงปฏิทินดาวไทย (Begin Reference Validation Research)
* **รายละเอียด**: ศึกษาแหล่งข้อมูลปฏิทินทางกฎหมายและจริยธรรม สำหรับจัดทำระบบเทียบเคียงตำแหน่งดวงดาวไทย โดยไม่ใช้การ Scraping หรือก๊อปปี้ข้อมูลที่มีลิขสิทธิ์
* **ข้อดี**: ได้กรอบความถูกต้องเชิงวิชาการสำหรับใช้เปรียบเทียบก่อนลงรหัสคำนวณ
* **ข้อเสีย**: ใช้เวลาในเชิงเอกสารและการหาข้อมูลวิชาการอ้างอิง

### ทางเลือก Option E — เริ่มต้นวางแผนและพัฒนาโครงคำนวณแกนกลาง (Start Calculation Core Plan)
* **รายละเอียด**: เริ่มจัดทำแผนงานและลงรหัสคำนวณตำแหน่งการเคลื่อนที่เฉลี่ย (Mean-motion) หรือตารางค้นหาข้อมูลตำแหน่งดาว (Lookup-table) ของปฏิทินไทย
* **ข้อดี**: ระบบขยับเข้าใกล้การคำนวณองศาดาวเคราะห์จริง
* **ข้อเสีย**: ความเสี่ยงทางวิศวกรรมค่อนข้างสูง ต้องมีมาตรการตรวจสอบความปลอดภัยและความเที่ยงตรงเทียบปฏิทินจริงเข้มงวด

## 11. Risk Review (บทวิเคราะห์ความเสี่ยงระยะยาว)

* **ความเสี่ยงจากการเริ่มพัฒนาส่วนคำนวณเร็วเกินไป (Early Calculation Risk)**: หากจัดทำส่วนประมวลผลดวงดาวเร็วเกินไปโดยไม่ผ่านการสอบทานกรณีศึกษาอ้างอิง อาจได้ผลลัพธ์ตำแหน่งดวงดาวที่เพี้ยนหรือผิดพลาดจากกฎดาราศาสตร์ไทยจริง
* **ความเสี่ยงจากข้อมูลจำลองถูกเข้าใจผิดว่าเป็นข้อมูลจริง (Placeholder Misinterpretation Risk)**: ผู้ใช้งานหรือผู้พัฒนาอาจนำค่าจำลองจากเครื่องมือวินิจฉัยไปตีความเปรียบเทียบความถูกต้องของดวงชะตาจริง
* **ความเสี่ยงเชิงลิขสิทธิ์และแหล่งข้อมูล (Copyright & Reference Risk)**: การดึงหรือก๊อปปี้สูตรคำนวณหรือข้อมูลปฏิทินที่มีลิขสิทธิ์เข้ามาในซอร์สโค้ดโดยตรง
* **ความเสี่ยงการรั่วไหลลง LocalStorage / Composer (Integration Contamination Risk)**: ข้อมูลตำแหน่งทดสอบหลุดรอดจาก Gate ความปลอดภัยและเข้าไปทำลายความสมบูรณ์ของ LocalStorage และ Natal/Transit Strategy Composer
