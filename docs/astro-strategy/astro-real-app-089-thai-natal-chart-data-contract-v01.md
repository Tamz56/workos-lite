# ASTRO-REAL-APP-DEV-089 — Thai Natal Chart Data Contract v0.1

เอกสารนี้กำหนดข้อกำหนดโครงสร้างข้อมูลดวงกำเนิดไทย (Data Contract) สำหรับเวอร์ชัน 0.1 ซึ่งจะใช้เป็นรากฐานสำหรับพัฒนาแกนการประมวลผล (Calculation Core) ในอนาคต โดยโครงสร้างนี้มุ่งเน้นการจัดเก็บและส่งผ่านค่าสัญญะทางดาราศาสตร์เพื่อแปลงเป็นแผนกลยุทธ์การทำงานและการใช้ชีวิตของผู้ใช้

---

## 1. Goal (เป้าหมายของการกำหนดโครงสร้างข้อมูล)

* **กำหนดมาตรฐานข้อมูล**: วางกรอบอินเทอร์เฟซอินพุตและเอาต์พุตสำหรับชุดข้อมูลดวงเกิดของไทย (Thai Natal Chart v0.1)
* **รากฐานการพัฒนา**: เพื่อเตรียมพร้อมสำหรับตัวประมาณค่า (Approximation Adapters) และโปรแกรมถอดความหมายที่จะพัฒนาในระยะถัดไป
* **ข้อจำกัดในรอบการพัฒนา**: 
  - ยังไม่มีการเขียนรหัสการคำนวณจริง (Runtime calculation) ในรอบนี้
  - ยังไม่มีการแก้ไขโครงสร้างการจัดเก็บข้อมูลของเบราว์เซอร์ (LocalStorage schema)

---

## 2. Input Data Model (โครงสร้างข้อมูลนำเข้า)

ข้อมูลนำเข้าดิบที่ระบบต้องรับจากผู้ใช้ผ่านหน้าต่างกรอกข้อมูลเพื่อประมวลผลดวงเกิด ประกอบด้วยฟิลด์ดังต่อไปนี้:

```typescript
interface ThaiNatalChartInputV01 {
  fullName?: string;                  // ชื่อและนามสกุล (ไม่บังคับระบุ)
  birthDate: string;                  // วันเกิด รูปแบบ ISO (YYYY-MM-DD)
  birthTime: string;                  // เวลาเกิด รูปแบบ HH:mm (ระบบ 24 ชั่วโมง)
  birthPlaceName: string;             // ชื่อจังหวัดหรือสถานที่เกิดในประเทศไทย
  birthCountry: string;               // ประเทศที่เกิด (ค่าเริ่มต้นคือ "TH")
  timezone: string;                   // เขตเวลาของสถานที่เกิด (เช่น "Asia/Bangkok")
  latitude?: number;                  // พิกัดเส้นรุ้ง (ไม่บังคับระบุใน v0.1)
  longitude?: number;                 // พิกัดเส้นแวง (ไม่บังคับระบุ in v0.1)
  calendarSystem: 'suriyayart' | 'lahiri' | 'approximate'; // ระบบการคำนวณปฏิทินดาราศาสตร์
  birthTimeConfidence: 'high' | 'medium' | 'low' | 'unknown'; // ระดับความแน่นอนของเวลาเกิด
  birthplaceConfidence: 'high' | 'medium' | 'low' | 'unknown'; // ระดับความแน่นอนของสถานที่เกิด
}
```

## 3. Normalized Birth Data (ชุดข้อมูลวันเกิดหลังการแปลงมาตรฐาน)

ข้อมูลดิบจากอินพุตจะถูกประมวลผลและแปลงเป็นโครงสร้างมาตรฐาน (Normalized Object) เพื่อใช้เปรียบเทียบกับปฏิทินดาราศาสตร์และดาวจรได้อย่างคงเส้นคงวา:

```typescript
interface NormalizedBirthDataV01 {
  localDateTime: string;              // วันเวลาท้องถิ่น รูปแบบ ISO-8601 (YYYY-MM-DDTHH:mm:ss)
  utcDateTime?: string;               // วันเวลามาตรฐานสากล (UTC) (ไม่บังคับระบุหากระบุพิกัดไม่ได้)
  timezoneOffset: number;             // ความต่างของเวลากับ UTC ในหน่วยนาที (เช่น +420 สำหรับไทย)
  localNoonGuard: boolean;            // แฟล็กป้องกันความเข้าใจคลาดเคลื่อนกรณีเกิดช่วงกึ่งกลางวัน
  dayBoundaryRisk: boolean;           // แฟล็กแจ้งเตือนความเสี่ยงช่วงรอยต่อวัน (เช่น เกิดเวลาระหว่าง 00:00 - 06:00 น.)
  missingBirthTime: boolean;          // แฟล็กระบุว่าไม่มีข้อมูลเวลาเกิดที่แน่นอน (ส่งผลต่อการประมาณลัคนา)
  missingBirthLocation: boolean;      // แฟล็กระบุว่าไม่มีข้อมูลพิกัดสถานที่เกิดที่แน่นอน
  confidenceScore: number;            // คะแนนความน่าเชื่อถือโดยรวมของข้อมูลนำเข้า (ช่วงคะแนน 0.0 - 1.0)
}
```

## 4. Thai Natal Chart Output Contract (โครงสร้างข้อมูลผลลัพธ์)

อินเทอร์เฟซหลักสำหรับการคืนค่าข้อมูลดวงกำเนิดหลังจากผ่านแกนประมวลผล (ThaiNatalChartV01) มีโครงสร้างดังนี้:

```typescript
interface ThaiNatalChartV01 {
  chartId: string;                    // รหัสอ้างอิงเฉพาะของดวงชะตานี้ (UUID)
  source: string;                     // ที่มาของข้อมูล (เช่น "AstroStrategyLab_Client")
  calculationVersion: string;         // เวอร์ชันของระบบการคำนวณ (เช่น "0.1.0")
  birthData: NormalizedBirthDataV01;  // ข้อมูลเกิดที่แปลงค่ามาตรฐานแล้ว
  ascendant: ThaiAscendantV01;        // ข้อมูลลัคนาชะตา
  zodiacPlacements: PlanetPlacementV01[]; // รายการตำแหน่งดาวเคราะห์ในแต่ละราศี
  housePlacements: HousePlacementV01[];   // รายการความสัมพันธ์ของดาวเคราะห์กับภพเรือนชะตา
  planetaryPlacements: Record<number, PlanetPlacementV01>; // คีย์แมปตาม PlanetId (ดาว 0 ถึง 9)
  elementBalance: ElementBalanceV01;  // สัดส่วนสมดุลธาตุ
  dominantHouses: number[];            // รายการรหัสภพชะตาที่มีดาวสถิตหนาแน่นหรือมีอิทธิพลสูง
  strategicSignals: string[];          // รายการ Signal IDs หลักที่สกัดจากพื้นดวงเกิด
  confidenceNotes: string;            // หมายเหตุอธิบายระดับความน่าเชื่อถือและการคำนวณประมาณค่า
  safetyDisclaimer: string;           // คำชี้แจงสิทธิ์ความปลอดภัยและข้อจำกัดการใช้งานเพื่อการวางแผนเชิงยุทธศาสตร์
  generatedAt: string;                // วันเวลาที่ทำการสร้างข้อมูลชิ้นนี้ (ISO-8601)
}
```

## 5. Ascendant Contract (อินเทอร์เฟซข้อมูลลัคนา)

โครงสร้างการระบุข้อมูลลัคนาที่ประมวลผลได้ โดยมีการควบคุมระดับความมั่นใจ:

```typescript
interface ThaiAscendantV01 {
  zodiacSign: string;                 // ชื่อราศีที่ลัคนาสถิต (ภาษาอังกฤษตัวเล็ก เช่น "aries", "taurus", ...)
  degreeApprox?: number;              // องศาโดยประมาณของลัคนาในราศีนั้น (ไม่บังคับระบุใน v0.1)
  houseSystem: string;                // ระบบเรือนชะตาที่ใช้คำนวณ (เช่น "equal_house_system")
  calculationMethod: 'sunrise_offset' | 'table_lookup' | 'precise'; // วิธีการประมวลผลลัคนา
  confidenceScore: number;            // คะแนนความมั่นใจเฉพาะจุด (0.0 - 1.0)
  uncertaintyNotes: string;           // บันทึกคำเตือนกรณีไม่มีเวลาเกิดที่แน่นอนและผลกระทบต่อตำแหน่งลัคนา
}
```

## 6. Planet Placement Contract (อินเทอร์เฟซตำแหน่งดาวเคราะห์)

รายละเอียดตำแหน่งดวงดาวแต่ละดวง (ดาว ๐ ถึง ๙ ตามการบันทึกโหราศาสตร์ไทย) มีโครงสร้างข้อมูลดังนี้:

```typescript
interface PlanetPlacementV01 {
  planetId: number;                   // รหัสดาวเคราะห์ตามระบบไทย (0 = อาทิตย์, 1 = จันทร์, ... ถึง 9 = เกตุ)
  planetNameThai: string;             // ชื่อดาวในภาษาไทย (เช่น "อาทิตย์", "จันทร์", "อังคาร")
  zodiacSign: string;                 // ราศีที่สถิตอยู่ (ภาษาอังกฤษตัวเล็ก เช่น "gemini", "cancer")
  degreeApprox?: number;              // องศาโดยประมาณของดวงดาวในราศีนั้น
  houseNumber?: number;               // ลำดับภพเรือนชะตาที่ดาวดวงนี้ไปสถิตอยู่ (1 ถึง 12 อิงตามลัคนา)
  isApproximation: boolean;           // แฟล็กระบุว่าตำแหน่งนี้เป็นค่าประมาณการ
  confidenceScore: number;            // ระดับความเชื่อมั่นของการประมาณตำแหน่งดาว
  interpretationSignalIds: string[];  // รายการรหัสสัญญะสำหรับนำไปตีความแปลความหมายเป็นกลยุทธ์
}
```

## 7. House Contract (อินเทอร์เฟซภพเรือนชะตา)

โครงสร้างข้อมูลของภพชะตาทั้ง 12 ภพ เพื่อประเมินบริบทหรือสภาพแวดล้อมที่ส่งผลกระทบต่อชีวิตและการทำงานของผู้ใช้:

```typescript
interface HousePlacementV01 {
  houseNumber: number;                // ลำดับภพชะตา (1 = ตนุ, 2 = กฎุมพะ, ... ถึง 12 = วินาศ)
  houseNameThai: string;              // ชื่อภพชะตาภาษาไทย (เช่น "ตนุ", "กัมมะ", "ลาภะ")
  workLifeTheme: string;              // แกนความหมายหลักของภพชะตาที่เกี่ยวข้องกับการงานและชีวิต
  zodiacSign: string;                 // ราศีของภพชะตานั้น
  lordPlanetId?: number;              // รหัสดาวเจ้าเรือน (ดาวเกษตรผู้รักษาภพชะตานั้น)
  strategicMeaningIds: string[];      // รายการรหัสกลยุทธ์ที่เชื่อมโยงกับภพชะตานี้
}
```

### การจัดลำดับความสำคัญของภพชะตา (Priority Houses)
ในการออกแบบระบบแปลผล เวอร์ชัน 0.1 จะให้ความสำคัญเป็นพิเศษกับภพชะตาที่ส่งผลต่อการวางแผนทำงานและจัดภารกิจของผู้ใช้ ได้แก่:
1. **ตนุ (House 1)**: ตัวตน ระดับพลังงานพื้นฐาน และแรงขับเคลื่อนส่วนบุคคล
2. **กัมมะ (House 10)**: กิจกรรม หน้าที่การงาน และภารกิจส่งมอบหลัก
3. **ลาภะ (House 11)**: ผลสัมฤทธิ์ เป้าหมาย ความลุล่วง และโหมดการส่งมอบงาน
4. **อริ (House 6)**: ปัญหา อุปสรรค จุดที่ต้องตรวจสอบ และเงื่อนไขการแก้ปัญหาเฉพาะหน้า
5. **วินาศ (House 12)**: ข้อจำกัด จุดบอดภายใน โหมดกักตัวทำงานเงียบๆ หรือการจำศีล
6. **ปัตนิ (House 7)**: ผู้ร่วมงาน หุ้นส่วน และการประชุมประสานงานกับบุคคลภายนอก
7. **พันธุ (House 4)**: สภาพแวดล้อมที่ทำงาน ฐานราก และความมั่นคงเชิงอารมณ์
8. **ศุภะ (House 9)**: ความสำเร็จในระยะยาว การเรียนรู้องค์ความรู้ใหม่ และวิสัยทัศน์

## 8. Element Balance Contract (อินเทอร์เฟซสมดุลธาตุ)

โครงสร้างการวิเคราะห์สัดส่วนธาตุในแผนผังดวงเกิด เพื่อแนะนำความต้องการทางกายภาพและการจัดโหมดกิจกรรม:

```typescript
interface ElementBalanceV01 {
  fireScore: number;                  // สัดส่วนธาตุไฟ (พลังงานผลักดัน ความเร่งร้อน การลงมือทำ)
  earthScore: number;                 // สัดส่วนธาตุดิน (ความมั่นคง ความสม่ำเสมอ การจัดระเบียบโครงสร้าง)
  airScore: number;                   // สัดส่วนธาตุลม (การคิดวิเคราะห์ การสื่อสาร ความคล่องตัว)
  waterScore: number;                 // สัดส่วนธาตุน้ำ (ความรู้สึกร่วม การฟื้นคืนจิตใจ การปรับตัว)
  dominantElement: 'fire' | 'earth' | 'air' | 'water'; // ธาตุเด่นหลักในชะตา
  underrepresentedElement: 'fire' | 'earth' | 'air' | 'water'; // ธาตุที่อ่อนกำลังหรือขาดแคลน
  interpretationSignalIds: string[];  // รายการรหัสตีความกลยุทธ์การปรับสมดุลธาตุประจำวัน
  confidenceScore: number;            // ความเชื่อมั่นของการประเมินสมดุลธาตุ
}
```

## 9. Strategy Signal IDs (รหัสสัญญะสำหรับพจนานุกรมแปลผล)

เพื่อหลีกเลี่ยงการจัดเก็บประโยคบรรยายยาวเหรอเชิงทำนายชะตากรรมที่ล้นเกินข้อมูล เอาต์พุตของสัญญาข้อมูลจะบรรจุเฉพาะรหัสสั้น (Signal IDs) ซึ่งจะนำไปแมปคู่คำบรรยายผ่านพจนานุกรมกลยุทธ์ในอนาคต:

### 1. รูปแบบพฤติกรรมการทำงาน (TH_NATAL_WORK_STYLE)
* `TH_NATAL_WORK_STYLE_DEEP_FOCUS`: เหมาะกับการทำงานที่ต้องการสมาธิลึกซึ้งและสันโดษ
* `TH_NATAL_WORK_STYLE_COLLABORATIVE`: เหมาะกับการแลกเปลี่ยนและการผลักดันเป้าหมายร่วมกับทีม
* `TH_NATAL_WORK_STYLE_ROUTINE_SYSTEM`: เหมาะกับการจัดระเบียบงานเอกสารและสร้างเสถียรภาพระบบ

### 2. วิธีการตัดสินใจ (TH_NATAL_DECISION_STYLE)
* `TH_NATAL_DECISION_STYLE_ANALYTICAL`: เน้นข้อมูลเชิงตัวเลขและการประเมินเหตุผลอย่างละเอียด
* `TH_NATAL_DECISION_STYLE_INTUITION`: ใช้สัญชาตญาณและการจับแนวโน้มความรู้สึกร่วมของทีมงาน
* `TH_NATAL_DECISION_STYLE_FAST_ACTION`: ตัดสินใจฉับพลันในสถานการณ์เร่งด่วน

### 3. โหมดการพักฟื้นคืนพลัง (TH_NATAL_RECOVERY_STYLE)
* `TH_NATAL_RECOVERY_STYLE_ISOLATION`: พักผ่อนคนเดียวในสภาพแวดล้อมที่เงียบสงบ
* `TH_NATAL_RECOVERY_STYLE_SOCIAL_CONNECT`: คืนพลังด้วยการสนทนาอย่างไม่เป็นทางการในหัวข้อผ่อนคลาย
* `TH_NATAL_RECOVERY_STYLE_PHYSICAL_REST`: เน้นการนอนหลับหรือผ่อนคลายกล้ามเนื้อทางกายภาพ

### 4. รูปแบบการร่วมมือกับบุคคลอื่น (TH_NATAL_COLLABORATION_STYLE)
* `TH_NATAL_COLLABORATION_STYLE_DIRECT_LEAD`: เหมาะกับการรับบทบาทนำและสั่งการภารกิจ
* `TH_NATAL_COLLABORATION_STYLE_SUPPORT_FACILITATE`: เหมาะกับการอำนวยความสะดวกและประสานประโยชน์

### 5. แนวโน้มจุดเสี่ยงเฉพาะตัว (TH_NATAL_RISK_PATTERN)
* `TH_NATAL_RISK_PATTERN_BURNOUT_PRONE`: มีโอกาสเหนื่อยล้าสะสมง่ายจากการรับภาระเกินตัว
* `TH_NATAL_RISK_PATTERN_OVERTHINKING`: มีแนวโน้มทบทวนซ้ำซ้อนจนเกิดสภาวะงานหยุดนิ่ง (Analysis Paralysis)

### 6. รูปแบบการเปิดรับความรู้ (TH_NATAL_LEARNING_PATTERN)
* `TH_NATAL_LEARNING_PATTERN_STRUCTURED`: เรียนรู้จากตำรา ข้อมูลเชิงระบบ และทฤษฎีอ้างอิง
* `TH_NATAL_LEARNING_PATTERN_EXPERIENTIAL`: เรียนรู้จากการทดลองทำจริงและพบข้อผิดพลาดหน้างาน

### 7. ลักษณะการส่งมอบงาน (TH_NATAL_EXECUTION_PATTERN)

## 10. Confidence Policy (นโยบายการควบคุมระดับความมั่นใจ)

เพื่อความโปร่งใสและถูกต้องตามความเป็นจริงเชิงระบบ แกนการประมวลผลดวงเกิดเวอร์ชัน 0.1 จะใช้เกณฑ์การจำกัดความมั่นใจอย่างเข้มงวด:
* **กรณีผู้ไม่ระบุเวลาเกิดที่ละเอียด**: 
  - ระบบจะลดระดับความมั่นใจของลัคนาชะตา (Confidence Score) ลงเหลือ 0.0 ทันที
  - กำหนดให้ระบุค่า `missingBirthTime = true`
  - คืนค่าตำแหน่งดาวเคราะห์ด้วยระดับความเชื่อมั่นที่จำกัด และซ่อนคำอธิบายเชิงภพชะตา
* **กรณีผู้ไม่ระบุพิกัดสถานที่เกิด (จังหวัดเกิด)**:
  - กำหนดค่า `missingBirthLocation = true`
  - ทำการลดระดับความมั่นใจของลัคนาลง 20%
* **กรณีคาบเกี่ยวกับรอยต่อของวัน**:
  - หากวันเวลาเกิดอยู่ในช่วง 00:00 - 06:00 น. ระบบจะเปิดสถานะ `dayBoundaryRisk = true` เสมอ และแจ้งหมายเหตุในส่วน `confidenceNotes` เพื่อเตือนถึงความเป็นไปได้ในการเปลี่ยนผ่านวันตามปฏิทินแบบโหราศาสตร์ไทยเดิม
* **การระบุการจำลอง**: 
  - ทุกจุดที่มีการคืนค่าแบบประมาณการ ต้องระบุแฟล็ก `isApproximation = true`
  - ต้องแสดงข้อความ `confidenceNotes` ชี้แจงขีดจำกัดความแม่นยำแก่ผู้ใช้ในทุกหน้าจอแสดงผลเอาต์พุต

## 11. Data Safety & Privacy Policy (นโยบายความปลอดภัยและความเป็นส่วนตัว)

* **ความละเอียดอ่อนของข้อมูลเกิด**: ข้อมูลวันเกิด เวลาเกิด และสถานที่เกิด เป็นข้อมูลระบุตัวตนที่มีความละเอียดอ่อนสูง
* **ข้อจำกัดการใช้งานภายในเครื่อง (On-Device Processing)**:
  - การวิเคราะห์และการจัดเก็บข้อมูลในระยะเริ่มต้นจะต้องทำภายในเครื่องของผู้ใช้แบบปิด (Client-side environment) เท่านั้น
  - ห้ามส่งผ่านข้อมูลเกิดดิบของผู้ใช้ออกไปนอกบราวเซอร์หรือส่งไปยัง API ตรวจสอบภายนอกโดยไม่ได้รับการยินยอมอย่างโจ่งแจ้ง
* **การส่งออกข้อมูลส่วนตัว (Data Export Warning)**: ในอนาคตหากมีระบบ Export ข้อมูลการตั้งค่าระบบในรูปแบบไฟล์ JSON ระบบจะต้องเพิ่มการเตือนความเป็นส่วนตัว (Privacy warning) ชี้แจ้งแก่ผู้ใช้ว่าไฟล์ดังกล่าวบรรจุข้อมูลวันเกิดละเอียดอ่อน
* **ไม่มีผลกระทบต่อ LocalStorage ในรอบนี้**: ไม่มีการเพิ่ม Key หรือเปลี่ยนแปลงโครงสร้างของ LocalStorage เดิม การรันข้อมูลสัญญาเวอร์ชัน 0.1 จะประมวลผลแบบชั่วคราวชั่วขณะ (In-memory evaluation) เสมอ

## 12. Non-Scope (ขอบเขตที่ไม่มีการดำเนินการ)

* **ไม่มีการผูกดวงหาองศาลัคนาจริง**: จะไม่มีระบบคำนวณอันโตนาทีหรือการประมาณพิกัดดาราศาสตร์เต็มพิกัดในรอบนี้
* **ไม่มีการคำนวณพิกัดดาวจรจริง**: ไม่มีการเขียนรหัสหาตำแหน่งดวงดาวจริงจากสูตรคณิตศาสตร์ดาราศาสตร์
* **ไม่มีการบรรจุฐานข้อมูล Ephemeris**: ไม่เพิ่มไลบรารีคำนวณตำแหน่งดาวที่ทำให้ขนาดของบันเดิลซอฟต์แวร์ล้นเกิน
* **ไม่มีการเชื่อมต่อเครือข่าย**: ไม่ต่อสัญญาส่งข้อมูลเกิดไปยังเซิร์ฟเวอร์ภายนอก
* **ไม่มีการปรับแก้ UI และ Runtime Source**: รักษาความคงรูปเดิมของโค้ดโปรเจกต์ภายใน `src/` ทั้งหมด
* **ห้ามแสดงข้อความทำนายทายทักเชิงทำนายอนาคตเด็ดขาด**: มุ่งเน้นการประเมินสภาพและระดับพลังงานของกลุ่มงานเท่านั้น
