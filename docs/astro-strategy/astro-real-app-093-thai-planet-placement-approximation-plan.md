# ASTRO-REAL-APP-DEV-093 — Thai Planet Placement Approximation Plan

เอกสารฉบับนี้จัดทำขึ้นเพื่อกำหนดแผนงานและข้อกำหนดทางเทคนิคสำหรับการคำนวณประมาณตำแหน่งดาวเคราะห์ไทย เวอร์ชัน 0.1 (Thai Planet Placement Approximation Plan v0.1) เพื่อใช้เป็นฐานสำหรับการพัฒนาขีดความสามารถการคำนวณดวงชะตาเกิด (Natal Chart) และการเชื่อมต่อดวงจร (Transit Interpreter) ในระยะถัดไป

---

## 1. Goal (เป้าหมายของแผนการประมาณตำแหน่งดาว)

* **วางแผนประมาณตำแหน่งดาวไทย v0.1**: กำหนดกรอบแนวทางการประมาณราศีที่สถิตของดาวเคราะห์หลักทั้ง 10 ดวงบน Client-side
* **ระบบข้อมูลขัดเกลา**: คืนค่าตำแหน่งดวงดาวแยกตามมิติราศีและภพเรือนชะตา เพื่อแปลงเป็นรหัส Signal IDs สำหรับเชื่อมโยงกับพจนานุกรมแปลผลกลยุทธ์
* **ข้อจำกัดเชิงสถาปัตยกรรม**:
  - ยังไม่เริ่มเขียนรหัสคำนวณจริง (Runtime code) ในรอบนี้
  - ยังไม่มีการแก้ไขโครงสร้าง LocalStorage schema หรือจัดตั้งฐานข้อมูล Ephemeris
  - ไม่อ้างอิงความแม่นยำระดับวินาทีลิปดาเทียบเท่าโปรแกรมผูกดวงชะตาเชิงพยากรณ์เต็มระบบ

---

## 2. Why Planet Placement Matters (ความสำคัญของตำแหน่งดาวเคราะห์)

ในทางโหราศาสตร์เชิงระบบ ดวงดาวทำหน้าที่เป็นสัญญะเด่นประธาน (Core Signifiers) ในการเปลี่ยนระดับและทิศทางพลังงาน:
* **สัญญะขับเคลื่อนกลยุทธ์**: ตำแหน่งดวงดาวเกิดปะทะตำแหน่งเรือนชะตาจะชี้วัดลักษณะสไตล์การทำงาน การจัดลำดับเป้าหมาย การตัดสินใจ และข้อควรระวัง
* **ความเบี่ยงเบนสะสม**: เมื่อประมาณราศีดาวเคราะห์ผิดพลาด การตีความสัญญะยุทธศาสตร์ (เช่น คตินิยมดาวพุธในภพกัมมะ) จะแปรเปลี่ยนไปทั้งมิติ ระบบจึงต้องควบคุมความแม่นยำด้วยการใช้คะแนนความมั่นใจ (`confidenceScore`) และหมายเหตุความไม่แน่นอน (`uncertaintyNotes`) เสมอ

## 3. Required Inputs (ข้อมูลนำเข้าสำหรับการคำนวณ)

ชุดตัวแปรนำเข้าที่ได้จากขั้นตอน Normalize วันเกิด และตัวคำนวณลัคนาก่อนหน้า:
* `normalizedBirthData`: ชุดข้อมูลวันเกิดที่แปลงรูปแบบมาตรฐานแล้ว
* `birthDate` / `birthTime` / `timezone`: ข้อมูลวัน เวลา และเขตเวลาชั่วเกิด
* `latitude` / `longitude`: พิกัดภูมิศาสตร์ (ไม่บังคับระบุใน v0.1)
* `ascendantZodiacSign`: ราศีลัคนาที่ประเมินได้
* `houseMapping`: แผนผังเรือนชะตา 12 ภพที่จัดสรรแล้ว
* `calculationMethod`: วิธีการประมาณที่ส่งต่อมา
* `confidenceScore` จากลัคนา: คะแนนความมั่นใจลัคนาสำหรับใช้ทอนสิทธิความน่าเชื่อถือ
* `dayBoundaryRisk`: สถานะแจ้งเตือนรอยต่อเปลี่ยนวันเกิด

## 4. Planet Scope v0.1 (ขอบเขตดาวเคราะห์ที่ระบบรองรับ)

แกนประมาณค่าในเวอร์ชัน 0.1 จะรองรับการระบุตำแหน่งราศีของดวงดาวหลัก 10 ดวง (ดวงดาว ๐ ถึง ๙ ตามการบันทึกโหราศาสตร์ไทย) ดังนี้:

* **0 ลัคนา / Ascendant reference**: จุดวิถีชีวิตหลักและจุดศูนย์กลางเรือนชะตา
* **1 อาทิตย์ (ดวงดาว ๑)**: ตัวแทนเจตจำนง ความชัดเจนในการนำ และทิศทางวิสัยทัศน์
* **2 จันทร์ (ดวงดาว ๒)**: ตัวแทนสัญชาตญาณ อารมณ์ความรู้สึก และการฟื้นฟูกายใจ
* **3 อังคาร (ดวงดาว ๓)**: ตัวแทนความขยัน การลงมือทำ ความเร่งร้อน และความอดทนทางกายภาพ
* **4 พุธ (ดวงดาว ๔)**: ตัวแทนความคิดสร้างสรรค์ การเจรจาสื่อสาร และการวิเคราะห์เอกสาร
* **5 พฤหัสบดี (ดวงดาว ๕)**: ตัวแทนสติปัญญา องค์ความรู้ ครูบาอาจารย์ และวิสัยทัศน์ระยะยาว
* **6 ศุกร์ (ดวงดาว ๖)**: ตัวแทนการประสานประโยชน์ สุนทรียภาพ ศิลปะ และทักษะมนุษยสัมพันธ์
* **7 เสาร์ (ดวงดาว ๗)**: ตัวแทนความรับผิดชอบ โครงสร้าง วินัยระยะยาว และภาระสะสม
* **8 ราหู (ดวงดาว ๘)**: ตัวแทนความทะเยอทะยาน งานเทคโนโลยี/ต่างประเทศ และจุดบอดที่ต้องระวัง
* **9 เกตุ (ดวงดาว ๙)**: ตัวแทนการปล่อยวาง การสะสางงานตกค้าง และการทำงานปิดทองหลังพระ

*หมายเหตุ: ในเวอร์ชัน 0.1 นี้ จะมุ่งเน้นเฉพาะการจับพิกัดราศีที่สถิตและเรือนชะตาเท่านั้น ยังไม่มีการคำนวณหามุมองศา ลิปดา ละเอียด*

## 5. Approximation Strategy v0.1 (กลยุทธ์การประมาณตำแหน่งดาว)

* **สถาปัตยกรรมอ้างอิงดัชนี (Simplified Reference Structure)**: ใช้ระบบอ้างอิงตารางพิกัดเฉลี่ยชั่วขณะ (Simplified lookup table) ร่วมกับความเร็วโคจรเฉลี่ยของดาวเคราะห์แต่ละดวง แทนการรันคำนวณฟิสิกส์ดาราศาสตร์เต็มพิกัด
* **แยกแยะตรรกะราศีและภพชะตา**:
  - ประเมินหาพิกัดราศีของดวงดาวก่อน (Zodiac Placement)
  - นำตำแหน่งราศีดาวเทียบกับตำแหน่งราศีลัคนาเพื่อระบุพิกัดเรือนชะตา (House Placement)
* **องศาแบบประมาณการ**: คืนค่าองศาเฉลี่ยแบบไม่ผูกพัน (`degreeApprox?: number` เป็น optional ฟิลด์)
* **การชี้แจงความเป็นจริง**: คืนค่าสถานะ `isApproximation = true` ในทุกชุดคำตอบ และห้ามอ้างอิงผลลัพธ์ดั่งเป็นลองจิจูดดวงดาวที่แท้จริงระดับองศาเด็ดขาด

## 6. Planet Placement Output Contract (ข้อตกลงรูปแบบผลลัพธ์ดวงดาว)

อินเทอร์เฟซสำหรับการคืนข้อมูลตำแหน่งดาวเคราะห์รายดวง (ThaiPlanetPlacementV01):

```typescript
interface ThaiPlanetPlacementV01 {
  planetId: number;                   // รหัสดาวเคราะห์ไทย (0 ถึง 9)
  planetNameThai: string;             // ชื่อดาวเคราะห์ภาษาไทย (เช่น "อาทิตย์")
  planetNameSanskrit?: string;        // ชื่อภาษาสันสกฤตของดวงดาว (ไม่บังคับระบุ)
  zodiacSign: string;                 // ราศีที่สถิตอยู่ (ภาษาอังกฤษตัวเล็ก เช่น "aries", "taurus")
  degreeApprox?: number;              // องศาโดยประมาณ (ไม่บังคับระบุ)
  houseNumber?: number;               // ลำดับภพชะตาที่ดาวสถิต (1 ถึง 12 อิงตามลัคนา)
  isApproximation: boolean;           // สถานะการประมาณค่า (ต้องเป็น true เสมอใน v0.1)
  calculationMethod: 'lookup_table_v1' | 'mean_motion_approx' | 'fallback_baseline'; // วิธีที่คำนวณ
  confidenceScore: number;            // คะแนนระดับความมั่นใจเฉพาะดาว (0.0 - 1.0)
  uncertaintyNotes: string;           // บันทึกระบุสาเหตุความเบี่ยงเบน
  interpretationSignalIds: string[];  // รายการรหัสสัญญะสำหรับส่งต่อไปยังพจนานุกรมแปลผล
  generatedAt: string;                // วันเวลาสร้างข้อมูล (ISO-8601)
}
```

## 7. Planet Meaning Strategy Categories (การจัดหมวดความหมายดาวเชิงกลยุทธ์)

ตรรกะถอดรหัสความหมายดวงดาวจะต้องแปลงออกเป็น **โหมดพฤติกรรมการจัดการภารกิจ** เท่านั้น ปราศจากการทำนายทายทักเรื่องราวอนาคต:
* **อาทิตย์ (๑)**: จุดโฟกัสความเป็นผู้นำ ความชัดเจนในการอนุมัติงาน และเป้าหมายที่ตรงประเด็น
* **จันทร์ (๒)**: ความละเอียดอ่อนในการประสานอารมณ์ความรู้สึก และการชะลอการสื่อสารกรณีล้าสะสม
* **อังคาร (๓)**: ความขยันขันแข็งในการสะสางงานที่ต้องออกแรงกล้ามเนื้อหรืองานเร่งด่วนหน้างาน
* **พุธ (๔)**: กิจกรรมการคิดวิเคราะห์ การออกแบบโครงสร้างเอกสาร และการติดต่อทำข้อตกลงสำคัญ
* **พฤหัสบดี (๕)**: การทบทวนแผนงานวิชาการ การเรียนรู้ทักษะใหม่ และการรับฟังความเห็นจากผู้ทรงคุณวุฒิ
* **ศุกร์ (๖)**: ความสร้างสรรค์เชิงศิลปะ การสร้างสายสัมพันธ์อันดีในที่ทำงาน และการจัดระเบียบรูปลักษณ์หน้างาน
* **เสาร์ (๗)**: การลุยภารกิจยากที่ต้องใช้ความอดทนระยะยาว การทนแรงกดดัน และการควบคุมวินัยเข้มงวด
* **ราหู (๘)**: การทดสอบระบบความปลอดภัย การวิเคราะห์ช่องโหว่ความเสี่ยงเชิงลึก และงานเทคโนโลยีสารสนเทศ
* **เกตุ (๙)**: การทำงานเบื้องหลัง การตรวจแก้คำตกหล่นของเอกสารสัญญาเงียบๆ และการจัดพื้นที่ผ่อนคลาย

## 8. Planet-to-House Strategy Mapping (การเชื่อมโยงความสัมพันธ์ดาวและภพ)

การแปลงอิทธิพลของดวงดาวเมื่อตกลงไปในภพชะตาเฉพาะกลุ่มงาน:
* **ดาวเคราะห์ในภพกัมมะ (การงาน)**: บ่งชี้คุณลักษณะสำคัญของงานหลักประจำวัน (เช่น หากมีดาว ๓ สถิตอยู่ จะแปลว่าช่วงนี้งานต้องลงมือทำอย่างรวดเร็วและใช้พลังขับเคลื่อนสูง)
* **ดาวเคราะห์ในภพลาภะ (ผลประโยชน์)**: ประเมินเครือข่ายอำนวยความสะดวกในการบรรลุหลักไมล์งาน
* **ดาวเคราะห์ในภพอริ (ปัญหาและข้อขัดแย้ง)**: ชี้วัดสไตล์และธรรมชาติของปัญหาที่ต้องเผชิญหน้า (เช่น ดาว ๔ ในภพอริ หมายถึงปัญหาเกี่ยวกับระบบเอกสารคลาดเคลื่อนหรือการสื่อสารล่าช้า)
* **ดาวเคราะห์ในภพวินาศ (การเก็บตัวและการพัก)**: การจัดกิจกรรมทบทวนเชิงลึกเงียบๆ
* **ดาวเคราะห์ในภพปัตนิ (หุ้นส่วนและการประชุม)**: ลักษณะเพื่อนร่วมงานและการจัดสรรการประสานงาน

## 9. Strategy Signal IDs (กลุ่มรหัสแปลผลระดับดวงดาว)

* `TH_PLANET_SELF_DRIVE`: แรงขับเคลื่อนตัวตนขั้นพื้นฐานตามดวงเกิด
* `TH_PLANET_EMOTIONAL_RHYTHM`: จังหวะการจัดการสภาพอารมณ์เพื่อประคองสมาธิ
* `TH_PLANET_ACTION_FORCE`: ระดับพลังงานการลงมือสะสางใบงานภารกิจ
* `TH_PLANET_COMMUNICATION_STYLE`: รูปแบบความพร้อมและการประสานงานเจรจา
* `TH_PLANET_LEARNING_EXPANSION`: คุณสมบัติการเรียนรู้และการยกระดับความรู้ภายใน
* `TH_PLANET_RELATIONSHIP_STYLE`: ลักษณะการสร้างเครือข่ายสัมพันธ์รอบตัว
* `TH_PLANET_STRUCTURE_DISCIPLINE`: วินัยความสม่ำเสมอในระยะยาว
* `TH_PLANET_COMPLEXITY_CHECK`: เกณฑ์การจับตาความเสี่ยงและความผิดพลาดซ่อนเร้น
* `TH_PLANET_BACKSTAGE_RELEASE`: โหมดการผ่อนปรนและลบความหนาแน่นที่ไม่จำเป็นออก
* `TH_PLANET_WORK_HOUSE_FOCUS`: จุดจดจ่อที่ภพเรือนชะตาการงานเด่น
* `TH_PLANET_DECISION_CAUTION`: ข้อจำกัดที่ควรควบคุมระมัดระวังในการตัดสินใจอนุมัติแผน
* `TH_PLANET_RECOVERY_SIGNAL`: สัญญาณแนะแนวทางคืนสภาพพลังสมองส่วนบุคคล

## 10. Confidence Policy (นโยบายควบคุมความเชื่อมั่น)

* **การถ่ายทอดผลความมั่นใจ (Confidence Cascading)**: ความมั่นใจของตำแหน่งภพดาวเคราะห์ (`houseNumber`) ต้องปรับลดต่ำสุดให้สอดรับตามความเชื่อมั่นของลัคนาชะตากำเนิดเสมอ
* **ข้อจำกัดเรื่องเวลาเกิด**: หากผู้ใช้เลือกไม่แสดงเวลาเกิดหรือไม่ทราบเวลาที่แน่ชัด ฟิลด์ `degreeApprox` และ `houseNumber` ของดาวเคราะห์ทั้งหมดจะต้องไม่แสดงผลลัพธ์บน UI ชี้วัดเพื่อความเสถียร
* **การหักคะแนนความไม่สมบูรณ์**: ข้อมูลพิกัดสถานที่เกิดหรือวันเกิดคาบเกี่ยว (dayBoundaryRisk สูง) จะต้องมีคะแนนความมั่นใจลดทอนลง และแจ้งเตือนด้วยส่วนหมายเหตุความไม่แน่นอน (`uncertaintyNotes`)
* **ไม่บิดเบือนข้อมูล**: ห้ามอ้างอิงตำแหน่งดาวเคราะห์เป็นข้อยืนยันความจริงแท้เมื่อคะแนนความมั่นใจจำกัดอยู่ในเกณฑ์ต่ำ

## 11. Reference & Validation Plan (แผนงานอ้างอิงและการตรวจสอบ)

ความสมเหตุสมผลของราศีที่ดาวเคราะห์สถิตจะได้รับการตรวจสอบเทียบเคียงกับ:
* **MyHora**: นำวันเวลาเกิดจำลองไปเทียบตำแหน่งดาวเคราะห์ ๑ ถึง ๙ ของระบบดาราศาสตร์ปฏิทินไทยเดิม
* **ตำราปฏิทินดวงดาวสำเร็จรูป**: สำหรับสอบทานรอบโคจรเฉลี่ยของดาวเคราะห์วงในและดาวเคราะห์วงนอก
* **กรณีทดสอบควบคุมหลักของผู้ใช้ (กรณีศึกษา 5 มิถุนายน พ.ศ. 2523)**: สอบทานว่าราศีตำแหน่งดวงดาวของระบบจำลองสอดคล้องกับพิกัดจริงที่คำนวณละเอียดจากตำราอ้างอิงระดับข้างเคียงหรือไม่

## 12. Product Interpretation Policy (นโยบายขอบเขตการแปลผล)

ตำแหน่งดวงดาวจะใช้จำกัดกรอบเฉพาะเพื่อประเมินความสอดคล้องของการจัดการตารางเวลาทำงาน:
* **สิ่งที่ระบุ**: รูปแบบพฤติกรรมการทำงาน (work style), วิธีการคิดและวิเคราะห์ปัญหา (decision style), โหมดการร่วมประสานงาน (collaboration style), และทิศทางจัดตารางการพักผ่อน (recovery style)
* **สิ่งที่ไม่พาดพิงเด็ดขาด**: ไม่ทายอนาคต ไม่ฟันธงเรื่องคู่ครองหรืออุบัติเหตุความล้มเหลว และไม่สร้างความวิตกกังวลแก่ผู้ใช้

## 13. Data Safety & Storage (การควบคุมความปลอดภัยข้อมูล)

* **ไม่จัดเก็บข้อมูลเอาต์พุตลงบราวเซอร์**: ระบบประมวลผลดวงดาวจะรันแบบชั่วคราวบน Client-side In-memory เท่านั้น
* **ไม่มีผลข้างเคียงต่อ LocalStorage**: โครงสร้าง schema เดิมและประวัติสะสมยังคงรูปสะอาดและปลอดภัย
* **การส่งออกข้อมูลส่วนบุคคล**: หากมีระบบกู้คืนข้อมูลสำรอง (Import/Export) จำเป็นต้องแสดงคำเตือนเรื่องความเป็นส่วนตัว (Privacy warning) เสมอเนื่องจากข้อมูลเกิดจัดเป็นข้อมูลอ่อนไหวระดับบุคคลสูง

---

## 14. Non-Scope (ขอบเขตนอกเหนือการดำเนินงาน)

* **ไม่พัฒนาซอร์สโค้ดจริง**: ไม่แตะต้องหรือเพิ่มฟังก์ชันใดๆ ในคลังไฟล์ `src/` ทั้งหมด
* **ไม่ใช้ Ephemeris Database หรือ API**: ป้องกันไม่ให้ขนาดซอฟต์แวร์เพิ่มปริมาณ Code Bloat
* **ไม่ระบุสมผุสองศาลิปดาดวงดาวที่แท้จริง**: ยึดถือระบบประมาณการในระดับเวอร์ชัน 0.1 เท่านั้น
* **ไม่แก้สไตล์ UI และโครงสร้างหน้าPrototype**: คงฟังก์ชันหน้าสรุป Today Panel และปุ่ม data tools เดิม

## 15. Copy Safety Guardrails (เกณฑ์การคัดกรองคำต้องห้าม)

ห้ามใช้คำศัพท์ที่อาจก่อให้เกิดความวิตกกังวลเชิงลบในเอกสารและซอร์สโค้ด:
* *เคราะห์, ซวย, กาลกิณี, อุบัติเหตุ, เงินเสียแน่, งานพัง, ความรักพัง, ห้ามทำเด็ดขาด, จะเกิดแน่นอน, ดวงบังคับ*

ให้เลือกใช้ภาษาที่ประคองการจัดลำดับชีวิตและกระตุ้นการสะท้อนคิดเชิงบวก:
* "ใช้เป็นข้อมูลสนับสนุนเชิงกลยุทธ์เพื่อทดลองประเมินสภาพความมั่นใจของการทำงาน"
* "ระดับความแน่ชัดของแนวทางขึ้นอยู่กับสถิติประวัติและวันเวลาเกิดที่ระบุ"
* "คำแนะนำนี้เป็นกรอบการวางแผนชีวิตและการบริหารพลังสมองเบื้องต้น"
